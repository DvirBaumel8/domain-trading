# AI Visibility Check

Private repo for the AI Visibility Check website (operator: Dvir Baumel). Not the public domain-trading repo.

The site is a small Python server (`site/server.py`) plus static pages. Deploy is a Render **free** web service; see `render.yaml`. Payment links stay empty until Polar is connected. Orders: set `ORDERS_REPO` + `ORDERS_GITHUB_TOKEN` (private repo; unset = local `private-orders/`), `ORDER_ALERT_WEBHOOK_URL`, `POLAR_WEBHOOK_SECRET`; Polar webhook URL is `/api/polar/webhook` (event `order.paid`). Automatic delivery (off by default): `AIVIS_AUTORUN=1` + `AIVIS_ALLOW_PAID=1` (per-order cap defaults to 12.00; `AIVIS_ORDER_CAP_USD` overrides) + the 3 engine keys (openai, gemini, claude); a paid order then builds its report in the background and publishes it at the private link `/r/<token>` (status page `/status/<token>`). With autorun off the order is only marked `queued`. Operator smoke test (real calls, a few cents, never in CI): `python -m aivis smoke`. Tests: `python3 -m unittest discover -s tests`.

Polar products (`site/products.py` is the one map of product id -> order type): `base` (AI Visibility Check) and `bundle` (AI Visibility Bundle) are the only types that can reach the automatic report run, and only through the gate above; `maps`, `listings` and `content` (and the three extra parts of a bundle) are delivered by hand: the webhook records a `manual_delivery` order with a due date (`MANUAL_DELIVERY_BUSINESS_DAYS = 3` business days after payment or intake, whichever is later) and sends one alert; no engine runs, nothing is emailed and no report page is published. An unknown or missing product id is recorded and alerted, never treated as the base check. Purchases are keyed by Polar order id, so a replayed webhook changes nothing.

Durability and alerts: the host sleeps, restarts and loses local disk, so state lives in the orders store. **`ORDERS_REPO` must be a PRIVATE repository**: it holds the orders and the alert issues. The webhook answers 200 right after the signature check and the event claim; matching, status changes and the delivery start run in a background worker (a failure marks the event `failed` and alerts; the payload is kept and retried, at most 3 times). At boot and every 10 minutes a background thread re-queues paid `queued` orders and `running` orders whose status is older than 20 minutes (`attempts` and `spent_usd` stay in the order record, so `MAX_ATTEMPTS` and the cap hold across restarts), alerts once per 6 hours for a paid autorun order that is failed or not `ready` after 2 hours and for a manual order past its due date, and retries alert issues that did not go out. Autorun starts only if `AIVIS_ALLOW_PAID=1`, the three engine keys, a positive cap and an alert channel are all set; otherwise the order stays `queued` with a note naming the missing setting. `/health` returns booleans only (`autorun` is `on`, `off` or `blocked`).

Alert channel: a GitHub issue in `ORDERS_REPO` (label `avc-alert` when it exists), created with `ORDERS_GITHUB_TOKEN` or the optional `ALERT_GITHUB_TOKEN`, for a new order, an unmatched or held payment, a failed or blocked run, a stuck or overdue order and a failed webhook event. An issue holds only the internal order id, the status and the product type (for a payment with no order: the opaque Polar order id and a reason code). `ORDER_ALERT_WEBHOOK_URL` stays optional and also receives the alert text. Env vars involved (names only): `ORDERS_REPO`, `ORDERS_GITHUB_TOKEN`, `ALERT_GITHUB_TOKEN`, `ORDER_ALERT_WEBHOOK_URL`, `AIVIS_AUTORUN`, `AIVIS_ALLOW_PAID`, `AIVIS_ORDER_CAP_USD`, `OPENAI_API_KEY`, `GEMINI_API_KEY`, `ANTHROPIC_API_KEY`, `POLAR_WEBHOOK_SECRET`.

Free check providers and caps (DA-6). The free check uses AI search, tried in this order: **Gemini** (`gemini-3.5-flash-lite` with Grounding with Google Search, key `GEMINI_API_KEY`, model override `AVC_GEMINI_MODEL`), then **OpenAI** (`gpt-4o-mini` with the Responses API `web_search` tool, key `OPENAI_API_KEY`, model override `AVC_OPENAI_MODEL`). The keys are set in the host dashboard, never in this repo; each goes only in a request header. OpenAI is tried only when Gemini is not configured, errors, is out of quota or would pass its cap; a good Gemini answer never triggers a fallback. Reading these two keys does **not** unlock paid mode (`AIVIS_ALLOW_PAID`, `PAID_ENGINES` and the paid default models are unchanged). Pollinations stays an explicit CLI option and never runs automatically or as a fallback. Autorun stays off.

- **Monthly hard caps, free-check usage only:** Gemini **$10**, OpenAI **$5** per calendar month. The month is **UTC** (`YYYY-MM`). Prices and rates are constants in `engine/aivis/free_config.py`, dated 27 Nov 2026 (Gemini 3.5 Flash-Lite $0.30 / $2.50 per 1M tokens in / out, Search grounding $14 per 1,000 after 5,000 free a month; `gpt-4o-mini` $0.15 / $0.60 per 1M, `web_search` $10 per 1,000 calls plus a fixed 8,000 input-token block per call). **Conservative choice:** the 5,000 free Gemini searches a month are shared project-wide with the paid pipeline, so every free-check search is counted at the paid $14 / 1,000 rate, and a grounded answer is billed as at least 2 searches (`webSearchQueries` is not a billing count). Spend is estimated from the token and search counts in the response; a missing count uses a conservative estimate, so a sparse response cannot bypass the cap. A call is only started when the remaining cap covers its conservative cost, and a whole check only when the cap covers all 8 questions. `AVC_TEST_BYPASS_TOKEN` does not skip the caps.
- **Counters:** one small record per provider per month (`caps/<provider>-<YYYY-MM>.json` in the orders store): calls, searches, tokens, estimated USD and an `alerted` flag. Written once per check, race-safe under a lock; a crash can lose only the checks in flight. No keys, prompts, answers, Suggestions, citations or names.
- **Cap alert:** the first `cap_reached` of a provider in a month logs one structured line (`free_cap provider=... reason=cap_reached spent_usd=... cap_usd=... month=...`) and sends one alert through the existing path (`ORDER_ALERT_WEBHOOK_URL` and the GitHub alert issue). At most one per provider per month; the text holds no keys, prompts, names or visitor data.
- **Unavailable:** when both providers are capped, a new check is refused up front (HTTP 503, "temporarily unavailable", not counted against the visitor's hourly limit). When both keys are unset or both fail, the run ends as `unavailable` or `failed` with a plain message. No stack trace, reason code, model id or vendor name reaches the visitor.
- **Reason codes** (the job log line `free_job answers=N/8 <code>=n ...` and the `reasons` field): `rate_limited`, `timeout`, `http_<status>`, `connection_error`, `empty_answer`, `parse_error`, plus `provider_not_configured` (key missing or empty, no network call), `cap_reached` (monthly cap hit or would be exceeded, permanent for that provider), `gemini_quota_exhausted` (Gemini 429 `RESOURCE_EXHAUSTED`, no retry), `model_unavailable` (404 or 403 naming the model) and `grounding_missing` (Gemini answer without grounding metadata or without Search Suggestions; an OpenAI answer with neither a search call nor a citation). Failures that a fallback answer hid are logged as `<provider>:<code>=n`. Retries (3 tries, about 30 s, `Retry-After` honoured up to 10 s) and the fail-fast after 3 permanent errors apply per provider. No body, URL or key appears in any of them.
- **Display (live only):** Gemini's `searchEntryPoint.renderedContent` (Search Suggestions) is shown unmodified, full width, in a sandboxed frame next to the result; when it is absent nothing is invented and that answer is not used. OpenAI results show inline clickable citations from the response's URL annotations, nothing invented. The names list, Suggestions and citations go only to the visitor who ran the check, once; after the first status poll that delivers them the server drops them. Everything is labelled AI output ("Names the AI gave (AI output, not verified)", "based on X of 8 answers", "Partial result: N of 8 questions answered"). User-facing copy does not name the vendors.
- **Storage (derived only):** the stored free result page holds our own numbers (answers, named or not, partial wording) and nothing else. Grounded text, Suggestions HTML, citations, prompts and the names list are never written (`answers.json` is not written for a free run; `aivis order --mode free` writes no report page). A later view shows the derived numbers only.
- **Outreach:** no outreach template is touched by this change. Outreach emails must never include free-check results (names, text, citations or scores); they may only invite a business to run its own check.
- **Smoke script (manual only):** `python3 scripts/free_check_smoke.py` makes exactly one live call per provider (a provider with no key is skipped as `provider_not_configured`) and prints only provider, model, status, reason code and counts; exit 0 only if at least one provider is `ok`. It is never run from CI, unittest or any workflow.
- Source terms: Gemini API Additional Terms (Grounding with Google Search is a "Paid Service" through the Gemini API; display Grounded Results only with their Search Suggestions to the end user who submitted the prompt; no caching, framing, syndicating or learning from them) and the OpenAI web search guide (show inline citations as prominent, clickable links). Re-check both before changing the display or storage.

Free check reliability: every free question records `ok` or a reason code (see above). Each free job prints one stderr line such as `free_job answers=1/8 rate_limited=7` (counts only, no user text). Fewer than 6 of 8 answers (`FREE_MIN_ANSWERS`) is shown as "Partial result: X of 8 questions answered", with no score, and raises at most one `free_check` alert per hour; zero answers is `failed` with a retry message. The live result lists "Names the AI gave (AI output, not verified)"; names are marked against the NPI register only for health trades (fetched in the free path too, cached 4 h, failure shows "could not verify names"). `AVC_FREE_PACING_S` now applies only to the explicit Pollinations option.

Internal test access: `AVC_TEST_BYPASS_TOKEN` (unset by default; set it in the Render dashboard, never in git). When it is 24+ characters, a request to `/api/check` that sends the same value in the `X-AVC-Test-Token` header skips the per-hour and concurrent free-check limits; the form body and query string are never read for it. Each use logs one `bypass_used` line (no token) and the lead file gets `bypass: true`. Live acceptance: `AVC_BASE_URL=... AVC_TEST_BYPASS_TOKEN=... python3 scripts/free_check_matrix.py` (5 trades x 3 cities, free path only; `--matrix file.json`, `--pace`, `--max-runtime`); not run in CI.

Add-on checkout flag: env `ADDONS_CHECKOUT`, read at request time, **on by default**. Unset, empty or any value other than the exact, case-sensitive string `off` shows the add-on buy buttons (Maps, the two Listings products, Content Pack, Bundle) and serves their checkout URLs; only `off` shows "Coming soon - join waitlist" mailto links and serves no add-on URL. `assets/config.js` is generated by the server from `PAY_LINKS` in `site/products.py` (there is no static copy). The base check button and the webhook are not affected by the flag.

Listings has two Polar products, both delivered by hand: `listings_check` ($99, the audit) and `listings` ($249, the audit plus a ready-to-paste corrected-listing pack; site label "Listings with fix pack"). The bundle includes the $249 tier.

Discovery routes (public GET): `/sitemap.xml`, `/llms.txt`, `/robots.txt` (with a `Sitemap:` line), one landing page per trade at `/for/<trade-slug>` (generated from `NICHES`) and the dated city pages (below). Product names and prices come only from `site/products.py` (the Polar map); `site/discovery.py` holds only wording, keyed by order type, and the home page has ONE FAQ block ("Honest answers", generated from `discovery.FAQ`, the same text as the FAQPage JSON-LD). The Maps description is never stronger than the pricing table ("once we have access"). Add-on offers (Maps, the two Listings products, Content, Bundle) are switched in ONE function, `discovery.addon_offers_enabled()`, which returns `products.addons_checkout_on()` and nothing else (`ADDONS_CHECKOUT`, on by default); with the flag `off`, trade pages, city pages, `llms.txt` and the JSON-LD carry no add-on checkout link and no add-on `offers` (only the base check keeps its offer and buy button); with it on, names and prices of every offered product come from `site/products.py`. Monthly plans never get an offer in the schema. Absolute URLs use the optional `AIVIS_PUBLIC_BASE_URL` (for example `https://example.com`, no trailing slash); if unset, the origin is built from a strictly validated `Host` header and `X-Forwarded-Proto`, and if that is not a plain hostname the Sitemap line is left out.

**Referral tags.** A `?ref=` tag (1-32 chars of `a-z 0-9 . _ -`, lowercased; anything else is dropped) on `/`, `/agency.html`, `/sample-report.html`, `/thanks.html`, `/for/<trade>`, `/city` or `/city/<slug>` (not `card.svg`) adds one line `{at, ref, path}` to `site/data/ref-hits.jsonl` (no IP, user agent, cookies or headers). That file lives on the running server's disk, which is not durable on Render's free plan, so page-hit counts reset when the server restarts. `site/assets/ref.js` (included on every public HTML page) keeps the first valid ref in `sessionStorage`, adds it to internal links and as a hidden `ref` field on the free-check and intake forms. The ref is saved in the lead record that `save_lead` writes to the private store (`leads/...`) and in the order intake record (`orders/...`); nothing request-like is written to the public data folder, and it is never in API responses. Weekly count: `python3 site/ref_counts.py [--days 7] [--data-dir D] [--store-dir D]`: page hits come from `<data-dir>/ref-hits.jsonl`, free-check requests from `<store-dir>/leads/*.json` and orders from `<store-dir>/orders/*.json` (`--store-dir` defaults to `ORDERS_LOCAL_DIR`, else `../private-orders`, like the server). A column whose folder is missing prints `n/a`: clone or sync the private orders repo into a folder and pass `--store-dir`. Local files only, no network; output is refs and counts, never emails, names, businesses, cities, tokens or IPs.

**City pages.** `/city` and `/city/<niche-plural>-<city>` (e.g. `/city/dentists-austin-tx`, plus a 1200x630 `card.svg`) are built only from the market cache `site/data/markets/*.json` by `site/cities.py` (never from leads, orders, free reports or ref hits); a file without a valid `data_date`, with no answers or malformed is skipped (no page, no sitemap entry, and `/city` is not linked if none is valid). To add a city, run `site/build_market_cache.py` with the required `--data-date YYYY-MM-DD`. `SHOW_NAMES = False` at the top of `site/cities.py` (shipped): pages and card show only aggregates (questions asked, distinct businesses named, matched to the official roster, share not matched, data date, source note) and never a business name; setting it True adds the "names the AI produced" block with its disclaimer. Canonical and share URLs use the same origin helper as discovery (`discovery.public_origin`). Each city page links to the matching trade page `/for/<trade-slug>` when that niche has one. `cities.public_paths()` lists the valid paths for the sitemap and `llms.txt`.

Needs `pillow` and `fpdf2` from `requirements.txt`; new env `AIVIS_PACK_DAILY_CAP_USD` (default 60, to be confirmed before the flag is turned on).
