# CR-001 P1a + CR-002 P1 (contract v1.1.0) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship contract v1.1.0: a persisted, resumable screening service (CR-001 P1a + CR-002 P1) with versioned selection settings, data-driven v10 tier rules, `pricing_settings` v3, tranches, a feature-table replay (CAP-21a) and BUY_HOLD enforcement.

**Architecture:** New code goes under `src/screening/*` (pure rules + checks + run engine) and `src/api/selection.ts` / `src/api/screening.ts` / `src/api/tranches.ts`. Every threshold, tier clause and per-lane gate list lives in one versioned JSON document (`selection_settings.values`), validated by a zod schema; code holds mechanics only. A screening run is DB-persisted (`screening_runs` + append-only `screening_results` + `screening_evidence`); a background worker in the API process runs it gate-by-gate, and the hourly `tick` (or a poll) resumes it after a Render sleep. Pricing v3 is a branch inside the existing calculator selected by new `pricing_settings` columns, not a new module.

**Tech Stack:** Node 22 ESM, TypeScript strict, Fastify 5, zod v4, Kysely + pg, node-pg-migrate plain SQL, Vitest + MSW (network blocked), native `fetch`, `node:dgram` (existing DNS client), `node:zlib`. **No new dependencies.**

**Spec:** `docs/requests/CR-001-selection-checks.md` (§3 conventions, CAP-00…05, 06/08 as manual, 07, 10, 11, 12, 17, 18, 20; §11 DOM response), `docs/requests/CR-001-HOLD-01.md` (hold now released), `docs/requests/CR-002-v10-checks.md` (whole file; **§5 DOM response is binding**), `docs/internal/selection.md` (v9.1 formulas §2), `docs/internal/listing-strategy.md` §10.13 (pricing v3), `docs/internal/gaps.md`.

## Global Constraints

- Founder rules in `CLAUDE.md` apply unchanged; especially: **no LLM calls**, **no outbound contact**, read-only toward the outside world (CR-001 ground rule 6), never premium/aftermarket/backorder/drop-catch (rule 5: "expired" = fully dropped and registrable at the normal price).
- **Hosting $0:** Render free (512 MB, sleeps after ~15 min idle), Neon free 1 GB, Cloudflare Worker cron (`tick` hourly, `daily` 00:05 UTC). No paid source, no credential, no new env secret.
- **No new npm dependencies.** HTML-to-text, CSV parsing, edit distance, gzip (`node:zlib`) are hand-written / built-in.
- **No outbound network in default tests** (MSW `onUnhandledRequest: 'error'`; DNS and RDAP are injected functions). Live data enters tests only as **recorded fixtures** under `tests/fixtures/screening/` (total ≤ 2 MB), recorded by the opt-in script `npm run record:screening` (Task 5).
- **Status enum everywhere** (CR-001 §3.1): `PASS`, `PASS_WITH_NOTE`, `FLAG`, `FAIL`, `UNKNOWN`, `MANUAL_REQUIRED`, `NOT_RUN`. Every non-PASS result has `reason_code` (UPPER_SNAKE) + `reason`. An error is **never** stored as available / clean / not listed / 0.
- **Rules are data, not code** (CR-002 §5 P-2, coordinator item 4): tiers, thresholds, actions and the gate list per lane come from `selection_settings.values`. No `if (version === …)` branches. `pricing_settings` branches only on its own columns (`drop_mode`, `floor_rounding`, `allowed_bins_cents IS NULL`).
- **`pricing_settings` stays admin-command only** (founder rule 4). Selection settings: drafts by WRITE token via API; **activation requires Dvir's `approval_ref`** (CR-001 §11 P-8). Priors (`tier.p_passive`, `lead.p_lead`, `priors_v91`) are locked against API drafts (SEL9-2); only a migration changes them.
- **Append-only:** `selection_settings`, `selection_settings_activations`, `selection_lists`, `screening_results`, `screening_evidence`, `manual_quotes`, `labelled_names`, `replay_runs` get the existing `reject_mutation()` UPDATE/DELETE/TRUNCATE triggers. Mutable by design (state, not records): `screening_runs` status/heartbeat/summary columns, `tranches.status/closed_*`, `tranche_members.removed_*`, `reference_files` (cache; pruned), `rdap_lookups` (cache; pruned).
- **Evidence** (CR-001 §11 P-4): URL, `retrieved_at`, sha256 of the full response, extracted visible text gzip'd and capped at `evidence.max_text_bytes` (default 32768) — **never raw HTML**.
- **Every POST** keeps the existing idempotency + audit middleware; every new body schema is zod `.strict()`. Money is integer cents with display pairs; times ISO 8601 with offset.
- **Contract:** every new route gets a `### \`METHOD /path\`` section in `docs/contract/endpoints.md`; every UPPER_SNAKE literal emitted from `src/` must appear in `docs/contract/` (`tests/contract/contract-doc.test.ts` must stay green after every task). `CHANGELOG.md` gets a `## 1.1.0 (unreleased)` entry that each task extends. `package.json` version → `1.1.0` in Task 10.
- **Source terms first:** an external source is used only after its terms are quoted (verbatim) with URL and date in `docs/internal/sources.md` and its `sources.<name>` flag is `true` in the active selection settings. A disabled source makes its check `UNKNOWN` / `SOURCE_DISABLED` (never PASS).
- Outbound HTTP identifies honestly: `User-Agent: domain-trading-api/<version> (+https://github.com/DvirBaumel8/domain-trading)`; no personal address.
- Repo size: committed data files ≤ ~1.5 MB total; sizes recorded in `data/README.md`.

## Review Focus

1. **Render sleeps mid-run and wakes after the time budget** → the run must finalise as `partial` with every unfinished check `UNKNOWN` / `TIMEOUT`, never leave a name `survivor`/`would_buy` with missing gates. Test in Task 4 (`resume after deadline finalises partial`).
2. **A source answers 200 with a non-conforming body** (RDAP 200 with HTML or invalid JSON, CDX empty/HTML body, NameBio CSV with a changed header, Tranco empty file) → `UNKNOWN` / `SOURCE_ERROR` (and for reference files: the refresh step fails and keeps the previous snapshot). Tests in Task 5 (RDAP), Task 6 (Tranco/NameBio), Task 7 (CDX).
3. **A draft whose tier DSL references an unknown feature, an unknown `$threshold`, an unknown check id in a lane gate list, or a non-feature check in `run.feature_checks`** → refused at draft creation with 422 `SETTINGS_INVALID`, never discovered mid-run. Test in Task 3.
4. **Odd domain spellings in runs, lists and uploads** (uppercase, trailing dot, `www.`, IDN/unicode, `.net`, duplicates within one batch, census lists with the target name inside) → normalised with the existing `normalizeDomain` or rejected per row (`INPUT_INVALID` in runs; 422 on lists/uploads); duplicates in a batch → second one `INPUT_INVALID` `DUPLICATE`. Tests in Task 3 (lists) and Task 4 (runs).
5. **Activating a v3 pricing version while v2 plans are listed** → existing `price_schedule` rows keep applying with v2 math (the price job reads the row's planned version); only new plans use v3. Test in Task 2 (`v2 plan keeps v2 drops after v3 exists`).
