## What worked
- **The tech-debt pass (v5.13.0–v5.15.0 and the R1/R4a/R5 commits).** The test suite went from 15–17 min to about 4 min locally. A CI run went from about 28 to about 9 billed minutes and 3–5 min wall time. The atomic deploy had no failed release since then.
- **Fewer follow-up fixes:** 3 patch releases, down from 11. Bigger releases with the full gate before the tag.
- **CR turnaround:** CR-059..063 were each built and confirmed within a day. Pre-approval of Gavriel's and the bots' CRs (15 and 17 Oct) removed the wait for Dvir.

## What didn't
- **Time bombs in tests:** approval ages read from the real clock turned CI red on 12 Oct with no code change (BUG-042). R1 moved them to a fixed `now`, but nothing stops a new one.
- **Deploys wait one extra tick:** every release this week lost about 10 min because `deploy.sh` exits when CI is still running and only checks again 10 min later.
- **The feedback loop has no bot input yet.** No pain points and no DB size reading arrived; the loop ran on DOM's own signals only.
- **Production is stopped (18 Oct, Dvir's request).** DOM unloaded the api and deploy agents. v5.15.0 had been running since 17 Oct 15:03 UTC. There is no stop/pause command in the host kit, so "down on purpose" is invisible to Gavriel and to `deploy.sh`.
- **The v5.9.0 CI timeout (20 min)** cost a re-run and two CI changes before R1 fixed the root cause (a slow suite).

## Top 5 improvements (by value)
1. **G-109: a pause switch in the Mac host kit.** `scripts/local-host/stop.sh` and `start.sh --resume` write and clear a pause flag. `deploy.sh` honours it (no kickstart or bootstrap while paused), and the runbook documents it. Then a stop Dvir asks for is one command, and a later deploy can't undo it.
2. **G-110: deploy as soon as CI finishes.** While a tag's CI is `in_progress`, `deploy.sh` re-checks every 60 s, up to 15 min, inside its lock, instead of exiting. This saves about 10 min per release.
3. **G-111: a guard against real-clock time bombs in tests.** One extra CI step runs the unit and api projects with the clock shifted +45 days (a fake-timers setup behind an env flag), or a guard test that flags real-clock approval ages in test files. Pick the smaller one that catches BUG-042's pattern.
4. **G-98 (raised to medium): ledger CSV cells escaped against spreadsheet formulas.** Gizbar and Dvir open `/ledger?format=csv` in a spreadsheet. A cell starting with `= + - @` gets a leading `'`. This is a contract PATCH note.
5. **G-112: make bot input part of the loop.** The weekly notice to Gavriel asks for (a) pain points and (b) the `/health` DB size and job status, in a fixed short table, so the next loop has numbers. DOM can't read production itself (HARD RULE).
