## Cross-cutting (G1)
**Auth (AU):** AU-1 no or bad `Authorization` on every route except `/health/ping` (incl. `/health` and unknown routes) → 401, `audit_log` and `idempotency_keys` counts unchanged. AU-2 malformed or unknown token → 401. AU-3 READ token on `POST /buy`, `/list/x`, `/sold/x` → 403 `SCOPE_FORBIDDEN`, audit row, zero registrar calls. AU-4 READ on every GET → 200. AU-5 WRITE on every GET → 200. AU-6 revoked → 401 within one request. AU-7 no route creates, lists or reveals tokens (route table: no `/token*`). AU-8 responses, logs and audit rows of all tests contain no env secret value and no `pk1_`/`sk1_` prefix. AU-9 the 11th POST in a minute → 429. AU-10 Gavriel's WRITE token: `/sold` with ref + evidence, no approval → 200 `confirmed: false`; `/buy` without approval → 422, zero registrar calls. AU-11 the 21st failed auth from one IP in 10 min (IP = the right-most `X-Forwarded-For` entry, one trusted hop) → 429 `RATE_LIMITED` + `Retry-After`, zero DB access; another IP unaffected; the window rolls. AU-12 blocked IP: a token verified in the last 10 min passes only through the normal lookup; an unseen token → 429; the correct job token → 200, a wrong one → 429; a cached token revoked meanwhile → 429; a revoked token on the normal path → 401. AU-13 a valid token with the wrong scope (403) is still audited.

**Caps (CAP):** CAP-1 $1,500 POC cap (B-11) and its race (B-12). CAP-2 50-domain cap (B-13), `pending_purchase` counts. CAP-3 per-call `max_price` (B-8–B-10). CAP-4 approval age, future time, domain mismatch (B-7) → 422. CAP-5 no route writes `settings`; a body field `poc_cap` is rejected. CAP-6 property (200 random sequences): −Σ(registration + renewal + fee) ≤ `poc_cap_cents`.

**Idempotency (ID):** ID-1 missing key on each POST → 400. ID-2 replay on each POST (B-3, L-8, S-5) → same response, side effects once. ID-3 same key, other body → 409. ID-4 the registrar key derives from the purchase id and is reused on retries (B-19).

**Dry run (DR):** DR-1 `/buy dry_run` (B-16): no ledger/domain rows; audit row; registrar dry run with the exact cost. DR-2 a dry run enforces every check (cap, approval, `max_price`). DR-3 a dry run's key reused for the real call → 409 (new hash); use a new key.

**Audit (AL):** AL-1 every authenticated POST → exactly one `audit_log` row (incl. a valid-token 4xx); unauthenticated requests and framework errors write nothing. AL-2 UPDATE/DELETE on `ledger_entries` and `audit_log` → DB error. AL-3 row content: scope, token id, approval text and time, status code; no secrets.

**Max one renewal (RN):** RN-1 two-year = first year + one renewal (CK-9). RN-2 `drop_date` = expiry + 1 y (B-21, B-22). RN-3 `renewals_used = 2` insert fails. RN-4 `committed_forward` ≤ 1 renewal (R-3). RN-5 no renew option at final expiry (R-5). RN-6 `register` always with years = 1.
