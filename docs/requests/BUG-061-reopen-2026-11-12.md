## Rules

- R-1 **Lock heartbeat survives a dropped pooled connection:** if the checked-out connection that holds `job:datasave` (or the aftermarket step lock) is dropped (`57P01` / `terminating connection due to administrator command` / `Connection terminated unexpectedly`), the heartbeat must reconnect and retry. A dropped pool connection alone must not fail the step as `lock expired` while the process is still running and the 60-minute aftermarket budget has not been exhausted.
- R-2 **Expired or failed worker stops fetching:** once the lock has expired, or the step is marked failed / `lock expired`, the worker must stop further Dynadot fetches (no more aftermarket `listings` pages) within one in-flight call. No orphan paging that can overlap a retry.
- R-3 **Preserve 5.73.0 honesty:** a real failure still writes the `STEP_FAILED` error manifest (`status: error`, unsealed, no invented rows) and a later datasave or bot upload may still seal the day (existing 409 / seal rules). Do not weaken DS573-2 / DS573-3.
- R-4 **No Render suspend in this build.** If DOM mentions the legacy Render copy (`domain-trading-api`, `srv-db2m3haj9qps73ena0j0`), it is an ops pointer only. Suspending it needs Dvir's yes. Do not deploy, restart, scale, or suspend it as part of this CR.
- R-5 No money, no registrar actions, no DOM settings activation. Secrets never in logs, `/health`, or request files.
- R-6 No full Dynadot redo and no closeouts backfill as part of this fix. Tonight's closeouts partial seal (pages 64–68 HTTP 500, coverage 0.926) is the known tail-page pattern.

## Acceptance tests (tests-as-contract)

Pass/fail checks. Automate as fixtures; each must have a pass and a fail case where that applies.

- AT-1 **Heartbeat reconnects:** simulate a mid-run drop of the checked-out lock connection (`57P01` / administrator-command terminate). The heartbeat reconnects and retries. The step does **not** fail as `lock expired` solely because of that drop, provided the process is still running and the aftermarket budget has not been exhausted. The drop is logged; the process does not crash (existing DS573-3 still holds).
- AT-2 **Expired worker stops:** force a `lock expired` (or mark the aftermarket step failed) while a paging loop is in progress. The worker makes **no further** Dynadot fetch after the in-flight call returns. Fixture shows fetch count frozen after the fail, not growing for minutes.
- AT-3 **No overlap with retry:** after AT-2, start the scheduled aftermarket-only retry (or a test equivalent). Only the retry issues Dynadot `listings` calls; the expired run issues none.
- AT-4 **Manifest preserved:** on a real lock-expired or step failure, `GET /snapshots?date=D&source=dynadot_aftermarket` still shows a server `STEP_FAILED` error manifest, `sealed: false`, no invented rows (DS573-2). A later datasave can still seal the day.
- AT-5 **Negative:** no money routes; no settings toggled on; no secrets in logs, errors, or health output. This release does not suspend or change the legacy Render service.
