## 1. Findings
### F-1. A malformed but complete escape (%ZZ) in the path does not get the service's 400 INVALID_REQUEST
- **Contract:** releases/v2.1.0.md: 'a malformed percent-encoding such as /portfolio/%ZZ answers 400 INVALID_REQUEST in the error shape'; CHANGELOG 2.1.0 BUG-6; DOM's follow-up in CR-005: '%ZZ and %C3%28 reach DOM and get 400 INVALID_REQUEST'.
- **Expected:** 400, Content-Type application/json, {error:{code:'INVALID_REQUEST',...}}.
- **Actual:** 400, Content-Type text/html, a Cloudflare '400 Bad Request' page. Same with and without a token, with %zz, and from curl. %C3%28 does reach the service and is correct.
- **Reproduce:** curl -i https://domain-trading-api.onrender.com/portfolio/%ZZ -H 'Authorization: Bearer <token>' (2026-10-07 12:34 and 13:02 IDT).

### F-2. AUTO_RENEW_UNCONFIRMED is not shown for the manual GoDaddy name
- **Contract:** CR-004 §10.2 Q-4: 'a --manual GoDaddy name always shows AUTO_RENEW_UNCONFIRMED ... the warning stays as an honest "the API can't see it"'. reports.md lists no such code.
- **Expected:** GET /report (or /portfolio/{domain}) shows AUTO_RENEW_UNCONFIRMED for promptinjectionaudit.com.
- **Actual:** /report warnings are FLOOR_AUTO_ACCEPT and LANDER_PENDING only; /portfolio/{domain} has no auto-renew field. Either the contract (reports.md) needs the code and the service needs to emit it, or CR-004 Q-4 should be corrected.
- **Reproduce:** GET /report and GET /portfolio/promptinjectionaudit.com (2026-10-07 12:3x IDT).

### F-3. selection.md header still says contract v1.1.0

### F-4. Docs describe the truncated-escape case as 400; live it is 520
- **Contract:** test-evidence.md INVALID_REQUEST row: 'a truncated percent-encoding (GET /portfolio/%E0%A4%A) gets 400 INVALID_REQUEST'. CHANGELOG 2.1.0 BUG-6 makes the same claim in general terms.
