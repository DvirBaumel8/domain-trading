## 4. Operating rules (R1–R8) + decision ladder (L0–L3)

### R1 — One writer per durable fact
Name the writer in the CR or bot-logic stub. Readers get API or a dated export. Ban silent dual maintenance of the same field.

### R2 — FIXED fetch once; JUDGMENT many
Shared evidence blobs / DOM caches for TM kills, sealed comps, shortlist rows. Bots re-judge; default is “read cache, don’t re-scrape” unless Opinion / kill-list change demands live (see §9 Q2).

### R3 — Token ladder (cheap → expensive)
1. DOM job / API  
2. Bot scripted POST/GET (no browser)  
3. Grok browser / computerUse  
4. Multi-bot debate  
Never climb the ladder for FIXED work.

### R4 — Claude Code sees only git
Before BUILD NOW on anything that needs ledger/deals/lessons/decisions, DOM Architect commits a NOTE or cites an existing request doc. No “Claude should know from chat.”

### R5 — Migrate only FIXED rows from `08`
Next (when freeze allows, or as maintenance per §9 Q5): hard filters authoritative on shortlist; B-01 fields on card from ledger; listing provenance / approval_text completeness; Afternic Portfolio API sync; AUTO-FAIL assists; comps-count flag. **Stay bot:** meaning, CLEAR, Challenger, money after yes.

### R6 — Ping-pong then Dvir
Gavriel ↔ DOM Architect iterate until one joint plan. Bring Dvir only for (a) final approval of the joint plan, or (b) a hard disagreement we can’t resolve.

### R7 — Learning loop stays
Every run: read last lessons; append 3–5 lines. Outside reviews = weighted evidence, not auto-reshape (`knowledge/evidence-ledger.md` when acting).

### R8 — Don’t compete where we can’t win
Sedo automation: no. Browser wars on UI without API: no. Hand-reg lottery lanes: no. Prefer Afternic inbound + disciplined cheap aftermarket + buyer-first cards.

### Decision ladder

| Level | Who | Examples |
|---|---|---|
| **L0 — Bot alone** | Buyer/Sales/Risk Gate within written SOPs | Walk away on hard filter; FLAG a near-mark; draft a card; Monday snapshot with `n/a`+reason |
| **L1 — Gavriel alone** | Coordinator | Dual-runner backup seal; format Dvir card; file CR/NOTE; pause a broken routine; accept DOM FIXED classification |
| **L2 — Gavriel ↔ DOM ping-pong** | Both | FIXED vs JUDGMENT disputes; API design; where a job should live; TEAM-OPS joint plan; Afternic API sync design |
| **L3 — Dvir required** | Founder | Any money; strategy change; new marketplace investment; raising caps; shelving a major engine; final TEAM-OPS approval; true disagreements after L2 |

**Rule:** If Gavriel and DOM agree after one ping-pong round, **do not** escalate. If they disagree on strategy, edge, or money boundaries → **Dvir**.
