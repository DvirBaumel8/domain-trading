# Release v2.16.2 (8 Oct 2026)

**Contract:** 2.16.2. PATCH. Refactor step R1b (locks and efficiency) of `docs/superpowers/plans/2026-10-08-refactor-and-job-queue.md`.

- **Locks:** the nightly run, the tick, each job step, the review run, the post cap, intake and the daily-list rebuild are guarded by Postgres locks (`src/core/locks.ts`, named keys), not in-memory flags. A second instance during a deploy gets `skipped`, as a second run in the same instance always did.
- **One pace per registry:** all runs share one polite limit per RDAP host (at most 4 at once, at least 250 ms apart, slowing down and stopping on refusals). A live run keeps its stricter limit.
- **Fewer database calls:**
  - the heartbeat at most every 10 seconds;
  - the cancel check at most every 5 seconds;
  - manual rows read only for checks that can be manual.

  A 20-name run went from 225 to 83 statements.
- **Visible changes:**
  - `ms` on each job step;
  - `lookups` and `unknowns` are `null` on a test set while its run is going (use `run.done_n` for progress).
- **No migration.**
