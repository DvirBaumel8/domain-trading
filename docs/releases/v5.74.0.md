# Release v5.74.0 (28 Oct 2026)

**Contract:** 5.74.0 (MINOR: a new retention setting and new retention summary fields; migration `1769000000000_v5-74-0.sql`). Protects Neon's free 1 GB.

- **Why:** Gavriel's 5.73.0 receipt showed the database at 55.8% of 1 GB, up from 40.7% the night before. Since CR-080 the server seals the whole Dynadot aftermarket every day: about 377,000 rows, about 100 MB a day. Those rows were kept 120 days, so the database would have filled in about four days (around 1 Nov), and then every write would fail.
- **What changed:**
  - **Retention:** aftermarket rows are kept `settings.datasave_aftermarket_keep_days` = 2 days in the database (closed-auction rows keep their 120 days).
  - **Archive first:** before deleting a day, `snapshotRetention` writes it to the host's disk as `<ARCHIVE_DIR>/dynadot/<date>-aftermarket.jsonl.gz`, so no data is lost. If that write fails, the day stays in the database. The summary adds `aftermarket_cutoff_date`, `aftermarket_rows_deleted` and `aftermarket_archive {written, skipped, kept, error?}`.
  - **Market episodes:** the `episodes` step now folds each sealed day into the stored episodes instead of re-deriving them from every old row. The split rule is unchanged: a new episode starts after more than 7 days with a sealed day between. `seen_days`, `price_changes` and the first price carry over. This also fixes an old undercount: after a prune, a merged episode kept `seen_days` at the older value.
  - **Counts:** `dqMarket` coverage and `GET /market/coverage` count a pruned sealed day by its manifest's row count. Price sanity looks only at the kept days.
- **Unchanged:** manifests (`GET /snapshots`, `/snapshots/missing`), sealing and the 409 rules.
- **Tests:** DS522-8 (updated: aftermarket 2 days), DS574-1 (archive before delete, skip an existing file, keep the day when the archive fails), MK574-1 (fold with every older day pruned: counts keep growing, a second run writes nothing, the gap rule still splits).
- **How to test it (Gavriel):** after the 29 Oct datasave, `GET /jobs/runs?job=datasave` → `snapshotRetention.summary.aftermarket_*`. From 30 Oct, `/health.db_size` should stop climbing by about 100 MB a day.
- **Impact on Gavriel:** `GET /snapshots?source=dynadot_aftermarket` row reads return only the last 2 days. Older days live in the host archive.
- **Deploy:** tag → Mac host. The migration adds one settings column.
- **Lessons:** CR-080 (server-sealed aftermarket) went live without a storage estimate at 377,000 rows a day. A new daily feed should come with its size per day and its retention in the same release.
