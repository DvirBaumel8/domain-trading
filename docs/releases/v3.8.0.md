# Release v3.8.0 (10 Oct 2026)

**Contract:** 3.8.0, MINOR, additive. CR-039, approved by Dvir on 10 Oct 2026: a digit is fine when it is part of a regulation name.

- **What changed:**
  - **Intake** (`POST /candidates/intake`) accepts a name with a digit when `words` are given and every piece with a digit is a term on the current `regime` list. Without `words`, or with a digit piece that isn't on the list, the answer is still `HAS_DIGIT`. Drop-list uploads haven't changed.
  - **Screening:** the form check (SPELL-1) uses the same rule, so the name is screened normally, and its regime piece counts as `regime`.
  - **Regime list:** `POST /selection/lists/regime` accepts terms like `ets2` or `iso27001` (a letter first, then letters or digits). Other word lists stay letters only.
  - **Census lists** may be named with digits, for example `bt1_ets2compliance`.
- **Your step first:** add the codes to the regime list, for example `POST /selection/lists/regime {add: ["ets2"]}` (WRITE; it writes a new list version and needs no approval).
- **How to test it:** send ets2compliance.com to intake again with `words: ["ets2","compliance"]`. It should be `accepted`. The same name without `words` should be `removed` with `HAS_DIGIT`.
