# Release v5.76.0 (29 Oct 2026)

**Contract:** 5.76.0 (MINOR: the `datasave` schedule moves; no route, field, code or migration change).

- **What changed (CR-094):** GoDaddy publishes its inventory files at about 15:07–15:10 UTC (28 and 29 Oct), after the 15:05 UTC start. So the first run failed `godaddyInventory` every day with `GODADDY_NOT_PUBLISHED`, and only the retry an hour later saved the day.
  - The Mac host's agent (`com.domaintrading.datasave`) now runs at minute 25 of each hour, so the normal start is **15:25 UTC** (was 15:05). Catch-up after a sleep or restart is at minute 25 of the next hour.
  - The GitHub backup schedule is **15:20 UTC** (was 15:00). Both still use the same Idempotency-Key (`datasave-<15:00 UTC of the day in ms>`), so a second trigger is a replay.
  - The 60-minute retry after `GODADDY_NOT_PUBLISHED` is unchanged and still covers a late publish.
  - `docs/contract/jobs.md` no longer says GoDaddy rebuilds at about 14:40 UTC.
- **How to test it (Gavriel):** on 30 Oct, the first `datasave` run in `GET /jobs/runs?job=datasave` starts at about 15:25 UTC, `godaddyInventory` is ok with `data_date` 2026-10-30, and no `datasave-retry` run follows.
- **Impact on Gavriel:** the day's shortlist and data arrive about an hour earlier than with the retry. Read them after about 16:30 UTC (the Dynadot reads take about 40–60 minutes).
- **Deploy:** tag → Mac host, after the 29 Oct datasave finished. DOM reloads the `com.domaintrading.datasave` agent after the deploy so the new minute takes effect.
- **Lessons:** the schedule was set from GoDaddy's old rebuild time (14:40 UTC) and never checked against the files' real `Last-Modified`. Check a source's actual publish time before fixing a schedule to it.
