# Release v5.75.0 (28 Oct 2026)

**Contract:** 5.75.0 (MINOR: an additive field on `GET /health`). Builds CR-090. CR-089 and CR-091 are docs and CI only.

- **What changed:**
  - **CR-090:** `GET /health` keeps `datasave` (`ok` | `partial` | `error` | `overdue`) and adds `datasave_detail`: for the latest finished datasave run, each step's `status` (`ok` | `partial` | `error` | `skipped` | `not_configured`), `data_date` and `error`. It also adds `missing_files`, `dynadot_missing` and `dynadot_due_date`.
    - A Dynadot GAP shows as `error` with `GAP: <reason>`.
    - A late GoDaddy publish shows as `godaddyInventory` `error` with `GODADDY_NOT_PUBLISHED: ...` (5.73.0).
    - `not_configured` never changes `datasave`.
  - **CR-089:** discovery run packs live only in `docs/requests/discovery-runs/<date>-v3/`; there is no `sourcing/` tree in this repo. The Buyer SOP now says seal → commit the pack → exit. The README sets a size guide: about 5 MB a day, and over about 20 MB keep the bulky evidence off git.
  - **CR-091:**
    - Live `docs/bot-logic/04` (discovery v3, Option 1) and `09` (the day timeline) were copied from the request drafts.
    - The README lists them.
    - `requests-only.yml` now lets bot commits touch `docs/bot-logic/**` too, so the next stamp needs no Claude Code.
- **Tests:** CR090-1 (all steps ok, `not_configured` Dynadot, top level stays ok), CR090-2 (one GoDaddy file fails → `partial`, with the step and reason), CR090-3 (the step-state rule). The `/health` keys test now includes `datasave_detail`.
- **How to test it (Gavriel):** `GET /health` → `datasave_detail.last_run.steps`. After the 29 Oct datasave, it should show each step.
- **Impact on Gavriel:** none for clients that read only `datasave`. The L&L can name the failed step without reading `GET /jobs/runs`.
- **Deploy:** tag → Mac host. No migration.
- **Lessons:** the bots stamped live-doc changes in request drafts that nothing copied over. Letting them edit `docs/bot-logic/` directly removes that hop.
