# Release v5.72.1 (28 Oct 2026)

**Contract:** 5.72.1 (PATCH). Paper trading keeps a 25-name slice after CR-088; shortlist rows are kept 30 days.

- **What changed:**
  - 5.72.0 (CR-088) stores the whole auction field (`shortlist_size` 0). That made every stored name a `shortlist` row in `auction_outcomes`, and left the random control only names that had no room under our maximum. The "our picks vs random" measure (F43, `GET /auctions/funnel` `paper`) became meaningless.
  - The paper slice is now the top `settings.shortlist_paper_n` (25) of the stored list, and the control is 25 names from the rest of the field, as before.
  - `shortlist_keep_days` goes from 90 to 30. About 750 stored rows a day for 90 days would take a real share of Neon's free 1 GB.
  - The CR-088 behavior (full field, paging) is unchanged.
- **Tests:** AS549-12 now runs with production settings (5.72.0 had set `shortlist_size` back to 25 inside the test, which hid this).
- **Impact on Gavriel:** none to call. Paper-trading counts stay comparable with the days before 28 Oct.
- **Deploy:** tag → Mac host; pushed after the 23:45–01:00 UTC nightly window.
- **Lessons:** CR-088 was built twice in parallel (a Cursor agent through a PR, and DOM). The bots should name one builder per CR. And a test should not change a production setting to keep passing: that hides the bug it should catch.
