# Release v4.0.0 (13 Oct 2026)

**Contract:** 4.0.0 (MAJOR: `POST /buy` now requires `stre` and `stre_reason`, so a /buy without them gets 400). CR-044, CR-045 (and its follow-ups), CR-046, CR-048, CR-049: portfolio discipline, outcomes, and the Spaceship SellerHub listing sync.

## Contract changes
- **Domain cap 40** (migration; Dvir, 13 Oct 2026). Dry run: `would_be_blocked: "DOMAIN_CAP_REACHED"`; a real buy: 409 `DOMAIN_CAP_REACHED`.
- **`POST /buy`:**
  - **required `stre` (0..1) and `stre_reason`.** Missing: 400 `VALIDATION_ERROR`. `BIN x (1 - commission) x STRe / renewal cost` under `buy.renewal_math_min` (1.0) is 422 `RENEWAL_MATH_FAIL` (details `renewal_math`). The commission comes from the settings (Afternic 20%). The numbers are in the dry run and the 201 (`renewal_math`) and stored on the name;
  - optional `horizon` (`evergreen` default | `trend` | `regulation`); the dry run and 201 return `horizon` and `screening_group` (`passed` | `borderline`, `borderline` = the latest screening run holds a FLAG). A trend or regulation name with `drop_policy` other than `at_first_expiry` gets the warning `HORIZON_DROP_POLICY_MISMATCH`;
  - `lto_max_months` is 422 `LTO_NOT_ALLOWED` on a trend, regulation or first-expiry name (also `POST /list/{domain}`). **The field that marks a name evergreen is `horizon`.**
- **New routes** (`endpoints.md`): `POST /portfolio/{domain}/horizon`, `POST /portfolio/{domain}/stats`, `GET /portfolio/outcomes` (+ `/monthly`, `/quarterly`), `POST /outreach/emails`, `GET /outreach/emails/summary`, `POST /patterns/sales`, `GET /patterns/latest`.
- **`/report` warnings** (`reports.md`): `RENEWAL_DROP_SUGGESTED`, `SELL_BEFORE_DROP`, `HORIZON_DUE`, `DELIST_NEEDED`, `LANDER_PRICE_MISMATCH`, `LANDER_OFFER_MISSING`. `LANDER_DOWN` now fetches `https://` and a TLS failure counts.
- **Daily steps** (`jobs.md`): `listingSync` and `portfolioLifecycle`, after `dropJob`.
- **Selection settings keys** (`selection.md`): `buy.renewal_math_min`, `buy.math_venue`, `buy.commission`, `renewal.{drop_check_days 60, list_by_days_before_expiry 30, horizon_months 12, horizon_due_days 30}`, `outreach.max_emails_per_name` 5, `portfolio.{holdout_passed_n 20, holdout_failed_n 20, holdout_recheck_months 6, patterns_min_cents, patterns_max_cents, judge_sales_months 24}`. Old stored versions read these defaults; no new settings version is needed.
- **Admin command** `record-renewal` (not an API route; DOM-run on the host, with Dvir's line).
- **Migration** `1763100000000_v3-11-0.sql`: `settings.max_domains` 40; `domains.horizon`, `sell_or_drop_by`, `screening_group`, `buy_card`; tables `portfolio_stats`, `outreach_emails`, `holdout`, `sales_pattern_uploads`, `sales_pattern_rows`, `listing_sync_log`; portfolio check kinds `price` and `lookalikes`. All new tables are in the nightly export.

## Impact on Gavriel
- **Every `POST /buy` (dry runs too) now needs `stre` and `stre_reason`** from the scout's card, or it is 400. Plan: `stre` is the chance (0..1) that the name sells within the renewal period; with Afternic at 20% and a $1,488 BIN, a $11 renewal needs `stre` of about 0.01 or more to reach ratio 1.
- **The 4 current names:** call `POST /portfolio/{domain}/horizon` for D-002, D-003, D-004 with Dvir's line in `approval_ref` (it names the domain). It sets `sell_or_drop_by` (buy + 12 months) and moves `drop_date` to the first expiry. LTO stays off.
- **Stats:** send `POST /portfolio/{domain}/stats` per name, month and venue (`afternic`, `sedo`, `sellerhub`) with views, leads, offers, from the Afternic and SellerHub dashboards. The outcomes reports and the renewal drop check read them.
- **Outreach:** log every email with `POST /outreach/emails` (recipient as the company's domain, never an address). The 6th for one name is 409 `EMAIL_CAP`.
- **Sales patterns:** upload the CSV with `POST /patterns/sales` (`{csv}` of `domain,price_usd,date,venue`); read `GET /patterns/latest` and write `docs/requests/patterns/<date>.md` yourself (the service never writes into the repo).
- **Sell before drop:** `SELL_BEFORE_DROP` (60 days before expiry) gives `list_by` and the venues. A wholesale price is a pricing exception: `POST /list` with an override and Dvir's `approval_ref` naming the domain and the price. The service never lists or posts by itself.
- **After a sale** (`POST /sold`): SellerHub is delisted by the service; `DELIST_NEEDED` stays until the Afternic and Sedo listings are recorded as removed (`POST /listings/{domain}/venue` with `delisted: true`). A sale made at SellerHub: record it with `POST /sold` (venue `other`).
- **Lander price check:** `LANDER_PRICE_MISMATCH` / `LANDER_OFFER_MISSING` / `LANDER_DOWN (tls_error)` come from the daily check of `https://<name>/`.
- **Renewal:** DOM books the one renewal with the admin command `record-renewal` after Dvir's line; ask in `DOM-TO-GAVRIEL.md`.
- **Not built, and why:** `POST /demand/keywords` (put one real Keyword Planner export in `docs/requests/exports/` first); the Companies House clue (no key); an Afternic stats CSV import (put one real export in `docs/requests/exports/`).

## For Dvir: environment variables on the Mac host (never the repo)
`SPACESHIP_SELLERHUB_API_KEY` and `SPACESHIP_SELLERHUB_API_SECRET`: an API Manager key pair at Spaceship with only the `sellerhub:read` and `sellerhub:write` scopes (not the registrar pair). Without both, `listingSync` is skipped. SellerHub verifies ownership by a TXT record; that joins the CR-040 switch window.

## How to test it (dry_run, reads, no real purchase)
- `POST /buy` with `dry_run: true` and a `stre`: read `renewal_math`, `horizon`, `screening_group`, `would_be_blocked`. A tiny `stre` (0.0001) must give 422 `RENEWAL_MATH_FAIL`.
- `POST /patterns/sales` with a small CSV, then `GET /patterns/latest`.
- `GET /portfolio/outcomes`, `/monthly?month=YYYY-MM`, `/quarterly`; `GET /outreach/emails/summary`.
- `GET /report` for the new warnings once a name is inside 60 days of its first expiry (60 days before its expiry).
- After the key pair is set: the next daily run shows `listingSync` with `created[]` for the listed names; `GET /jobs/runs` has the step result. DOM never calls SellerHub from a test or by hand.
