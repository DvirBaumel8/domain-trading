# Release v5.7.0 (14 Oct 2026)

**Contract:** 5.7.0. CR-058 owned-name endings watch (ENDING_REGISTERED, GET /owned/:domain/endings) and engine health hold-time slices

- **What changed:** (A) The owned names' other endings are watched. Every owned name (status owned, listed or delisted) gets its .net, .co, .org, .io and .ai checked weekly inside the daily `engineEndings` step (RDAP only), before the bulk names. The first answer is stored as a `baseline` event; a later registration is `newly_registered`, a changed registry creation date is `re_registered`; an ending created after our buy date at the first check is `newly_registered` right away. New route `GET /owned/{domain}/endings` and the `/report` warning `ENDING_REGISTERED`. (B) `GET /engine/health` and `GET /engine/train/{id}` carry `slices {threshold, quick, held, unknown_n}`, the hold-time split of the test rows. Migration `1764000000000_v5-7-0.sql` (table `owned_ending_events`, column `engine_endings.registrar`). Contract: `endpoints.md`, `jobs.md`, `reports.md`.
- **Impact on Gavriel:**
  - **The warning and the route are the lead list.** CR-058 asked for a leads-list write with `source: "ending_watch"`; the service has no per-name leads list that Sochen reads, so none was added. Pass `ENDING_REGISTERED` warnings (`owned_domain`, `host`, `created`, `registrar`) and `GET /owned/{domain}/endings` to Sochen. Nothing is sent (founder rule 10); outreach stays Sochen's draft and Dvir's per-email approval.
  - **No hyphen .com.** The five endings only; the hyphen form is the sibling scan (CR-050). Ask again if the data says it matters.
  - **Timing.** Owned pairs that have never been asked are asked in the next daily run after the deploy, so every owned name gets its baseline then; after that each pair is re-asked weekly. A warning stays in `/report` for 30 days after its event.
  - **Slices.** `quick` = sold under 91 days after the `.com`'s registry creation, `held` = 91 days or later, `unknown_n` = sold test rows with no `.com` creation date. `recall` is at a score of 0.5 (the model has no other threshold; the value is shown as `threshold`). `auc` = the slice's sold rows against all unsold test rows. `slices` is null until the next training (a model trained before 5.7.0 has none). The engine has no separate backtest report: `GET /engine/train/{id}` carries the same block, and that is the "backtest report" of the CR.
- **How to test it:**
  1. `GET /owned/{domain}/endings` for an owned name: five `endings`, `events` empty before the first daily run, five `baseline` events after it. A name we do not own (or a dropped one): 404 `DOMAIN_NOT_FOUND`.
  2. `GET /report` after a run that finds a new registration: one `ENDING_REGISTERED` per event, `details {owned_domain, host, created, registrar, kind, detected_at}`; the next run adds nothing.
  3. `POST /engine/train`, poll until `done`, then `GET /engine/health`: `slices.quick` / `slices.held` with `n`, `recall`, `net_pit_share`, `auc`.
- **Deploy:** migration `1764000000000_v5-7-0.sql` runs on start. Push to `main`, tag `v5.7.0`; it deploys to the Mac host after CI passes (`scripts/local-host/deploy.sh`, DOM). Gavriel confirms the live version on `/health`.
