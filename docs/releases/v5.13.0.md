# Release v5.13.0 (17 Oct 2026)

**Contract:** 5.13.0. Tech-debt pass R2: idempotency keys are bound to their token, cancel keeps its `reason`, the database-size warning follows Neon's 1 GB free plan, plus money-path and correctness fixes.

- **What changed:** (A) `Idempotency-Key` is bound to the token that first used it; another token reusing the key gets 409 `IDEMPOTENCY_KEY_MISMATCH`. (B) Both cancel routes store `reason`; the answers (and `GET /screening/runs/{id}` for a cancelled run) carry `cancel_reason`. (C) `DB_SIZE_HIGH` (the `/report` warning, the 409 on engine and data loads, the retention tight mode) counts against 1 GB instead of 0.5 GB. (D) Fixes: S8 / `import-domain` refuse any "cloudflare" registrar spelling; reconciler-booked trend / regulation names get `sell_or_drop_by`; the holdout date is read under the upload lock; `GET /data/tm-kills` and `/data/bigco-names` `host` filter ignores case; keep-alive ping only on Render; `last_used_at` written once a minute. Internal: dead code removed (`posts_cap` lock, `paramsFingerprint`, `wordsOf`, `replayReport`, `KEPT_LANES`, the `dotenv` dependency, `scripts/ac6-split.ts`), one `apiCents` helper, `buying/budget.ts` renamed `caps.ts`. Contract: `README.md` (Idempotency), `endpoints.md` (both cancel routes, size guard text), `reports.md`, `jobs.md`.
- **Impact on Gavriel:**
  - **Idempotency keys per token.** If Gavriel and another bot (Gizbar, a data token) ever send the same key, the second now gets 409 `IDEMPOTENCY_KEY_MISMATCH` instead of a replay. Keep keys unique per call (UUIDs); nothing else changes.
  - **Cancel.** Send `reason` and read it back as `cancel_reason`; no `reason` gives null.
  - **DB_SIZE_HIGH.** The warning and the 409 fire at 717 MB (70% of 1 GB), not 358 MB. A load that was refused near 358 MB now goes through; `details.limit_bytes` is 1073741824.
  - **S8 import.** A registrar such as `Cloud-flare` is 422 `VALIDATION_ERROR`, as `cloudflare` always was.
  - **Data reads.** `GET /data/tm-kills?host=ACME` finds a term loaded as `Acme`.
- **How to test it:**
  1. `POST /screening/runs` (dry data), then `POST /screening/runs/{id}/cancel` with `{"reason": "wrong list"}`: 200 with `cancel_reason: "wrong list"`; `GET /screening/runs/{id}` shows `cancel_reason`.
  2. Send the same `Idempotency-Key` and body with two different tokens: the second is 409 `IDEMPOTENCY_KEY_MISMATCH`; the first token's retry still replays.
  3. `GET /report` `DB_SIZE_HIGH`: absent below 717 MB; `limit_bytes` 1073741824 when present.
  4. `POST /portfolio/import` `dry_run: true` with `registrar: "Cloud-flare"` (S8 body): 422 `VALIDATION_ERROR`.
  5. `POST /data/tm-kills` a row `{term: "Acme Corp"}`, then `GET /data/tm-kills?host=acme corp`: one row.
- **Deploy:** migration `1764600000000_v5-13-0.sql` runs on start. Push to `main`, tag `v5.13.0`; deploys to the Mac host after CI passes (`scripts/local-host/deploy.sh`, DOM). Gavriel confirms the live version on `/health`.

**Lessons:** a key shared across tokens is a data leak even when only bots call the API: bind stored answers to the caller. A limit constant (Neon's size) goes stale silently; the warning had been calibrated to a plan that no longer exists.
