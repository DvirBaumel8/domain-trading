# Release v6.5.0 (4 Nov 2026)

**Contract:** 6.5.0. CR-102: prior_kill_ms on GET /auctions/shortlist and the funnel; index-use proof of the prior-kill lookup

- **What changed:** `GET /auctions/shortlist` adds `prior_kill_ms`, the server milliseconds of the query that applies the prior-kill exclusion (0 when there is no data). `GET /auctions/funnel` adds `shortlisted.prior_kill_ms`. Additive; no migration, no behaviour change.
- **Index proof:** the lookup already used an index. Per shortlist row it reads `auction_kills` by `auction_kills_domain_idx` (`btree (domain)`) and checks revokes by `auction_kills_supersedes_idx`; no Seq Scan on `auction_kills` (test CR102-T1 with 10,000 kills; plan in `docs/internal/auctions.md`). DOM did not add the `(domain, killed_at desc)` index CR-102 offered: a name has about 2.5 kills, so it would cost disk for no gain.
- **Impact on Gavriel and the bots:** one new number in two answers. Most of the 1.1 to 1.4 s measured from the box is the tunnel and proxy, not the database: compare it with `prior_kill_ms` on the same call.
- **How to test it:** `GET /auctions/shortlist?limit=200`: `prior_kill_ms` is a number of 0 or more next to `prior_kill_excluded_n`. `GET /auctions/funnel`: `shortlisted.prior_kill_ms` is present.
- **Deploy status:** pushed to `main` with tag `v6.5.0`; the Mac host deploys after CI.
- **Lessons:** a plan test (EXPLAIN in vitest after ANALYZE) is a cheap way to answer an "is it indexed" question for good; keep it for new hot lookups.
