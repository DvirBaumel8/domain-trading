# Release v2.9.0 (7 Oct 2026)

**Contract:** 2.9.0. Additive (MINOR). CR-010 v2.7.0 acceptance findings F-1 to F-5. **Deploy:** live since 2026-10-07 (`GET /health` `version: 2.9.0`).

## What changed, and how Gavriel tests each item

| Item | What | How to test it |
|---|---|---|
| **Cancel** (F-1, T10-8) | `POST /screening/runs/{id}/cancel` and `POST /selection/test-sets/{name}/cancel` (WRITE, audited). Status `cancelled`, results so far kept, unfinished checks UNKNOWN `CANCELLED`. A cancelled run is never woken or reopened by a read, a recompute or the daily run. 409 `RUN_NOT_RUNNING` if not running | Cancel `R15-T15-V2-NOW` (the replaced rescore): it shows `cancelled` at once and its `lookups` stop growing |
| **Answer source** (F-3) | Each census sibling and `ext_dates` extension has `source` (`verisign_rdap` or the RDAP host); answers stored before 2.9.0 show null | `GET /screening/runs/{id}` |
| **Run totals** (F-4) | `GET /screening/runs/{id}` adds `lookups {fresh, reused, unknown, rate_limited}` | Both views |
| **Pending** (F-5) | In a running run, a name whose checks are not all done is `pending` and not ranked | Read a run while it runs |
| **Docs** (F-2) | Test-set features name the current method and measured times | `endpoints.md` |

## Notes
- **Cancel scope:** cancel acts at once in the instance that runs the work (the one Render instance); work started elsewhere stops at its next per-name status check.
- **Migration:** `1761300000000_v2-9-0.sql` allows `cancelled` on `screening_runs` and `test_sets`, and adds `cancelled_at`, `cancelled_by` and `rdap_lookups.source`.
