# Release v5.27.0 (21 Oct 2026)

**Contract:** 5.27.0. CR-076 listing provenance, display-name route; PUT Idempotency-Key wording. MINOR (additive). Migration `1765900000000_v5-27-0.sql`.

## What changed (contract)
- **Provenance on every venue record:** `ours_confirmed` | `observed_public` | `unknown`. `POST /listings/{domain}/venue` (WRITE only; a bots token is still 403 `SCOPE_FORBIDDEN`) accepts `provenance` (`ours_confirmed` default, or `unknown`; `observed_public` is 422) and returns it.
- **New `POST /listings/{domain}/observed`** (bots or WRITE; `Idempotency-Key`; audited): body `{venue: "afternic"|"sedo", price_usd: "1488", url, seen_at (ISO with an offset), dry_run?}`. Stores an `observed_public` record: 201 (200 with `dry_run`, nothing stored). A `provenance` key is 422 `VALIDATION_ERROR`. It never changes the listing, price, export state, plan, `listing_history` or `listed_venues`.
- **`listed_venues`** (`GET /portfolio` new array field; `GET /books.csv`) counts only the latest `ours_confirmed` record per venue that is not a removal. **`observed_venues`** lists the venues whose latest record is a sighting: a new `GET /portfolio` field and the **last** books.csv column, so Sales' diff by column position keeps working (`formats.md` §Books CSV).
- **Seed (R-4), by migration:** `ours_confirmed` Afternic $1,488 for promptinjectionaudit.com, ukcbamcompliance.com, aievalsconsulting.com, roofingvoiceagent.com (listed_at 2026-10-13 15:32 UTC for the first, the migration time for the other three); mineunited.com Afternic `observed_public` ($1,488, `https://www.afternic.com/domain/mineunited.com`, seen 2026-10-20 12:00 UTC); every earlier record is `unknown`, the Sedo records of ukcbamcompliance.com and aievalsconsulting.com included. The seed does nothing for a name that is not in the portfolio.
- **New `POST /portfolio/{domain}/display-name`** (bots or WRITE; `Idempotency-Key`; audited): `{display_name}` equal to the domain apart from capitalisation, else 422 `DISPLAY_NAME_MISMATCH`; 404 `DOMAIN_NOT_FOUND`. The name is in the export rows, so a `listed` name whose display name changes gets `export_pending_since` set like a plan change and goes out in the next export. Nothing is seeded for mineunited.com: Gavriel calls it.
- **PUT and the key:** `PUT /portfolio/{domain}/forward-costs` (and every mutating PUT) needs an `Idempotency-Key`, as before. The 400 `IDEMPOTENCY_KEY_REQUIRED` message now names the method used, and the README says PUT is included.
- A sighting is never a hand listing: `GET /portfolio/{domain}` `export.<venue>`, `pending`, the `/sold` checklist and `DELIST_NEEDED` ignore `observed_public` records.

## Impact on Gavriel and Sales
- Sales can log what it saw on a public page with the bots token without it counting as ours. Only Gavriel's WRITE token can record `ours_confirmed` (a hand listing).
- After the deploy, `listed_venues` for the four Line 1 names is `afternic` and empty for mineunited.com (`observed_venues` = `afternic`). Sedo for ukcbamcompliance.com and aievalsconsulting.com reads `unknown` until Gavriel records it.
- Call `POST /portfolio/mineunited.com/display-name` with `{"display_name":"MineUnited.com"}`; the next Afternic export carries it.
- Nothing here asks Dvir to do anything.

Deploy: pushed to `main` with the tag; the Mac host deploys after CI passes. Gavriel confirms the live version on `/health`.

**Lessons:** an append-only table can still take a new column with a default (no row update, no trigger switched off), and a seed is simply new appended rows with "latest row wins"; guard every seed row on the domain existing and on the latest row, so it is a no-op on an empty database and safe to re-run. Routes that only record what a bot saw should be separate from the money route, so the token scope, not a field, decides who can write `ours_confirmed`.
