# Release v6.1.1 (1 Nov 2026)

**Contract:** 6.1.1. PATCH: no route, field or answer changes. No migration.

- **What changed (G-139):**
  - The datasave step `episodes` now works inside the database. Before, it read all of `market_names` (468k rows, 354 MB on 1 Nov) to the server on every run, folded the day in Node and wrote nearly every row back.
  - Now each sealed Dynadot day is one `UPDATE` (names that continue an episode) and one `INSERT` (new episodes); only the new names travel to the server, to get their ids. Closed auctions, GoDaddy endings and labels are staged and applied in SQL.
  - A row whose values don't change is not rewritten (`derived_at` stays). That also stops the daily table bloat.
- **Same results:**
  - Every existing market test passes unchanged.
  - The builder compared old and new code row by row on 25 random data sets of 7 rounds each.
  - One edge is now fixed: two candidate episodes that tie exactly are picked by `episode_id` instead of by table order.
- **Why:** Neon free allows 5 GB of data transfer out a month; this step alone read about 354 MB a run (31 Oct outage, G-138).
- **How to test it:** after a datasave, `GET /jobs/runs?job=datasave` shows the `episodes` step's `db.bytes_in` in the kilobytes to low megabytes, not hundreds of MB, and its `summary` counts look like the previous day's. Tests EP-139-1 (reads under 20% of the table; a second run writes nothing) and EP-139-2 (the GoDaddy source hash matches the Node formula).
- **Deploy:** tag → Mac host. No migration. Pushed before the 15:25 UTC datasave.
- **Lessons:** a step that loads a whole table to apply a day's changes looks cheap while the table is small. Write folds as set-based SQL from the start.
