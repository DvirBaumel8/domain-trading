# Release v5.20.0 (20 Oct 2026)

**Contract:** 5.20.0. CR-069 shared bots token; BUG-047 tick health + renewal price record; BUG-046 test hits dropped

**Deploy status:** pushed and tagged; the Mac host deploys after CI passes. Gavriel confirms on `/health`.

## Contract changes
- **CR-069, scope `bots`:** one shared key for all the bots, for everyday work with no money. It may do every GET, the data and intake uploads, the visits routes (not `/visits/hit`) and every other mutating route that is not a money route. A money route (a real `/buy`, `/portfolio/import`, `/list`, `/listings/*`, exports confirmed uploaded, offers, `/sold`, horizon, manual quotes, review runs and settings, selection activation, sibling approval) works with this token only with `"dry_run": true` in the body, otherwise 403 `SCOPE_FORBIDDEN`. `POST /jobs/run` stays WRITE-only. Every route is classified in code, a guard test fails for an unclassified one, and an unlisted route counts as money.
- **New `POST /tokens/bots/rotate`** (WRITE or bots caller, Idempotency-Key, audited): returns `{token, expires_old_at}`; the value is shown once and is in no audit row, log or idempotency replay (a replay answers `token: null`). The previous shared token keeps working for 10 minutes. A bots token can rotate itself.
- **`X-Bot-Name`** (optional header, up to 40 characters of letters, digits, space, `_`, `.`, `-`): stored in the audit row and shown as `bot_name` in `GET /audit`. Not a security check.
- **BUG-047, `/health`:** `jobs` is `overdue` also when no `tick` run was created in the last 26 hours. New field `jobs_last: {daily, tick}` (ISO time of the last run, `null` = never).
- **BUG-047, new `POST /portfolio/{domain}/renewal-price`** (WRITE or bots; records a number, not a money action): `{renewal_price: "22.48", source, as_of}`. `GET /portfolio/{domain}` shows `renewal_price_source` and `renewal_price_as_of`.
- **BUG-046:** the migration deletes the `visit_daily` rows of the UTC day 2026-10-19 (all test hits).

## Impact on Gavriel
- The shared token is created by DOM on the host and delivered to the shared bot computer by the host kit; nobody prints, pastes or commits the value (CR-069 item 3). Once you confirm it works for the bots, DOM retires the per-bot READ tokens and `data-engineer-upload` by a later migration (nothing is revoked in this release). Your WRITE token keeps working until CR-065 replaces what it still does.
- To rotate: `POST /tokens/bots/rotate` with a new Idempotency-Key; write the returned value to the bots' file; the old value stops 10 minutes later.
- BUG-047 record fix: record mineunited.com's renewal price from the registrar's current .com rate with `POST /portfolio/mineunited.com/renewal-price` (the price itself is handled by DOM in BUG-047).
- `/health.jobs` now also fails for a missed tick; read `jobs_last` to see which job is late.
- Nothing in this release asks Dvir to do anything.

## How to test
- With a bots token: `GET /health`, `GET /portfolio`, `GET /visits` answer 200. `POST /buy` with `{"domain": "...", "max_price": 11.5, "dry_run": true}` passes the scope (and buys nothing); without `dry_run` it is 403 `SCOPE_FORBIDDEN`. Same for `/list/{domain}` and `/sold/{domain}`.
- `POST /portfolio/{domain}/renewal-price` then `GET /portfolio/{domain}` shows the price, source and date.
- `GET /health` carries `jobs_last`.

Local tests: B520-1..B520-8, L520-1, L520-2, V520-1.

**Lessons:** a scope is only as safe as its route list: the classification table plus a guard test that walks every registered route is the pattern to reuse for any future scope. A unique active token name forced a rename of the old shared token on rotation; check unique indexes before designing a rotation. `/health` `jobs` watched only the daily job, which is why the missed ticks were silent for days: a health flag must cover every scheduled job.
