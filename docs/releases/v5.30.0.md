# Release v5.30.0 (21 Oct 2026)

**Contract:** 5.30.0. CR-073a: GET /pickproof/{date}/pool and the pool-hash recipe. MINOR (additive). No migration.

## What changed (contract)
- **`GET /pickproof/{date}/pool`** (READ or bots): `{date, data_date, pool_n, pool_sha256, seed, sources, fields, rows}`, rows `[domain, source, price_cents, passes_k1, is_two_word]` sorted by domain in byte order. The SHA-256 of the compact JSON of `[[domain, source, price_cents], ...]` is `pool_sha256`, so the Challenger can check the hash without the snapshot files. It freezes the day on first use (like the manifest) and shows no arm. About 130,000 rows, a few MB. After 45 days the rows are pruned: 410 `PICKPROOF_POOL_PRUNED` (the hash and manifest stay).
- **Manifest `sources.excluded_sales_graded`:** the names taken out as sales-graded when the day was frozen. With it, the pool can be rebuilt from the GoDaddy zip and the Dynadot upload alone. Days frozen before this release lack it; use the pool call for them.
- **The recipe** (CR-073a item 6) is in `docs/internal/pickproof.md`, "Pool-hash recipe": the input file and its data date, the item filters, the Dynadot rows, the exclusions, the order, the exact bytes hashed and the seed.
- **Doc fix (G-117):** when a GoDaddy and a Dynadot row of the same name have the same price, the pool keeps the Dynadot row. The internal doc said GoDaddy; the code is unchanged, so no frozen day changes.
- **Correction to the 5.29.0 note:** the `POST /rdap/batch` field is `domains` (the note said `names`; the contract was right).

## Impact
- **Challenger, Gavriel:** use `GET /pickproof/{date}/pool` to check `pool_sha256` for every sealed day; quote it next to the seal line. Nothing else changes.
- Nothing here asks Dvir to do anything.

## How to test (via the API)
- `GET /pickproof/2026-10-21/pool`: `pool_n` equals the manifest's; SHA-256 of `JSON.stringify(rows.map(r => r.slice(0, 3)))` equals `pool_sha256`.
- `GET /pickproof/2026-10-22/manifest` (a day frozen after the deploy): `sources.excluded_sales_graded` is a list.
- A data token on the pool call: 403. Local test: PP530-1 (`tests/modules/pickproof/pickproof.test.ts`).

Deploy: pushed to `main` with the tag; the Mac host deploys after CI passes. Gavriel confirms the live version on `/health`.

**Lessons:** a hash that outsiders must reproduce needs its inputs published with it: the server-side exclusions made `pool_sha256` impossible to rebuild from public files, and writing the recipe out turned up a doc that described the tie rule backwards.
