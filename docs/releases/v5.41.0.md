# Release v5.41.0 (25 Oct 2026)

**Contract:** 5.41.0. MINOR. One migration (`1766700000000_v5-41-0.sql`: `settings.datasave_auction_min_cents`, default 10000, CHECK >= 100). Migration count 70.

## Why
Dvir, 25 Oct 2026: feed the learned scoring engine with real data as soon as possible, free sources only. The engine had 0 sold and 0 unsold rows, and the holdout date (2026-10-14, CR-061) made the server throw away every newer row. Dvir: "sounds incorrect". The trainer already keeps the newest full calendar quarter as its frozen test file, which is the fair test.

## What changed (contract)
1. **Holdout date removed as a rule.** `POST /engine/sales`, `POST /engine/unsold` and the `/data/*` loads no longer reject a row for being dated after `engine.sales_max_date`. A future date is still `DATE_IN_FUTURE`. `HOLDOUT_SEALED` stays in the code list but is no longer returned. `GET /engine/holdout-date` and `POST /engine/holdout-date` stay (no caller breaks) and now answer `effect: "none since 5.41.0"`; changing the date changes nothing.
2. **Job `datasave` has an eleventh step, `engineFeed`** (between `buildPanel` and `pickproofSeal`):
   - Unsold: GoDaddy closeout names that left the list early and are RDAP-tagged `deleted` become `engine_unsold` rows (`dropped_after_held`, `observation_date` = the day they left the list, `caught_by_catcher` true for a re-registration, false for not registered, null for a redemption or pending-delete status).
   - Sold: GoDaddy auctions that ended with at least 1 bid and a final price of at least `settings.datasave_auction_min_cents` become `engine_sales` rows (final price, end day in Israel, venue `godaddy`, source `godaddy_auctions_file`). These are mostly investor-to-investor sales; the source marks them so they can be separated later.
   - Summary: `unsold_inserted_n`, `sales_inserted_n`, `skipped_dup_n`, `regime_n` (plus candidate counts, upload ids, `auction_min_cents`, `status`: `ok` or `db_size_high`).
3. **`buildPanel` looks up engine-regime names first** within the daily cap of 1,500 RDAP lookups (letters only, 6..20 characters, 2..3 words); `tags.regime_due_n` shows how many due names were in the regime.
4. **`godaddy_auctions` keeps auctions from `settings.datasave_auction_min_cents` ($100)** instead of a fixed $500 (migration only, never below $1). `market_names` keeps its own $500 floor.

## Impact on Gavriel
- Rows dated after 2026-10-14 now load. No change needed on his side; `GET /engine/holdout-date` is a no-op, no need to call `POST`.
- `GET /engine/health` `data.*` and `last_upload` will show `by: datasave` uploads every day. `GET /snapshots?source=godaddy_auction_end` lists more ended auctions (from $100).
- The engine's first training needs a full calendar quarter with sales in the regime; the feed builds that history from today on (no backfill of past days).

## Findings to know
- NameBio's terms forbid training models on its data without written permission (round-2 research). No engine code reads a NameBio table. **New in this release:** `POST /engine/sales` now refuses a row whose `venue`, `source` or `source_url` names NameBio (`SOURCE_NAMEBIO_FORBIDDEN`, as `POST /data/sales` already did; test EN-1b). Nothing was stored before (0 rows).
- Deploy: no deploys 23:45 to 01:00 UTC; the new step runs in the 15:00 UTC datasave run.

**Lessons:** a guard rule (the 14 Oct holdout block) was built to the letter of a request and threw away every new row for 11 days before anyone asked whether it made sense; DOM now questions a rule's effect when building it. Full suite 265 files, 2,889 tests passed before the NameBio refusal; engine and contract tests re-run after it.
