# Release v5.79.0 (30 Oct 2026)

**Contract:** 5.79.0. MINOR: one new read route (`GET /kb/load-preview`), two new reject fields (`key`, `fields`), a new count field in the `kbLoad` summary (`auto_superseded`), and a changed `kbLoad` rule. No migration.

- **What changed (CR-098, P0):** `kbLoad` failed three nights on `0008-fertilize-2026-10-28.jsonl`: 10 of its sources had been posted by a bot through `POST /kb/sources` on 26 Oct with other content.
  - **The file is the source of truth.** A file row whose key is stored with other content is now appended as the next version when the stored newest version came from a route call. The key is listed in `counts.<kind>.auto_superseded`. A clash with an earlier file still needs `"supersede": true`, and a question still can't be corrected.
  - **Errors say which row.** A failed file reads `source: N rejected: line L EXISTS_DIFFERENT <url> [title, excerpt]`, using the file line (not the place in the kind's batch), at most 5 rows, then `+N more`. Route rejects carry `key` and `fields` too.
  - **`GET /kb/load-preview`** (READ or bots) runs the next `kbLoad` on the files not yet loaded, in one rolled-back transaction, and answers its summary with `dry_run: true`.
  - **Data:** the 10 source rows in 0008 named in CR-098 carry `"supersede": true` (also covered by the new rule).
- **Not in this release:** CR-098 ask 4 (bot tokens get dry-run only on `POST /kb/*`) breaks a caller, so it ships as its own release after tonight's load is confirmed. Ask 5 (content hash) is parked: the key normalization already handles `www.` and the trailing `/`, and the new rule covers the route-row case.
- **How to test it (Gavriel):** `GET /kb/load-preview` should list `0008-fertilize-2026-10-28.jsonl` under `loaded` with `failed: []`. After 00:05 UTC 31 Oct, the daily `kbLoad` should show it under `loaded`, and `GET /kb/sources` should have those 10 URLs at `version` 2.
- **Deploy:** tag → Mac host. No migration. Pushed outside a datasave run and the 23:45–01:00 UTC window.
- **Lessons:** the loader's error named batch positions, which a person editing the file can't map to lines. That cost two nights (CR-092 fixed one author, then sources failed). Errors now name the key and the line, and the preview checks the whole file against production before the night run.
