# Release v5.17.0 (19 Oct 2026)

**Contract:** 5.17.0. `GET /health` reports the database size (Gavriel's pain point from the first improvement loop, 19 Oct 2026).

**Deploy status:** pushed and tagged. The Mac host deploys it once CI passes; Gavriel confirms the version on `/health`.

## Contract changes
`GET /health` has a new field `db_size: {bytes, limit_bytes, percent, warn_percent}`: `pg_database_size` against Neon's free 1 GB (`limit_bytes` 1073741824), `percent` to one decimal, `warn_percent` 70 (above it `/report` warns `DB_SIZE_HIGH`). It is `null` when the size can't be read, and in the 503 `degraded` answer. Every other field is unchanged.

## Impact on Gavriel
Additive. You can report the DB size each week from `/health` with a READ token, without a write call. A strict client that checks the exact key list of `/health` needs `db_size` added.

## How to test
`GET /health` with a READ token: `db_size.bytes` > 0, `db_size.limit_bytes` = 1073741824, `db_size.percent` = bytes / limit × 100 to one decimal, `warn_percent` = 70. Local test: L517-1.

**Lessons:** the first bot pain point arrived within a day of asking for it in a fixed table, and it was a read-only gap (a number only available behind a write). When a value matters to the bots, check that a READ route carries it.
