# Release v5.12.0 (17 Oct 2026)

**Contract:** 5.12.0. CR-063: one copy of the bots' data in DOM: RDAP answers for the candidate pool, live checks, trademark and big-company terms, graded comparable sales.

- **What changed:** (A) `POST /data/rdap`, `/data/live-checks`, `/data/tm-kills`, `/data/bigco-names`, `/data/sales-comps` load row arrays (WRITE or the `data` token), `GET /data/<same>` reads them (READ). (B) `domain_rdap` keeps only candidate-pool names and flags rows older than 24 h `stale`. (C) `tm_kills` and `bigco_names` are append-only; fix a row with `supersedes`. (D) `sales_comps` obeys the holdout date and links to `/engine/sales` rows. (E) The daily retention step removes live rows after 3 days, cc rows after 14 days and RDAP rows of names that left the pool. Contract: `endpoints.md` §Loaded data tables, `jobs.md` retention.
- **Impact on Gavriel:**
  - **Loads.** Data Engineer loads with the `data` token; each answer carries `db_bytes_before`, `db_bytes_after` and `rows` per table. A load that would pass 70% of 0.5 GB is refused (409 `DB_SIZE_HIGH`).
  - **RDAP.** Names outside the pool are counted in `skipped_not_in_pool_n`, not stored. Do not treat a stored row as fresh for a buy: `/check` and `/buy` do their own lookups.
  - **Reads.** Buyer, Shomer and the Scoring Scientist read with a READ token; a `data` token cannot read.
  - **Not included.** `GET /jobs/runs` does not show the load sizes (use the load answer or `GET /audit`); the term tables do not yet feed screening.
- **How to test it:**
  1. `POST /data/tm-kills` with `dry_run: true` and one row `{term, reason, source}`: 201, `dry_run: true`, `accepted_n: 1`, nothing stored (`GET /data/tm-kills` is empty).
  2. `POST /data/rdap` with a name that is in the pool and one that is not: `accepted_n: 1`, `skipped_not_in_pool_n: 1`.
  3. `POST /data/sales-comps` with a row dated 2026-10-15: `rejected_n: 1`, reason `HOLDOUT_SEALED`.
  4. A READ token on any `POST /data/...`: 403 `SCOPE_FORBIDDEN`.
- **Deploy status:** migration `1764500000000_v5-12-0.sql` runs on start (five new tables).
