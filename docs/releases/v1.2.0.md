## What's in it
- **Settings v1.2 keys:** `eu_tm`, `same_name`, `pack`, `sources.business_sites`, `freshness_hours.same_name` and `freshness_hours.tm_eu` (defaults fill the stored `v1` row; every v1.1.0 route works unchanged). A draft may add a key under `freshness_hours`. Gate lists are validated for dependency order.
- **EU trademark manual record (`tm_eu`, CAP-09):** `POST /screening/runs/{id}/manual` with `check: "tm_eu"` (EUIPO, WIPO, UK IPO search). MANUAL_REQUIRED for the lanes in `eu_tm.required_lanes` (default S6), PASS `NOT_REQUIRED_FOR_LANE` for the others.
- **FLAG verdicts:** `POST /screening/runs/{id}/verdicts` (PASS or REJECT on one FLAG result row) and `verdicts` on each name of `GET /screening/runs/{id}`. A verdict never changes `final_status` or `flags`.
- **`same_name` check (CAP-12, G8):** the same name on the other `ext.list` extensions: RDAP registration plus a polite read of each home page. **Safe outbound fetching rules:** public addresses only (connection to the vetted IP, so DNS rebinding cannot reach a private address), default ports only, redirects followed manually and re-vetted, robots.txt honoured, honest User-Agent, one request per site per `same_name.min_ms_between_fetches`, size and time caps, no login or CAPTCHA, `linkedin.com` never fetched. A site that answers but cannot be read is FLAG `SITE_UNKNOWN`, never PASS.
- **Same-run recompute:** a manual `history` record reopens a finished run and recomputes the checks that read history (`ext_dates`, `tier`, `price`, `tm_us`) in the same run, from the exact inputs each row recorded. Rows are appended; earlier ones stay.
- **Screening pack (CAP-19):** `POST /screening/packs`, `GET /screening/packs/{id}`, `GET /screening/packs?domain=`: a frozen, versioned snapshot of a finished run's current rows with `missing` codes. **`POST /buy` with `dry_run: true`** gains `screening_pack` and `advisories` (`SCREENING_PACK_REQUIRED`, `PACK_NOT_FROM_LATEST_RUN`). `would_be_blocked` is unchanged (`"BUY_HOLD"` only). A real `/buy` does not require a pack until 2.0.0.
- **Workflow:** `deploy-jobs-trigger` has a 15-minute job timeout, step timeouts and non-interactive wrangler (`CI=true`, `WRANGLER_SEND_METRICS=false`). Run 37373147693 never started: no runner picked it up (GitHub-hosted capacity), so it was not a hang (gaps G-77).

5. **`PACK_NOT_FROM_LATEST_RUN`:** a `/buy` dry run warns when the name's latest pack was built from a run that is no longer its latest run. Build a new pack.
6. **Verdict every FLAG** before issuing a pack. The judgment needs the van test, TN-1, BIGCO and one reason not to buy.
7. Record the EU trademark search for S6 names by hand (`tm_eu`).
8. **Lead verification is cut.** Gavriel verifies leads himself.
9. **Pre-deploy check (DOM):** the stored `selection_settings` gate lists must satisfy the dependency order in `selection.md` §Same-run recompute. The baseline `v1` does; a draft that breaks it is refused (`SETTINGS_INVALID`).

## How to test it (through the API, dry_run only)
WRITE token unless noted; every POST needs a fresh `Idempotency-Key`. No step buys or lists anything.
1. `POST /screening/runs` with 3-5 names, poll to `done`. `POST /screening/runs/<id>/manual` `{domain, check: "tm_eu", checked_at, evidence_url, result: {...}}` for an S6 name -> 201. `check: "history"` records reopen the run (`recompute: true`); poll again to `done`.
2. `POST /screening/runs/<id>/verdicts` on a FLAG row -> 201; on a non-FLAG row -> 422 `VERDICT_RESULT_NOT_FLAG`.
3. `POST /screening/packs` (body per `endpoints.md`) on a done run -> 201 with `missing`; on a running run -> 409 `RUN_RUNNING`. Under settings without `same_name` in the gates: incomplete with `same_name: NO_RESULT`.
4. `GET /screening/packs/<id>` and `GET /screening/packs?domain=<d>` (READ) -> the pack.
5. `POST /buy` with `"dry_run": true` for the name -> 200 with `screening_pack`, `advisories`, `would_be_blocked` unchanged. Never send a real `/buy`.
