# v5.70.0 — BUG-059: Afternic listing fallback for stale lander mismatches

**Date:** 2026-10-27
**Type:** PATCH (no migration, no new route)

## What changed

When an Afternic-NS name's primary apex/lander fetch fails (e.g. GoDaddy forsale returns HTTP 403 to our user-agent), no price check was performed and stale `LANDER_PRICE_MISMATCH` warnings (`$49,999,999`, `$100,000`) remained on `/report` indefinitely — "unknown neither raises nor clears" (contract `jobs.md`).

Now, when the primary fetch yields no usable price and the domain's lander is Afternic, `portfolioCheck` also fetches `https://www.afternic.com/domain/<name>` and parses it with the same 5.69.0 rules (512k body, LIMIT_COPY, tight "buy it now for"). If a matching BIN is found, a price `ok` row is written with `source: "afternic_listing"`, clearing the stale mismatch. If the Afternic listing also has no BIN, no new price row is written (no change in behaviour).

## Impact on Gavriel

- After deploy, the next `portfolioCheck` clears the stale `LANDER_PRICE_MISMATCH` on `roofingvoiceagent.com` ($49,999,999) and `ukcbamcompliance.com` ($100,000).
- Names whose Afternic listing page is also unreachable stay unknown (no worse than before).
- The `source: "afternic_listing"` field on the price row distinguishes fallback results from primary-fetch results.

## How to test

```
GET /health          → version "5.70.0"
POST /jobs/run       → { "job": "daily", "dry_run": true }   (portfolioCheck step)
GET /report          → no LANDER_PRICE_MISMATCH with $49,999,999 or $100,000 on Afternic-NS names
```

## Tests

- LP-13 (BUG-059 AT-1): primary 403; Afternic listing has "Buy it now for $1,488.00" + limit copy → shown $1,488; stale mismatch cleared.
- LP-14 (BUG-059 AT-2): primary 403 and Afternic listing has no usable BIN → no price row; no new mismatch.

## Lessons

A name whose lander page is behind a 403 (GoDaddy forsale to non-browser UA) will never get a price check from the primary fetch. The Afternic listing URL is a reliable, public, server-rendered alternative that carries the same BIN. Using it as a fallback is cheap (one extra GET per 403 name) and avoids false mismatches persisting forever.
