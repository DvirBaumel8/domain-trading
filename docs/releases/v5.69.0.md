# v5.69.0 — BUG-058: raise LANDER_BODY_BYTES; treat "must be below" as limit copy

**Date:** 2026-10-27  
**Type:** PATCH (no migration, no new route)

## What changed

1. **`LANDER_BODY_BYTES` raised from 200,000 to 512,000.** Current Afternic domain pages are ~337 KB; the buyer-visible "Buy it now for $1,488.00" sits at ~byte 251,000, past the old 200 KB cap. The lander price check now reads up to 512 KB, well past the real BIN on any current page.

2. **"must be below" classified as `LIMIT_COPY`.** The Afternic text "Buy Now price must be below $100,000" is offer-limit copy, not a buyer-visible BIN. The `LIMIT_COPY` regex now includes `must\s+be\s+below`, so any amount preceded by it is skipped (same spirit as BUG-054's "exceed / cannot" ceiling skip).

## Impact on Gavriel

- After deploy, the next successful `portfolioCheck` reads the full BIN on Afternic HTML pages and clears the false `LANDER_PRICE_MISMATCH` warnings (`$100,000` / `$49,999,999`) for names whose lander is reachable (R-5).
- Names behind GoDaddy 403 (`roofingvoiceagent.com`, `ukcbamcompliance.com`) stay `unknown` until GoDaddy UA handling is addressed (out of scope).

## How to test

```
GET /health          → version "5.69.0"
POST /jobs/run       → { "job": "daily", "dry_run": true }   (portfolioCheck step)
GET /report          → no LANDER_PRICE_MISMATCH with $100,000 on Afternic-NS names
```

## Tests

- LP-11 (BUG-058 AT-1): HTML >220 KB with early "must be below $100,000" and BIN past byte 200k → shown $1,488, no mismatch.
- LP-12 (BUG-058 AT-2): only "must be below $100,000" limit copy → unknown, not mismatch.

## Lessons

The 200 KB body cap was set when Afternic pages were smaller. Live pages grew; short test fixtures did not catch the truncation. Lesson: when a live check fails but the fixture passes, compare fixture size to real page size first.
