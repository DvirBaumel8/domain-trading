# Release v5.71.0 (27 Oct 2026)

**Contract:** 5.71.0. PATCH — BUG-059 Round 2: Afternic listing fallback also on unknown/no_price_text.

- **What changed:** The Afternic listing fallback in `portfolioCheck` now fires when the primary apex/lander price result is **unknown** (readable page with lander signature but no Buy Now text, e.g. `no_price_text`), not only when the primary fetch failed entirely (`price === null`). This covers the live case (roofingvoiceagent.com, ukcbamcompliance.com) where the page matches the Afternic lander signature but has no Buy Now amount because it's script-rendered or a 403 stub. When the Afternic listing page (`www.afternic.com/domain/<name>`) has a usable BIN, it writes `ok` with `source: afternic_listing`, clearing stale `LANDER_PRICE_MISMATCH` warnings.
- **How to test it:** `GET /report` after a `portfolioCheck` run: roofingvoiceagent.com and ukcbamcompliance.com must no longer show `$49,999,999` / `$100,000` mismatches. Test LP-15 (AT-1 regression): primary unknown/no_price_text + Afternic listing Buy it now $1,488 → ok/afternic_listing, mismatch cleared.
- **Tests added:** LP-15 (BUG-059 R2 AT-1).
- **No migration. No new route. No new error code.**

### Lessons
v5.70.0 shipped with `priceResult === null` as the only fallback trigger (R-6), missing the case where the primary page is readable but shows no Buy Now text. The AT-3 live check caught it immediately. Round 2 widens the condition to also cover `priceResult?.status === 'unknown'`.
