# Release v5.71.0 (27 Oct 2026)

**Contract:** 5.71.0. BUG-059 round 2: Afternic listing fallback on unknown; stale price fails stop raising.

- **What changed:**
  - `portfolioCheck` now reads the Afternic listing page when the lander gives no price result **or** an `unknown` one. In 5.70.0 it did so only when there was no result, which missed roofingvoiceagent.com and ukcbamcompliance.com.
  - `/report` skips a price `fail` when a newer price check of the same name exists, whatever its status. So a stale $49,999,999 or $100,000 row stops raising `LANDER_PRICE_MISMATCH` once a later check runs.
- **Tests:** LP-15 (primary unknown, listing $1,488 → `ok`, `source: afternic_listing`, warning cleared) and LP-16 (listing without a price either → `unknown`, the old fail raises nothing). The basic lander test now also expects the listing fallback fetch.
- **Impact on Gavriel:** after deploy and the next daily run (00:05 UTC), re-run the gates. The three names should show no `LANDER_PRICE_MISMATCH`.
- **How to test it:** `GET /report` after the next daily run (read-only).
- **Deploy:** tag `v5.71.0` → Mac host.
- **Lessons:** BUG-054 took four releases (5.66, 5.69, 5.70, 5.71), each fixing one page shape. A fix to a live parser should be tested against a saved copy of the real page **and** run once against the live names before it is called done.
