# Release v5.36.0 (25 Oct 2026)

**Contract:** 5.36.0. S8 per-name price cap raised from $50 to $250. MINOR (a limit change). Migration `1766400000000_v5-36-0.sql`.

## Why
Dvir, 25 Oct 2026, after research on closeouts vs auctions: "Let's raise the limit to 250 and make the auctions our main effort". Public auctions with real bidding mostly end above $50, so the old cap blocked them. The written rule (`CLAUDE.md`, "Main buying line") now says: within S8, GoDaddy/Dynadot public auctions get the main effort; closeouts get no money until the pick-proof shows an edge.

## What changed (contract)
- `POST /portfolio/import` (S8): `settings.s8_max_price_cents` is 25000 ($250). `S8_PRICE_CAP` (400) answers only for a `price_paid` above $250. The cap is still migration-only.

## Impact on Gavriel
- An S8 buy up to $250 can now be imported. Every buy still needs Dvir's `approval_ref` naming the domain.
- Above $50, show Dvir why the name is worth more (live businesses on other endings, age, comparable sales) before he approves.
- NameJet, SnapNames and DropCatch stay refused (`BACKORDER_SOURCE_REFUSED`).

## How to test (via the API)
- `POST /portfolio/import` with `dry_run: true` and `price_paid: 250.01` → 400 `S8_PRICE_CAP` with `details.s8_max_price_cents: 25000`; `price_paid: 250` passes the cap check.
- Local tests: S8-3 and S8-17 in `tests/modules/buying/s8-import.test.ts`.

Deploy: pushed to `main` with the tag; the Mac host deploys after CI passes and runs the migration. Gavriel confirms the live version on `/health`.

**Lessons:** a cap set before research can block the strategy research later points to. Look up how others work before fixing a limit.
