# Release v5.55.0 (26 Oct 2026)

**Contract:** 5.55.0 (MINOR, behaviour; no new fields).

- **What changed:** every one of the 25 served names scored 85+ and got the same $55 (26 Oct re-run). The maximum now also follows the name's position in the day's field: factor 1 for the top 1%, linear down to 0.4 at the top 9%, 0.4 below (`positionFactor`). Today: top 1% $55, top 4% about $40, top 9% about $20. A name whose new maximum is not above its price is dropped as no headroom. Reason line: "maximum $X: top Y% of today's field (position factor Z)".
- **Impact on Gavriel:** suggested maximums differ along the list.
- **How to test it:** after the next data save, `GET /auctions/shortlist`: `max_bid_suggested_cents` falls with `rank`. Tests AS555-1..3.
- **Deploy:** the Mac host after CI.
- **Lessons:** a maximum scaled only by a score that saturates at the top of the list is flat exactly where the decisions are made; scale by position as well.
