# Release v6.7.0 (5 Nov 2026)

**Contract:** 6.7.0. CR-104 (DOM Architect, approved by Dvir via Gavriel): the discovery pre-run gate. MINOR, one migration (three settings).

- **What changed:** new `GET /auctions/preflight` (READ or bots, optional `date`). It runs six checks and answers `{as_of, data_date, pass, checks_sha256, checks}`. It writes nothing (DOM's change to the CR: no log table, no write on a GET; the run pack's `preflight.json` is the record). The datasave job runs the same suite as its last step `preflight`, so `GET /jobs/runs` shows the daily result.
- **The checks:**
  - PF-01 `UNSCORED_ROWS`: a served shortlist row without a score, or a closeouts row with a null score that is not by design (only `NO_ACTIVE_MODEL` is).
  - PF-02 `COUNTS_DONT_RECONCILE`: the 6.6.0 identity `total + prior_kill_excluded_n + ended_n + prebid_dropped_n + not_stored_n = field_n`.
  - PF-03 `JUNK_AT_TOP`: an all-digit, hex-like or over-4-digit name in the top 50 of the shortlist or of the closeouts.
  - PF-04 `PRIOR_KILL_SERVED`: a served name with an active kill that does not re-show.
  - PF-05 `COVERAGE_UNFLAGGED` / `COVERAGE_BELOW_MIN`: a source whose pages failed without a low-coverage flag, or whose coverage is under 90%.
  - PF-06 `STALE_AS_OF`: the shortlist was built more than 12 hours before the read, or none exists.
- **Settings (migration only):** `preflight_max_digits` 4, `preflight_min_coverage_bp` 9000, `preflight_max_age_hours` **12**. The CR proposed 6 hours; DOM set 12, because the shortlist is built about 17:30 IDT and the discovery run starts at 02:05 IDT, 8.5 hours later: 6 would block every nightly run. 12 still catches a missed daily build.
- **Standing rule:** each BUG that a pre-run check could have caught adds the next PF id in its fix release; checks are retired with a reason, never removed (`docs/internal/auctions.md` "Pre-run gate").
- **Impact on Gavriel and the bots:** Buyer calls the route first in every discovery run and stops on `pass: false` (added to `docs/bot-logic/04-buyer-shortlist-to-card.md`). Expect PF-01 to fail for Dynadot today (BUG-063's rows of 4 Nov are cleaned by the 15:25 UTC datasave).
- **How to test it:** `GET /auctions/preflight`: six checks, each with `pass` and `reason_code`; after the next datasave `GET /jobs/runs` shows the step `preflight`.
- **Deploy status:** pushed to `main` with tag `v6.7.0`; the Mac host runs the migration and deploys after CI.
- **Lessons:** a default limit in a CR must be checked against the real schedule (build 17:30, run 02:05) before it ships, or the gate blocks every run on day one.
