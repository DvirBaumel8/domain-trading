# Release v5.73.0 (28 Oct 2026)

**Contract:** 5.73.0 (MINOR: two new error texts in the datasave results, no route change, no migration). Fixes BUG-060, BUG-061 and BUG-062, all seen in the 28 Oct datasave `run_9a1ec5a7`.

- **What changed:**
  - **BUG-060 (GoDaddy sealed yesterday):** GoDaddy published the 28 Oct files at about 15:07 UTC, two minutes after the Mac trigger. `godaddyInventory` now fails when the newest file day is older than the run's UTC day (`failed` entry `GODADDY_NOT_PUBLISHED: newest file day D-1, run day D`). The existing 60-minute retry run then seals today, without a WRITE rerun. Yesterday's sealed day is not touched, and the later steps run on it as before.
  - **BUG-061 (aftermarket "lock expired"):** the cause was not the lock's length (the step's budget is 60 minutes). At 15:27:46 UTC Neon closed a database connection (`57P01`, "terminating connection due to administrator command"). That connection was the one holding the job lock, checked out from the pool for the whole run, with no error listener. Node treated the unhandled error event as fatal and the server restarted. The new process found the step still `running` and failed it as `lock expired`. Two fixes:
    - Every checked-out database client now gets an error listener, so a dropped connection is logged instead of crashing the process.
    - A Dynadot pull step that fails without writing its own manifest (crash, lock expired, timeout) leaves an `error` manifest for its day: `error: "STEP_FAILED: <step error>"`. `GET /snapshots?date=D&source=dynadot_aftermarket` shows the hole instead of an empty list. A sealed day or an open `gap` row is never overwritten, and a later run or bot upload can still seal the day.
  - **BUG-062 (dqMarket "integer out of range"):** the price-sanity check multiplied an int4 price by 10. A Dynadot listing over about $2.1M overflowed. The price is now read as bigint. Failed checks remain data (`alert`), as before.
- **Tests:** DS573-1 (not published → retry seals today), DS573-2 (dead step → `STEP_FAILED` manifest), DS573-3 (checked-out client error is logged, not thrown), MK562-1 (a $20M listing does not overflow). The fixtures of DS550-1 and RPY81-6 now publish files dated on the run day, because a run on a later day than its files now fails `godaddyInventory`.
- **How to test it (Gavriel):**
  - After the next datasave, check `GET /jobs/runs?job=datasave`: `dqMarket` should be `ok`.
  - If GoDaddy publishes late again, `godaddyInventory` shows `GODADDY_NOT_PUBLISHED` and a `datasave-retry` run follows an hour later. `/snapshots/missing` should not list today after the retry.
- **Impact on Gavriel:** no WRITE rerun needed when GoDaddy is late. A failed Dynadot pull is visible in `GET /snapshots`.
- **Deploy:** tag → Mac host. Pushed outside the 23:45–01:00 UTC window, after the day's datasave and its rerun had finished.
- **Lessons:** BUG-061 looked like a lock-length problem, and the real cause was only in the host log (an unhandled pg error and a restart). Read `api.log` around the failure time before changing a timeout.
