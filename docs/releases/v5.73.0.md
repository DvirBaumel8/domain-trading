# v5.73.0 — BUG-060: datasave stale-day retry and schedule shift

**Date:** 28 Oct 2026
**Type:** MINOR (no migration, no new route)

## What changed

**BUG-060:** the Mac datasave at ~15:05 UTC sometimes raced GoDaddy's inventory publish (~15:07 UTC), finding only yesterday's sealed files. The step reported `ok: true` for the already-sealed day and queued no retry, so `/snapshots/missing` listed today until a human ran a WRITE datasave.

Two fixes, applied together:

1. **Schedule shift:** the LaunchAgent now fires at minute 35 (was 5) and the trigger script starts from 15:30 UTC (was 15:00), giving GoDaddy's publish a comfortable margin. The normal trigger is at **15:35 UTC**.

2. **Stale-day retry:** when `godaddyInventory` sees every file already sealed from a previous data date and today's UTC date is newer, the step returns `ok: false` with `failed: [{reason: "DATA_DATE_STALE", data_date, expected, message}]`. This triggers the existing 60-minute retry path, so a second run picks up today's files once they appear — without a manual WRITE trigger.

## Impact on Gavriel

- The daily shortlist arrives ~30 minutes later (15:35 instead of 15:05).
- No change to any route, response shape, or error code.
- If GoDaddy publishes later than 15:35 UTC, the automatic retry covers it (about 60 minutes later); no human action needed.
- `GET /jobs/runs?job=datasave` shows `godaddyInventory.summary.failed[0].reason = "DATA_DATE_STALE"` when the stale detection triggers.

## How to test (via the API, `dry_run`)

No `dry_run` applies; this is an operational timing fix. Verify after ship:

1. Check `GET /jobs/runs?job=datasave` — the `godaddyInventory.summary.data_date` should equal today's UTC date after a normal run.
2. `GET /snapshots/missing` should not list today after a successful datasave.
3. If `DATA_DATE_STALE` ever fires, a retry run should appear in `GET /jobs/runs?job=datasave` about 60 minutes later with today's data sealed.

## Deploy

After `install.sh` (which rewrites the plist) and the next `deploy.sh` run, the LaunchAgent fires at :35 instead of :05. No migration needed.

## Tests

BG060-1 (AT-1), BG060-2 (AT-2), BG060-3 (AT-4) in `tests/modules/ops/datasave.test.ts`.

## Lessons

The original 15:05 UTC trigger assumed GoDaddy always publishes before 15:00 UTC. Evidence from 28 Oct 2026 shows the publish can be as late as ~15:07 UTC. A defensive retry on stale data eliminates the race regardless of the publish time.
