# Release v5.77.0 (29 Oct 2026)

**Contract:** 5.77.0 (MINOR: additive fields and a looser size guard for small writes; no migration).

- **What changed:**
  - **CR-097 (size guard):** on the write routes (`POST /engine/*`, `/data/*`, `/kb/*`), a request body of at most 64 KB is refused only past **95%** of the 1 GB limit. A larger load still stops at 70%, and so does the datasave `engineFeed` step. The 409 `details` add `stop_percent`. `/health` and `/report` still warn from 70%.
  - **CR-096 (`price_sanity` samples):** `GET /market/dq` `price_sanity.detail.samples` lists up to 20 rows per sub-check, largest ratio first. `/report` `DQ_MARKET_FAIL.failures[]` carries the same `samples`.
  - **CR-095, part 1 (database size):**
    - `snapshotRetention` runs a plain `VACUUM (ANALYZE)` of `dynadot_rows`, `datasave_pool` and `godaddy_auctions_live` after its deletes, so the day's new rows reuse the freed space instead of growing the files.
    - `episodes` does the same for `market_names` after its daily fold.
    - Both summaries show `vacuum: {tables, ms, error?}`. A vacuum error never fails the step.
    - `/health.db_size.tables[]` adds `heap_bytes`, `index_bytes` and `dead_rows_estimate`, so the next step (compaction of the bloated tables) is chosen from real numbers.
  - **engineFeed after a skip:** nothing is lost. Every source is read again by the next run (by name and day, or `fed_at is null`), so the first run with room backfills the skipped days, including 29 Oct's 900 closeout expiries. Until then `/health.datasave_detail` shows `engineFeed` `db_size_high`.
- **Tests:** HG-7 and DT-9 (updated to the CR-097 rule: bulk refused at 70%, small refused at 95%), CR097-1 (6-row card evidence at 74.2% → 201), CR096-1, L538-1 (the new table fields).
- **How to test it (Gavriel):**
  - Replay the pending CR-083 card-evidence POST with a new Idempotency-Key: expect 201 at today's 74%.
  - Read `GET /health` `db_size.tables` for the heap, index and dead-row split.
  - After the next datasave, check `snapshotRetention.vacuum` and `episodes.vacuum` in `GET /jobs/runs?job=datasave`.
- **Impact on Gavriel:** small writes are no longer blocked between 70% and 95%. Bulk loads (snapshots, KB files over 64 KB) still wait for CR-095 part 2.
- **Deploy:** tag → Mac host, outside the datasave and the 23:45–01:00 UTC window.
- **Lessons:** the size guard was written for bulk uploads, then reused for every write route without asking whether a 2 KB evidence row should be stopped by a warning line. When a guard is shared, check what it blocks for each caller.
