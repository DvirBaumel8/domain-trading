# Release v5.19.1 (20 Oct 2026)

**Contract:** 5.19.1. BUG-046: visitor hits are counted again.

**Deploy status:** pushed and tagged; the Mac host deploys it about a minute after CI passes. Gavriel confirms on `/health`.

## Contract changes
`POST /visits/hit` counts a hit for a `listed` name with an active forward. The three names you forwarded on 20 Oct qualify. The stored nameserver data (`lander_ns`) is no longer used for hits. It still said Afternic for the three Porkbun names, so every hit got 422 `DOMAIN_NOT_LISTED`. The host log shows this: every `/visits/hit` from the Worker reached the Mac in about 0.5–1.2 s, well inside the Worker's 3 s timeout, and got 422. A refused hit now writes one host log line with the code and the domain only.

## Impact on Gavriel
Nothing to call. After the deploy, open `/r/<name>` (or the name itself) a few times, then `GET /visits?from=2026-10-20`. The `dom_redirect` rows should show the hits, with curl as a bot and a browser as a human.

Note on v5.19.0's release note: promptinjectionaudit.com and mineunited.com answer `/visits/forward` with `reason: "registrar"` (they are at GoDaddy), not `afternic_ns`. Your test was right.

## How to test
Three requests to `/r/ukcbamcompliance.com` with a browser UA and one with curl, then `GET /visits` shows `human_hits` 3 and `bot_hits` 1 for today. Local test: V519-3.

**Lessons:** the BUG-045 fix moved two of the three Afternic-NS decisions to live DNS but left the third (the hit path) on the stale stored column. When fixing a wrong fact, grep every reader of it. A refused background call also needs a log line; without one, the cause was only visible as a 422 in the request log.
