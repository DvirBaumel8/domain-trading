# Release v5.64.0 (27 Oct 2026)

**Contract:** 5.64.0 (MINOR, migration). JOINT-OPS build order #4: CR-083.

- **What changed:** a card evidence cache. Buyer and Risk Gate post the result of each USPTO check or firm screen once (`POST /data/card-evidence`); the next bot reads it (`GET /data/card-evidence?domain=` or `term=`) and re-judges without re-fetching while the row is `fresh` (24 hours for USPTO checks; any newer tm-kill makes it stale). Append-only; a wrong row is corrected by a new row with `supersedes`. No trademark lookup from the service; no money path.
- **Impact on Gavriel:** Buyer posts its checks; Risk Gate reads first and re-scrapes only when `fresh: false`, the kill list changed, or its Opinion demands live (JOINT-OPS R2). Send `X-Caller`.
- **How to test it:** `POST /data/card-evidence {"rows":[{"term":"example","kind":"uspto_check","verdict":"clear","checked_at":"..."}],"dry_run":true}`; `GET /data/card-evidence?term=example`. Tests CR083-AT1..AT6, CEC-1..10.
- **Deploy:** the Mac host after CI.
- **Lessons:** independence of judgment does not need independence of fetching: one stored fetch, many judges, saves tokens on every card.
