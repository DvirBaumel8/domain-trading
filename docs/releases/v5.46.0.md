# Release v5.46.0 (25 Oct 2026): the unsold feed for names that stayed to their end, auction score v2, the Mac starts the data save, engine age leak fix

Contract MINOR. Migration `1767100000000_v5-46-0.sql` (table `closeout_expiries`, three `settings.closeout_expiry_*` columns). Source: `docs/internal/loop/first-live-run-2026-10-25.md` problems 1, 2 and 4, and the engine lab (`docs/research/engine-lab-2026-10-25.md`).

## What changed
- **Unsold feed (problem 1):** GoDaddy closeout names that stayed on the list to their end date are recorded while the pool still holds them (`closeout_expiries`) and checked by RDAP from 3 days after the end, again every 7 days until decided or 80 days after the end. 404, redemption / pending delete, or a registration created after the end = `dropped` (an `engine_unsold` row, `dropped_after_held`, `observation_date` = the end day in Israel, `caught_by_catcher` true for a new registration); a moved expiry date = bought and renewed (not unsold). The checks share the 1,500 per-run lookups with the disappearance tags (tags first, regime names first). `buildPanel` returns `expiries`; `engineFeed` returns `expired_unsold_candidates_n` and `expired_unsold_inserted_n`.
- **Auction score v2 (problem 2):** `score_version` `auction-v2`. Every word must be a common word (frozen lists); the name part is multiplied by the word quality, a name with an uncommon word is capped at 50 (about 35 for a coined string), shape is graded by letters, and `SCORE_FULL_MAX` is 85 (was 70), so only strong names get the full suggested maximum. `parts.name` adds `word_quality`, `word_levels`, `all_common`. Stored `auction-v1` rows are unchanged.
- **Mac trigger (problem 4):** LaunchAgent `com.domaintrading.datasave` + `datasave-trigger.sh` start the datasave at 15:05 UTC from the Mac (same Idempotency-Key as the GitHub workflow, so GitHub's late run is a replay). GitHub stays as the backup.
- **Engine date leak (lab finding):** `com_age_years` is whole years (floor). A dropped name is dated at its expiry anniversary, so a fractional age gave the label away (lab: 678 of 686 drops at N.0 or N.2 years; AUC 0.96 full against 0.74 clean). The new closeout-expiry label is tied to the same anniversary. The `acq_*` 36-month cut is kept (coarse). `trend_pit_*` and `tok_rate_pit` can leak when sold and unsold rows cover different date ranges; in the live feed both start on 25 Oct 2026. No model exists in production yet, so nothing is retrained.

## Impact on Gavriel
- The shortlist scores spread (about 30 to 90) and the suggested maximum bids differentiate: coined names get 40-50% of the full maximum or less, good phrases 90-97%. `score_version` is `auction-v2` on new rows.
- `GET /jobs/runs?job=datasave` shows the new summary fields. The run starts at about 15:05 UTC (not 18:20).

## How to test via the API
Read only: `GET /auctions/shortlist` (`score_version`, `parts.name.word_quality`), `GET /jobs/runs?job=datasave` (`buildPanel` `expiries`, `engineFeed` `expired_unsold_*`). The first `dropped` rows appear after 28 Oct - 1 Nov (names collected 25-28 Oct become due 3 days after their end).

## Deploy status
Pushed to `main` with the tag; the Mac deploys after CI. DOM runs `install.sh` and loads the new datasave agent on the host, then re-runs the data save with its own token.

**Lessons:** a label that is dated by a rule of the data source (expiry anniversary) leaks into any feature that is also dated by that rule; check the feature against the label date before shipping a new label source. A schedule we do not control (GitHub) is a delay we pay every day; the host that owns the data should start it. Word quality from offline lists separates most coined strings (thrune, idward) from real phrases, but not all (finsplat: two dictionary words): the trained model or the lift score has to take over. Full suite: 275 files, 2,975 tests passed.
