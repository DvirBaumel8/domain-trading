# Release v5.15.0 (17 Oct 2026)

**Contract:** 5.15.0. Tech-debt pass R4: dead features and duplicated code are gone. No route, field or error code changed.

- **What changed:** (A) The automated Internet Archive history reader is deleted (Dvir's decision of 6 and 14 Oct 2026); `history` is still a manual HIST-2 record, `sources.wayback` can only be `false`. (B) NameBio: only RetailStats (POST and the CSV file) is called, the unread TLDStats table and drop-order calls are removed, the CSV is capped at 100 MB and filtered to the keywords the service can ask about, and `namebio.spot_max_per_min` leaves the settings document. (C) `/buy`, `/list` and the import share one plan-writing function; the `/buy` code is split into five files; the CR-063 `/data/*` tables moved to their own module on the same bulk-upload helper as `/engine/sales` and `/engine/unsold`; the job audit rows and both command-line tools share helpers. (D) Unused exports, imports and constants removed. Contract: `selection.md` (history, sources, NameBio), `test-evidence.md`.
- **Impact on Gavriel:**
  - **Settings.** `GET /selection/settings` no longer lists `namebio.spot_max_per_min`; a draft that sets `sources.wayback: true` is refused (422 `SETTINGS_INVALID`). Nothing else in a settings draft changes.
  - **NameBio.** If `sources.namebio` is on and the CSV URL is set, `GET /selection/namebio?keywords=x` has data only for keywords of intake names, owned domains and names screened in the last 90 days; screen or submit the name first. The `referenceRefresh` NameBio summary reports a CSV over 100 MB as an error and stores nothing from it.
  - **History.** No change for you: record HIST-2 by hand or through a domain record as before.
  - **Nothing else to change.** `/buy`, `/list`, `/data/*`, `/engine/*` answer with the same shapes and values.
- **How to test it:**
  1. `POST /buy` with `dry_run: true` and `POST /list` with `dry_run: true` for a name you know: same `proposed_listing`, `would_be_blocked` and `screening_pack` as on 5.14.0.
  2. `POST /data/rdap` with `dry_run: true` and one row: 201 with `accepted_n`, `db_bytes_before`, `db_bytes_after`, `rows` as before.
  3. `GET /selection/settings`: no `namebio.spot_max_per_min`; `sources.wayback` is `false`.
  4. A screening run with `history` in its plan: MANUAL_REQUIRED `MANUAL_SOURCE` until a record is posted.
- **Deploy:** migration `1764800000000_v5-15-0.sql` runs on start (drops one table; instant). Push to `main`, tag `v5.15.0`; deploys to the Mac host after CI passes (`scripts/local-host/deploy.sh`, DOM). Not during the nightly run (23:45 to 01:00 UTC). Gavriel confirms the live version on `/health`.

**Lessons:** a test that moves a database sequence by hand must do it before the code under test can run, not after the call that starts that code (the worker started by the POST raced the test body); and a "should only grow" assertion about a size read from the database (`pg_database_size`) is false whenever the server checkpoints, so assert presence, not order. When a feature is permanently disabled, delete it: the dead path kept over 2,000 lines of code, tests and recorded fixtures and a 5,000-character contract row alive.
