# Release v5.23.0 (21 Oct 2026)

**Contract:** 5.23.0. CR-075 market episodes, labels, matched sets, data-quality checks. MINOR (additive). Migration `1765500000000_v5-23-0.sql`.

## What changed (contract)
- **New route `POST /data/sales`** (bots, WRITE or data token; `Idempotency-Key`; audited, the audit row keeps `[n rows]`; `dry_run` supported). Add-only sale reports, up to 5,000 rows a call. Exact row (strict; prices are **integer cents**; `name` is lowercased, IDN as punycode):
  - `{"name": "name.com", "venue": "dnjournal", "sale_price_cents": 125000, "sale_date": "2026-10-14", "source": "dnjournal_weekly", "tier": "B"}`, optional `source_url`, optional `listing_type` (`bin` default, `offer`, `auction`, `closeout`).
  - `tier` is required (`A`..`D`). A `source` or `source_url` containing `namebio` (any case) is refused. Either way the whole call is **422 `VALIDATION_ERROR`**, nothing stored, `details.rejects` lists `{row, reason}` (`SOURCE_NAMEBIO_FORBIDDEN`, `TIER_REQUIRED`, ...).
  - **Add-only.** Key of a row: `(name, venue, sale_date, source)`. Same key, same price: counted as `duplicate_n`. Same key, **changed price: 409 `APPEND_ONLY`** (whole call, nothing stored, `details.conflicts` shows the stored and the sent price). The same sale from another source is kept as its own row; the episode uses the highest tier and lists the others in `dup_sources`.
  - **`PUT`, `PATCH`, `DELETE` on `/data/sales` and `/data/sales/{id}` answer 405 `APPEND_ONLY`** (for any token; no `Idempotency-Key` needed to get the 405).
  - Answer 201: `{dry_run, received_n, accepted_n, duplicate_n, rejected_n, below_floor_n, audit_id}`. A sale under $500 is stored but makes no episode (`below_floor_n`). A sale shows in the episodes after the next `datasave` run.
- **`GET /market/episodes`**: summary counts first (`by_outcome`, `by_rule`, `by_band`), then rows; filters `outcome`, `rule`, `band`, `from`, `to` (on `first_seen`), `venue`, `limit` (1000 max). Row fields: `episode_id`, `name`, `sld`, `tld`, `venue`, `listing_type`, `list_price_first/last` (cents + display), `price_changes`, `first_seen`, `last_seen`, `days_listed`, `seen_days`, `outcome`, `outcome_rule`, `sale_price` (cents + display), `sale_date`, `source`, `source_url`, `source_sha256`, `tier`, `feat_asof`, `dup_group`, `dup_sources`, `price_band`, `letters_only`, `sale_only`.
- **`GET /market/matched?asof=&ratio=4&seed=`**: each positive (a sold `.com` episode, sale date up to `asof`) gets up to `ratio` negatives (`UNSOLD_60D`, `.com`, same price band, same letters-only flag, listing overlapping a window of 30 days either side of the sale date). The draw is seeded; a negative is used once. **Frozen:** the first call stores the set with a sha256 (canonical JSON, keys sorted) and later calls with the same `(asof, ratio, seed)` return it unchanged, even after new data. Rows failing the leakage check are excluded. `unknown` is never in either class.
- **`GET /market/dq`** and **`GET /market/coverage`**: the latest checks; rows per source per day, counts per label and band, `unsold_30d_n`, `unsold_60d_matched_n` and progress against the targets (1,000 by 2026-11-25, 2,000 by 2026-12-20), `db_rows`.
- **Labels (R-2).** `SOLD_REPORTED` (a sale report for the name, from `first_seen` to 90 days after `last_seen`), `SOLD_BIDS` (a GoDaddy auction ending or Dynadot closed auction with at least 1 bid; reported separately), `UNSOLD_60D` (on two or more sealed snapshot days spanning 60+ days and still listed; a name that left the source counts only after 90 days from `first_seen`), `UNSOLD_30D` (provisional, 30..59 days), `unknown` (`SEEN_ONCE`, `DISAPPEARED`, `TOO_SHORT`; never counted). A gap between sightings splits an episode only if the name was absent from a sealed day and the gap is more than 7 days.
- **`tier`:** `A` = GoDaddy's official inventory files, `B` = the bots' Dynadot uploads, sales carry their own. **Storage (Q1):** nothing under $500 is stored; the closeout pool is not in `market_names`; `db_rows` in `/market/coverage` shows the size.
- **`datasave` job:** steps `episodes` and `dqMarket` run last (seven steps now). `episodes` is idempotent and re-derives from all sealed sources on every run, so a Dynadot upload that arrives after 15:00 UTC is picked up by the retry run or the next day. No new schedule.
- **`GET /health`** adds `dq_market` (`ok | alert | unknown`; `status` is unchanged). **`/report`** adds `DQ_MARKET_FAIL` when a check fails. New code `APPEND_ONLY`.

## Impact on Gavriel
- DOM Architect / Data Engineer can start posting sales (weekly DNJournal / DNW files) to `POST /data/sales` with the shared bots token or a data token. Send `tier` and a real `source` name on every row; a NameBio source is refused. A wrong price cannot be fixed by re-posting (409); report it to DOM in the CR file.
- Nothing appears in `/market/episodes` before the first `datasave` run of 5.23.0 (15:00 UTC); the first `UNSOLD_30D` rows need 30 days of Dynadot saves.
- Watch `/health.dq_market`: `alert` means a check failed; `GET /market/dq` names it (a Dynadot day at under half its usual size is the one to expect first). `unknown` before the first run.
- Nothing here asks Dvir to do anything.

## How to test (with `dry_run`)
- `POST /data/sales` with `"dry_run": true` and one row: the answer shows `accepted_n: 1` and nothing is stored. The same row without `dry_run`, then again with a changed `sale_price_cents`: 409 `APPEND_ONLY`. A row with `"source": "NameBio"` or without `tier`: 422.
- After the next `datasave` run (or `POST /jobs/run {"job":"datasave"}`): `GET /market/episodes?outcome=sold` shows the sale, `GET /market/coverage` the counts and targets, `GET /market/dq` the checks.
- `GET /market/matched?asof=2026-12-20&ratio=4&seed=1` twice: the same `sha256` and rows.
- Local tests: MK523-1..MK523-21 (`tests/modules/market/market.test.ts`); DS521-4, DS521-6 and the `/health` key test updated for the two new steps and `dq_market`.

Deploy: pushed to `main` with the tag; the Mac host deploys after CI passes. Gavriel confirms the live version on `/health`.

**Lessons:** a label that depends on the clock (a name that left the source, unsold only after 90 days) must be recomputed from stored facts on every run, not frozen at the first sight, or a late sale report can never correct it; and a fixture name with a digit silently changes the letters-only flag in a matched set, so the matching fixtures use letters only.
