# Release v6.3.0 (4 Nov 2026)

**Contract:** 6.3.0 (MINOR). CR-100: stop `market_names` growing about 28 MB a day.

- **Why:** the datasave `episodes` fold moves `last_seen` forward for about 357k of the 470k episodes every day. Each move rewrote the whole wide row (~300 B), so the table held two versions of nearly every row and grew again after the 6.2.0 index rebuild (74.0% → 69.3% → 74.1% in one day).
- **What changed:**
  - **Storage:** `market_names` is now a view over two tables.
    - `market_episodes` holds the wide part. It is written only when an episode starts or its label or source changes.
    - `market_episode_seen` holds `last_seen`, `seen_days`, `list_price_cents_last` and `price_changes`: about 40 B a row, only a primary key, fillfactor 50. The daily update is in place (HOT): no new row version in the wide table, no index entry.
  - **The view:** same columns, order and types as before.
    - `days_listed` = `last_seen - first_seen` (unchanged rule).
    - A Dynadot Buy-Now row's `source_sha256` is the sha of the complete `dynadot_aftermarket` manifest of its `last_seen` day, the same value as before.
    - INSTEAD OF triggers keep every other writer working; `episodes` writes the two tables directly.
  - **Changed meaning:** a market episode's `derived_at` is when it was created or its label or source last changed (the daily continue no longer bumps it).
  - `GET /db/report` age keys are `market_episode_seen` and `market_episodes`. `dbMaintenance` and the datasave vacuum use the two tables. `/market/coverage.market_names_bytes` sums both.
- **Migration order (disk headroom, about 290 MB free on 4 Nov):** each file is one transaction, and space is freed at each commit.
  1. `…v6-3-0-pre` drops the old table's three secondary indexes (46 MB).
  2. `…v6-3-0` copies the data into the two tables and drops the old table. Peak about 220 MB extra.
  3. `…v6-3-0-indexes` builds the three secondary indexes on `market_episodes` and runs ANALYZE.

  The migrations run in `start.sh` before the server starts, so nothing reads in between.
- **Measured locally** (50k rows, 3 folds): 53.0 MB → 29.5 MB (−44%); HOT updates 32% → 100%.
- **Impact on Gavriel:** none to the answers except the `derived_at` meaning. Check `/db/report` after the deploy and after today's datasave.
- **How to test it:** `GET /market/episodes?limit=5` answers as before; `GET /db/report` lists `market_episodes` and `market_episode_seen`; after the datasave, step `episodes` has the usual counts.
- **Deploy status:** pushed to `main` with tag `v6.3.0`; the Mac host deploys after CI.
- **Lessons:** a fillfactor change alone can't save a table whose every row is rewritten daily; split the hot columns out. Check the migration's disk peak against prod free space before release (an extra pre-migration dropped 46 MB of indexes first).
