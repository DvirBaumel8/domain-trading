# Release v4.1.0 (13 Oct 2026)

**Contract:** 4.1.0 (MINOR, additive). CR-050 part 1, the sibling scan. Part 2 (the free dropped-names feed) is not built; it waits for Dvir's CZDS access.

- **What changed:**
  - `POST /selection/sibling-scan` (WRITE): `{domains: [...]}`, 1 to 20 `.com` names. For each name it checks the same words on net, org, io, co, ai, us and co.uk, the hyphenated `.com` at the word boundaries, and `get` / `try` + the name. RDAP says registered or not (`null` with a `reason_code` where an ending has no public RDAP, never guessed). A registered sibling's home page is fetched safely (robots, paced, at most 3 redirects) and judged: `live_business` is true only for a real site answering 200; parked, for-sale, marketplace redirects and 4xx pages are false.
  - Per sibling: `url`, `http_status`, `fetched_at`, `title`, `company` (og:site_name or title, at most 120 characters) and `contact_url` (a same-site link whose path or text says "contact"). **No email address and no person name is stored or returned**; the scout opens the contact page.
  - `lead_points {points, formula, live_n, parked_n}`: 10 per live business sibling (counted up to 3), 2 per registered-but-parked one (counted up to 3), at most 30, 0 when nothing is registered. `formula` shows the arithmetic. The weights are the new `siblings` selection setting, not code; older settings versions read the defaults.
  - `GET /selection/sibling-scan/{domain}` (READ): the newest stored scan, so a card can cite it. 404 `SIBLING_SCAN_NOT_FOUND` if none. Scans are kept (append-only); each has `fetched_at`, `upstream_calls` and `complete`.
- **Impact on Gavriel:** none to existing calls. Run `ets2compliance.com` and `drscompliance.com` once it is live. A call with 20 names can take a minute or more (paced fetches); the whole call has an 80 s budget, after which the remaining siblings come back `reason_code: TIMEOUT` and `complete: false`. Scan again (RDAP answers are cached) or send fewer names per call.
- **How to test it:** `POST /selection/sibling-scan` with a fresh `Idempotency-Key` and `{"domains": ["ets2compliance.com"]}`, then `GET /selection/sibling-scan/ets2compliance.com`. A non-`.com` name gives 422 `TLD_NOT_SUPPORTED` and fetches nothing. (The scan reads real public sites, so there is no `dry_run`.)
- **Deploy:** tag v4.1.0; migration `1763200000000_v4-1-0.sql` adds `sibling_scans`. Confirm `version: 4.1.0` on `/health`.
