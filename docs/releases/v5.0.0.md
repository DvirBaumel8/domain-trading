# Release v5.0.0 (14 Oct 2026)

**Contract:** 5.0.0 (MAJOR). G-86: the service no longer tracks a money budget (POC cap, tranche spend cap, small-buy weekly cap and the /report budget block removed); Gavriel owns the budget.

- **What changed:** Dvir, 14 Oct 2026: "You shouldn't be aware of budget at all. That topic should be managed by grok bot. Delete all related code and rules and update grok for that." The service no longer holds, checks or reports a money budget. The 40-domain cap, the per-call `max_price`, Dvir's approval rules, the ledger and the plain accounting facts in `/report` (spent, sales, profit, ROI, dates) are unchanged.
- **Impact on Gavriel:** you now own the budget. **Before you ask Dvir to approve a buy, check the spend yourself** (the $1,500 figure is yours to keep): read `spend.spent` in `GET /report` or the ledger, and add the open purchases and the quote you are about to approve. The service will not refuse a buy for money any more; only Dvir's approval, the domain cap, `max_price` and the other gates apply. Removed:
  - **Codes:** `POC_CAP_EXCEEDED`, `TRANCHE_SPEND_CAP`, `SMALL_BUY_WEEKLY_CAP` (and the admin import warning `POC_CAP_EXCEEDED_BY_IMPORT`). `would_be_blocked` no longer takes the first two of them or the third.
  - **`POST /buy` fields:** dry run `poc_spent`, `poc_spent_cents`, `poc_remaining_after`, `poc_remaining_after_cents`, `small_buy`; 201 `poc_spent_after`, `poc_spent_after_cents`, `poc_remaining`, `poc_remaining_cents`.
  - **Tranches:** `POST /tranches` input `spend_cap`; `POST /tranches/{id}/members` input `est_cost`; view fields `spend_cap_cents`, `spend_cap`, `committed_cents`, `committed`, member `est_cost_cents`. Stop sending the inputs (422 otherwise).
  - **`GET /selection/buy-hold`:** `small_buy` is now only `{max_first_year_cents, max_first_year}`; step 7 evidence has no `cap_cents` / `cap`.
  - **`GET /report`:** `budget` is now `spend` with `spent` (pair), `committed_forward` and `domains`; `budget.poc_cap` and `budget.remaining` are gone. `?format=md` heading `## Budget` is `## Spend`. Gizbar's read of `spent`, sales, profit and ROI keeps working under the new key `spend`.
  - **Still there:** the small-buy exception itself and its $11.08 price ceiling (`SMALL_BUY_PRICE`), `DOMAIN_CAP_REACHED`, `PRICE_ABOVE_MAX`.
- **How to test it:** `POST /buy` with `dry_run: true`: no `poc_*` field in the 200, and `would_be_blocked` is one of `BUY_HOLD`, `SCREENING_PACK_REQUIRED`, `NO_TRANCHE`, `SMALL_BUY_PRICE`, `DOMAIN_CAP_REACHED` or `null`. `GET /report`: `spend` has `spent`, `committed_forward`, `domains`. `GET /tranches`: no `spend_cap` fields. `POST /tranches` with `spend_cap` is 422.
- **Deploy:** tag `v5.0.0`; migration `1763400000000_v5-0-0.sql` runs on start (drops three unused columns). DOM deploys it on the Mac after CI passes; confirm the live version on `/health`. Update your own rules and prompts: the budget is yours.
