# Release v6.2.0 (3 Nov 2026)

**Contract:** 6.2.0 (MINOR, additive). CR-100 part 1: measure the database, then rebuild indexes safely. **No row is deleted by this release.**

- **What changed:**
  - **`GET /db/report` (READ, new).** For the 10 largest tables it shows:
    - heap, index and TOAST bytes, and the heap's free space (null if Neon doesn't allow `pgstattuple_approx`);
    - each index's bytes and `idx_scan`, plus `stats_reset_at`;
    - for tables with a date column, rows and bytes by age (`le_3d`, `3_30d`, `gt_30d`).

    It is computed inside the database (only the totals cross to the server) and cached 60 minutes, so repeated reads don't wake Neon.
  - **New daily step `dbMaintenance`**, after `retention`. It covers `market_names`, `dynadot_rows`, `datasave_pool` and `pickproof_pool`. When a table's indexes weigh over 0.8 × its heap (and over 1 MiB), it runs `REINDEX INDEX CONCURRENTLY` one index at a time. Rules:
    - it skips an index (`HEADROOM`) when free space under the 1 GB limit is less than twice the index;
    - it stops starting new rebuilds after 10 minutes (`BUDGET`);
    - a failed index is reported as `ERROR: ...` and the step stays ok;
    - it first drops any leftover invalid `_ccnew` index;
    - the step timeout is 20 minutes, with 1 attempt (a retry could start a second rebuild).
  - **`POST /jobs/run {job: "daily", only: "db_maintenance"}`** (WRITE) runs that step alone.
  - **Migration:** `market_names` fillfactor 80. The daily continue UPDATE changes only columns that no index uses, so with room left on the page it becomes a HOT update with no new index entries. It applies to pages written from now on; no table rewrite.
- **Impact on Gavriel:** none to existing routes. Read `GET /db/report` once after the deploy; DOM posts the numbers in CR-100 before 6.3.0 (the archives) deletes anything.
- **How to test it:**
  - `GET /db/report` with a READ token: `tables[]` with `indexes[]` and `age`. A second call within the hour has `cached: true`.
  - After the next daily run, `GET /jobs/runs?job=daily`: step `dbMaintenance` has `status` `ok`/`nothing_due` and `tables[].ratio_after`.
- **Deploy status:** pushed to `main` with tag `v6.2.0`; the Mac host deploys after CI.
- **Lessons:** CR-100 assumed `market_names` held raw payloads; it holds only typed columns. Measuring first (this release) keeps the archive design honest.
