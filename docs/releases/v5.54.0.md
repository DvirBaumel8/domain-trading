# Release v5.54.0 (26 Oct 2026)

**Contract:** 5.54.0 (MINOR, additive step summary fields).

- **What changed:** 26 Oct's GoDaddy file was saved at 15:05 UTC by v5.48.0, before v5.49.0 began storing the free demand fields; a re-run skipped the sealed file, so the day's shortlist had no demand part. Now a sealed auction day whose live rows lack the demand fields is parsed again from the raw zip kept on the host (same merge; the sealed manifest is unchanged). File code `SNAPSHOT_SEALED_REPARSED`, summary `reparsed_n`.
- **Impact on Gavriel:** none; the shortlist of such a day gets its demand part on the next run.
- **How to test it:** `POST /jobs/run {"job":"datasave"}` once; `godaddyInventory.summary.reparsed_n` >= 1, then `GET /auctions/shortlist` rows have `parts.demand.known: true`. Test DS554-1.
- **Deploy:** the Mac host after CI.
- **Lessons:** a new parsed field needs a catch-up path for data already saved; otherwise the first useful day is the next one.
