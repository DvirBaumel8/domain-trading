# Release v5.2.0 (14 Oct 2026)

**Contract:** 5.2.0 (MAJOR: routes removed). CR-057: X posting removed (post routes, jobs, Buffer client, image rendering and post tables)

- **What changed:** everything that posted to X is gone, as Dvir asked (14 Oct 2026, 02:36 IDT). Founder rule 10 now reads: the service never sends email or chat, never contacts buyers, and publishes nothing. Removed: the `/posts*` routes, `GET /media/{token}`, the daily step `postsRefresh`, the Buffer client and its schema check, the image inspection code, the X length counter, the post allowance and pause switches, the env vars `BUFFER_API_KEY` and `BUFFER_CHANNEL_ID`, and the five post tables. There was no image renderer library (the image code only inspected uploaded files), so no npm dependency leaves.
- **Impact on Gavriel:**
  - **Routes now answering 404 `NOT_FOUND`:** `POST /posts`, `POST /posts/schema-check`, `GET /posts`, `GET /posts/{id}/images/{part}/{position}`, `POST /posts/{id}/remove`, `POST /posts/pause`, `POST /posts/burst`, `GET /media/{token}`. Stop calling them.
  - **Codes gone:** `POST_INVALID`, `POST_TOO_LONG`, `POSTING_PAUSED`, `POSTING_NOT_CONFIGURED`, `POST_DAILY_CAP`, `POST_FAILED`, `POST_NOT_REMOVABLE`, `POST_DELETE_UNSUPPORTED`.
  - **`GET /health`** has no `posting` and `posting_reason` any more (the answer is `status`, `db`, `jobs`, `review`, `review_model`, `version`, `adapters`, plus `review_reason` when the review failed). Nothing in `/health` mentions X or Buffer.
  - **`GET /jobs/runs`:** the `daily` run has no `postsRefresh` step. No job references X or Buffer. `/report` never had a posting block, so it is unchanged.
  - **Old posts:** the tables are dropped; each post's creation and changes stay in `audit_log`. Posts already on X stay there; delete them by hand if wanted.
  - Not touched: listings, buys, outreach emails, the outside review, the company document and forbidden terms, the engine.
- **Secrets Dvir can delete:**
  - `BUFFER_API_KEY` and `BUFFER_CHANNEL_ID`: nothing reads them now. Delete them from the Mac host env file (`~/.config/domain-trading/prod.env`) and from the Render service env (or leave them unset when Render resumes). `render.yaml` and `.env.example` no longer list them.
  - The Buffer account itself (API access token at publish.buffer.com/settings/api, the connected X channel) and any X developer or account credentials Gavriel's side holds for posting.
  - GitHub Actions: no secret or variable was used by a posting workflow (none existed in `.github/workflows/`), so nothing to delete there.
  - **Keep** `PUBLIC_BASE_URL`: the job queue's keep-alive ping still reads it.
- **How to test it:** call `GET /health` (READ token): it has no `posting` keys. Call `GET /posts` or `POST /posts/pause` (with an `Idempotency-Key`): both answer 404 `NOT_FOUND` in the standard error shape. No route of this release takes `dry_run`.
- **Deploy:** one migration, `1763600000000_v5-2-0.sql` (drops the five post tables and `posts_guard()`; it is not reversible). It runs on start. Push to `main`, tag `v5.2.0`; Gavriel confirms the version on `/health`. Old backups that contain the post tables restore fine (the restore ignores files it no longer lists).
