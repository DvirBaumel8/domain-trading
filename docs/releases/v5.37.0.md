# Release v5.37.0 (25 Oct 2026)

**Contract:** 5.37.0. GoDaddy auctions in our buying range are kept daily; new `GET /auctions/live`. MINOR (additive). Migration `1766500000000_v5-37-0.sql`. Also deploys v5.36.0 (S8 cap $250), whose CI run failed on a migration-count test.

## Why
Dvir, 25 Oct 2026: auctions with real bids are the main buying effort, cap $250 a name (`docs/research/auctions-playbook.md`). The daily save already downloads GoDaddy's four official auction files, but kept only auctions that reached $500, so the auctions we now buy in were thrown away. Dvir: "Yes sounds good build it."

## What changed (contract)
- **`GET /auctions/live`** (READ or bots; data token 403): `.com` GoDaddy auctions, not adult, price up to the S8 cap, at least 1 bid, from the latest daily save. Rows: `domain, end_time, auction_type, price_cents, price, bid_count, domain_age, valuation_cents, pageviews`. Filters: `date`, `max_price`, `min_bids`, `ends_within_hours` (1..240), `type`, `sort` (`end_time` | `bids` | `price`), `limit` (≤ 500), `offset`, `include_ended`. By default only auctions that haven't ended.
- **Datasave:** step `godaddyInventory` stores them in `godaddy_auctions_live` (kept 7 days); summary `live_kept_n`, `live_band_max_cents`. The band follows `settings.s8_max_price_cents` at every run. `snapshotRetention` adds `auctions_live_cutoff_date`, `auctions_live_deleted`.

## Impact on Gavriel
- The first rows appear after the next datasave run (15:00 UTC).
- It's a tip sheet: price and bids are as of GoDaddy's file (about 14:40 UTC), not live. Check the auction page before proposing a name.
- Every proposal follows the playbook: a written maximum bid with its reason. Dvir approves the name and the maximum and bids by hand. Import the name (`POST /portfolio/import`) only after the transfer is final (redemption window).

## How to test (via the API)
- After the next datasave run: `GET /jobs/runs?job=datasave`, step `godaddyInventory` has `live_kept_n` > 0 and `live_band_max_cents: 25000`.
- `GET /auctions/live?ends_within_hours=24&min_bids=2&sort=bids&limit=20`.
- `GET /auctions/live?foo=1` → 400 `VALIDATION_ERROR`.
- Local tests: DS537-1..4 (`tests/modules/ops/datasave.test.ts`), MK537-1..3 (`tests/modules/market/auctions-live.test.ts`). Full suite: 2,847 passed.

Deploy: pushed to `main` with the tag; the Mac host deploys after CI passes and runs both migrations. Gavriel confirms 5.37.0 on `/health`.

**Lessons:** v5.36.0 added a migration and broke the `doctor` test, which counts migrations; I ran only the buying and contract tests. A release that adds a migration runs `tests/modules/ops/admin-cli.test.ts` too (or the full suite).
