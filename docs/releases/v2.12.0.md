# Release v2.12.0 (7 Oct 2026)

**Contract:** 2.12.0. Additive (MINOR). CR-011 part A and addendum A: posting to the company's X account through Buffer's free plan, with images. Founder rule 10 was changed by Dvir to allow this; Dvir gave the go-ahead in DOM's session. **Nothing posts until Dvir adds `BUFFER_API_KEY` in Render.** **Deploy:** see the end.

| Item | What | How to test it |
|---|---|---|
| **Preview** (T11-1, T11-2, T11-3, T11-30) | `POST /posts` with `dry_run: true`: length per part, every image and alt text checked, the allowance left; nothing sent or counted | A 300-character text → `ok: false`, `POST_TOO_LONG`; an email in the text → `TEXT_BLOCKED` `email` |
| **Post** (T11-4, T11-5, T11-7, T11-28) | A real post with up to 4 images per part and a thread of up to 3 parts; Buffer publishes now; idempotent | After the key is set: Phase 1's first post |
| **Cap and pause** (T11-6, T11-8) | 1 a day; `POST /posts/burst` for 2–5 on one day; `POST /posts/pause` | The second post of a day → 409 `POST_DAILY_CAP` with `next_allowed_at` |
| **Images** (T11-29, T11-31, T11-32, T11-34) | PNG/JPEG only, 5 MB, 8,192 px, alt 1–1,000, metadata stripped; per-image reasons; stored with sha256 | A GIF → 422 `POST_INVALID` `IMAGE_TYPE` at its position |
| **Remove** (T11-9, partly) | `POST /posts/{id}/remove` asks Buffer; if Buffer can't delete a published post, 409 `POST_DELETE_UNSUPPORTED`; then `marked_removed_by_hand: true` after deleting on X | |
| **List** (T11-10, our records only) | `GET /posts`; the daily `postsRefresh` fills the X link and send time | |

## Notes
- **Buffer's API shapes** are taken from its public reference and are not yet checked against the live API. The first real post shows whether they hold; an error comes back as 502 `POST_FAILED` with Buffer's message.
- **Not read:** reach and replies (Buffer's free plan).
- **Public images:** they are served at `/media/<token>` (unguessable, 7 days) so Buffer can fetch them.
- **Cap and Buffer calls run one at a time** inside the one server instance.
- **Migration:** `1761700000000_v2-12-0.sql`. The backup leaves image bytes out.
