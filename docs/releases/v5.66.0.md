# Release v5.66.0 (27 Oct 2026)

**Contract:** 5.66.0 (MINOR). F47 hand-registration paper test; BUG-054 lander Buy Now parser.

- **What changed:**
  - **F47 paper test** (Dvir, 27 Oct 2026: "Yes accept"). Once a week the bots send `POST /handreg/weeks` `{pool, picks}`. The pool holds the currently unregistered `.com` names they considered (up to 2,000); the picks are their ~20 choices from it (up to 30).
    - The server draws a random control of the same size from the rest of the pool. The seed is random and stored, and anyone can recompute the draw (`drawControl`).
    - It RDAP-checks both groups and seals the week in the same call, so the bots never see the control before they pick.
    - The datasave step `handregLabels` labels each name at 6 and 12 months: `taken` if someone else registered it. `GET /handreg/report` compares picks with control on taken and sold, with a one-sided Fisher p, or `UNPOWERED` below 10 events.
    - No money, no buying, no AI in the service. Rules and tests: `docs/internal/handreg.md` (HR66-*).
  - **BUG-054:** the weekly lander check reads Afternic's "Buy it now for $1,488.00". It no longer takes the offer-form ceiling "Offer cannot exceed $49,999,999" as the price (LP-6..8).
- **Impact on Gavriel:**
  - Start the weekly submission. Pool and picks go in one call per week; a second call that week is 409 `HANDREG_WEEK_SEALED`.
  - The three false `LANDER_PRICE_MISMATCH` warnings clear at the next `portfolioCheck`. To clear them now, run it with `POST /jobs/run`, then stamp BUG-054 AT-4.
- **How to test it:** `POST /handreg/weeks` with `dry_run: true` validates and stores nothing. `GET /handreg/weeks` and `GET /handreg/report` are read-only.
- **Deploy:** Mac host, `deploy.sh` after CI; migration runs on start.
