# Release v5.3.0 (14 Oct 2026)

**Contract:** 5.3.0. CR-053: scout lessons store (POST/GET/PATCH /lessons, /lessons/check, /lessons/report)

- **What changed:** a lessons store for the scouts (CR-053): `POST /lessons`, `GET /lessons`, `GET /lessons/check`, `PATCH /lessons/{id}`, `GET /lessons/report`. Contract: `endpoints.md` Scout lessons. No change to `/buy`, selection or scoring, and no job reads the table.
- **Impact on Gavriel:**
  - Where the request and DOM's answer differ: the report is a route (`?format=md` for Markdown); the service does not write `docs/requests/exports/lessons-YYYY-MM.md`, you commit what it returns. Errors follow the usual codes: 422 `VALIDATION_ERROR` for a body, 400 for a query.
  - **Import of the backfill (about 70 lines):** send them as arrays of up to 200 in one `POST /lessons` (one `Idempotency-Key`; writes are limited to 10 a minute per token). Each line is `{scout, sector, domain, rule, lesson, recheck_if, source_file}`; `domain` may hold several names, comma-separated. `sector` and `rule` and `lesson` are required; `scout` defaults to `other`, `recheck_if` to `never`. Names must be second-level `.com`: a line with a bad name (or a non-`.com` one) rejects the whole call with 422 `DOMAIN_INVALID` / `TLD_NOT_SUPPORTED` and stores nothing, so drop or fix that name and resend. Repeats of the same sector, rule and name merge, in order, also inside one call (`merged: true`, the differing text becomes a dated note).
  - Rule 18/19 check: `GET /lessons/check?domain=x.com`.
  - `rule` is lowercased and at most 20 characters; `lesson` at most 300; `recheck_if` at most 200 (`never` allowed).
- **How to test it:** (use a WRITE token for the POSTs)
  1. `POST /lessons` with three lessons, two of them on the same `sector`, `rule` and name: the answer has 3 results, the second repeat has the first's id and `merged: true`; `GET /lessons` shows 2 rows.
  2. `GET /lessons?sector=S6`, `?rule=r11`, `?since=2026-10-01`, `?q=cbam` filter correctly, newest first.
  3. `GET /lessons/check?domain=<a name that was merged in>` finds the lesson.
  4. After the import, `GET /lessons/report?month=2026-10`: S6's first rule is the most frequent one (r11 or taken); rules with 3 or more lessons carry the recurring flag. Add `&format=md` for the Markdown.
  5. A body without `sector`, `rule` or `lesson` gives 422 with `details.issues`; no token gives 401; a READ token on POST/PATCH gives 403; repeating a POST with the same `Idempotency-Key` returns the same answer with `Idempotent-Replayed: true`.
  6. `PATCH /lessons/{id}` with `{"recheck_if": "..."}`, `{"superseded_by": "<other id>"}` or `{"lesson": "..."}`; any other key is 422, an unknown id is 404 `LESSON_NOT_FOUND`.
- **Deploy:** one migration, `1763700000000_v5-3-0.sql` (new table `scout_lessons`, runs on start). Push to `main`, tag `v5.3.0`; Gavriel confirms the live version on `/health`.
