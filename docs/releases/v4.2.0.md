# Release v4.2.0 (13 Oct 2026)

**Contract:** 4.2.0 (MINOR, additive). Keyword demand upload (CR-044 item 3, the follow-up) and Companies House matches (CR-046 item 2).

- **What changed:**
  - `POST /demand/keywords` (WRITE): body `{file_base64, location?, month?}`. It takes the Keyword Planner export exactly as Dvir saves it (UTF-16LE with a BOM, tab-separated, a title line and a date-range line before the header). Columns are read by header name; required are `Keyword`, `Avg. monthly searches` and `Competition (indexed value)`; `Three month change` and `YoY change` are kept as text; the localized `Competition` column is ignored. The segmentation rows (empty Keyword) are skipped. A missing required header is 422 `KEYWORD_CSV_INVALID` with `details.missing_headers`, and nothing is stored. Uploads are kept (append-only); the newest row of a keyword is its demand.
  - `GET /demand/keywords?keyword=` (READ): the latest stored values of a keyword (404 `KEYWORD_NOT_FOUND`).
  - New screening input `demand` on every screened name: `fields.demand {keyword, avg_monthly_searches, competition_index, as_of}` or `{status: "unmeasured"}`. The keyword is the name's split tokens joined with spaces (then the scout `words`). It informs and never rejects.
  - The renewal drop check (`RENEWAL_DROP_SUGGESTED`) now keeps a name whose latest upload shows at least `demand.keep_min_searches` (default 10) average monthly searches; `details.signals.keyword_searches` shows the number.
  - New screening input `companies`: UK Companies House matches (`uk_matches_n` and up to 5 of `{title, company_number, company_status}`, active first). A match is a company whose title contains every split token as a whole word. It informs and never rejects. **It stays UNKNOWN `SOURCE_DISABLED` until Dvir puts `COMPANIES_HOUSE_API_KEY` in the host env file.**
- **Impact on Gavriel:** no existing call changes. Every screening result list now also has `demand` and `companies` rows (feature checks, gate G8); neither changes a status or a pack. Settings: `demand` (`enabled`, `keep_min_searches`) and `companies` (`enabled`, `max_per_minute` 60, `timeout_ms`).
- **Monthly upload steps (Gavriel):**
  1. On the 1st of the month Dvir exports from Google Ads Keyword Planner: location **United States**, the **Saved keywords** tab, download as **CSV**, and hands you the file unchanged (do not open and re-save it).
  2. Base64 the file as it is (for example `base64 -i keyword-planner-stats-YYYY-MM-DD.csv`, no line wrapping needed but wrapped lines are accepted).
  3. `POST /demand/keywords` with a fresh `Idempotency-Key` and `{"file_base64": "<the base64>", "location": "United States", "month": "YYYY-MM"}`. Expect 201 with `rows` and `skipped` (the two segmentation lines are skipped).
  4. Check one name: `GET /demand/keywords?keyword=cbam%20compliance`. A keyword with no number in the export reads `avg_monthly_searches: null` (unmeasured); a name is then `{status: "unmeasured"}`.
  Add the keywords of the names you want measured to the Saved keywords list before the export (a name matches by its split tokens joined with spaces).
- **How to test it:** upload the real file `docs/requests/exports/keyword-planner-stats-2026-10-13.csv` (10 keywords, 2 skipped); `GET /demand/keywords?keyword=cbam compliance` gives 50 searches, competition 47. A file without the `Avg. monthly searches` header gives 422. Run a screening with `checks: ["form", "demand"]` (and `companies` once the key is set). There is no `dry_run`: an upload only stores your numbers.
- **Deploy:** tag v4.2.0; migration `1763300000000_v4-2-0.sql` adds `keyword_demand_uploads` and `keyword_demand`. Confirm `version: 4.2.0` on `/health`. Dvir registers the free Companies House API key and adds `COMPANIES_HOUSE_API_KEY` to the host env.
