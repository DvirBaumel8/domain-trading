# Release v3.10.0 (13 Oct 2026)

**Contract:** 3.10.0 (MINOR). CR-043 scout checks. Every new reject is off under the active settings; verdicts do not change until a settings version that turns them on is activated.

## Contract changes
- **Settings keys** (`selection.md`): `form.max_sld_chars` (null), `intake.require_sellers_min` (0), `intake.require_comps` (false), `intake.topic_window_days` (30), `lookalikes.{enabled, endings, prefixes, timeout_ms, max_bytes, max_checks}`, `buy.exclude_lanes` ([]).
- **Codes:** `SLD_TOO_LONG` (form check FAIL; also an intake `removed` reason), `SELLERS_TOO_FEW` and `COMPS_MISSING` (`tier` FAIL), `LANE_NOT_FOR_BUY` (final status `not_for_buy`), `TOPIC_REUSED` (intake flag).
- **`lookalikes` check (G-70):** other endings, hyphenated, get-/try- forms by RDAP, with a home-page check of the registered ones. It informs only. Result `fields.lookalikes {registered_n, in_use_n, unknown_n, items}`. It appears in every new run's plan.
- **`POST /candidates/intake`:** optional `topic`; the answer's `accepted[]` gains `topic` and `flags`.
- **`GET /screening/runs/{id}/report.csv`** (READ): one row per name.
- Migration: `candidate_intake.topic`.

## Impact on Gavriel
- Nothing changes in verdicts today. To use the gate, draft a version with `POST /selection/settings` (WRITE), based on the active version, `set`: `{"form.max_sld_chars": 20, "intake.require_sellers_min": 3, "intake.require_comps": true, "buy.exclude_lanes": ["S2"]}`, label it (for example `v12`). Dvir activates it with `POST /selection/settings/{label}/activate`; his line must name the label and the changes (the four keys above). DOM does not write that line.
- S2 names screened under such a version end as `not_for_buy`, never `buy_candidate`, and stay off the daily list.
- Send `topic` at intake when you know the topic; else DOM uses `<lane>:<first two words of 3+ letters>`. `TOPIC_REUSED` is information, not a reject.
- Not built (as answered in CR-043): closest past sale by lookup, search demand, the 404 check of sale pages, `competing_forsale_n`.

## How to test it (dry_run, reads and screening only)
- Run a screening run and read `names[].results[]` for the `lookalikes` check; `GET /screening/runs/{id}/report.csv` for the batch.
- Draft the v12 version and run a full screening with `settings: "<label>"` (a backtest run, labelled as such) to see `SLD_TOO_LONG`, `SELLERS_TOO_FEW`, `COMPS_MISSING` and `not_for_buy` before Dvir activates it.
