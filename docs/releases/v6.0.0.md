# Release v6.0.0 (31 Oct 2026)

**Contract:** 6.0.0. MAJOR: a bots or data token can no longer commit rows through `POST /kb/*`. No new route, no migration.

- **What changed (CR-098 ask 4, one writer):**
  - The six `POST /kb/*` routes (sources, authors, claims, evidence, links, questions) answer **403 `KB_DRY_RUN_ONLY`** to a bots or data token unless the body has `dry_run: true`. Nothing is stored.
  - A dry run works as before: every check runs and the answer shows what would be accepted.
  - A WRITE token still commits.
  - New research goes into a numbered `data/knowledge/` file, and the daily `kbLoad` loads it. `GET /kb/load-preview` checks such a file against production first.
- **Why:** on 26 Oct the `bots-shared` token committed KB rows that file 0008 later clashed with, which blocked the load for three nights (CR-098). Since 5.79.0 a file row replaces a route row, so a clash can no longer block a load. This release closes the second writer.
- **Impact on Gavriel and the bots:** a bot that posts KB rows must add `dry_run: true` and send the rows to DOM as a file (or a CR). In the audit, the `bots-shared` token made 8 committed and 12 dry-run KB posts since 20 Oct; `dom-write` made 9 dry runs.
- **How to test it:** `POST /kb/sources` with a bots token and `{rows: [..]}` → 403 `KB_DRY_RUN_ONLY`; the same body with `dry_run: true` → 201, `dry_run: true`. Test KB-098-3.
- **Deploy:** tag → Mac host. No migration. Pushed after 01:00 UTC and outside the datasave.
- **Lessons:** a store with two writers needs a single owner before the second writer exists. This rule should have shipped with CR-078, when the route and the repo files both started writing the same tables.
