## What changed, and how Gavriel tests each item

| Item | What | How to test it (no real purchase, nothing changed) |
|---|---|---|
| **Manual runs with the WRITE token** (T-2) | `POST /jobs/run` `{"job":"daily"}` or `{"job":"tick"}` with the WRITE token, at most 4 per hour per token, same overlap lock. `GET /jobs/runs` shows `trigger: "manual"` and `triggered_by` (the token's name) | Once the new WRITE token is in place (D-1): start `daily`, then `GET /jobs/runs?job=daily`. `{"job":"x"}` → 422; the READ token → 401; a 5th call within an hour → 429 |
| **Token expiry** (T-3) | DOM can set an expiry time on a token; after it the token gets 401 like an unknown one | AC-25 after the WRITE token switch announced in `DOM-TO-GAVRIEL.md` |
| **Automatic Web Risk** (G-6) | With the server's key, `web_risk` calls Google's Lookup API: match → FAIL `UNSAFE`, no match → PASS (CR-001 CAP-06), quota → UNKNOWN `QUOTA`, error → UNKNOWN `SOURCE_ERROR`, past DOM's cap of 10,000 a month → UNKNOWN `QUOTA_CAP`. Without the key: MANUAL_REQUIRED as before | A screening run on any name: `web_risk` has `fields.source: "web_risk_api"`. The manual record still works as a fallback |
| **Daily `portfolioCheck`** (G-5) | Every owned, listed or delisted name, hand-bought ones included: registry (RDAP) daily, web answer daily (listed names with verified lander nameservers), blocklists weekly. `/report`: `REGISTRY_MISMATCH`, `LANDER_DOWN`, `OWNED_NAME_BLOCKLISTED` | After the next daily run: `GET /jobs/runs?job=daily` → `steps.portfolioCheck.summary.names` lists promptinjectionaudit.com with `registry: "ok"`; `web` is `skipped` until its nameservers point to Afternic |

## Notes
- **Web Risk key:** read from `GOOGLE_WEB_RISK_API_KEY` on the Render service (the name Dvir used). It is sent in a header, never in a URL, and never logged or returned. The Update API is never called (a static test in `test-evidence.md`).
- **Not in this release:** the marketplace page price check (out of reach, CR-007 Q-7), the US trademark search (manual: the USPTO key has no wordmark search), and the research items, which come in v2.4.0 and v2.5.0 (CR-007 §19.1).
- **Migration:** `1760700000000_v2-3-0.sql` adds `job_runs.triggered_by`, `api_tokens.expires_at`, the counter table `api_usage` and the append-only table `portfolio_checks` (operational, not in the data backup). All additive.
