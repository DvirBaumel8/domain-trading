# Release v5.58.0 (26 Oct 2026)

**Contract:** 5.58.0 (MINOR, migration). CR-079 (DOM Architect, approved by Gavriel from Dvir's widget yes).

- **What changed:** the daily missing-name check, folded into `portfolioCheck` (no new step). `/report` computes it live from the registrar check, the registry (RDAP) state, the venue records and the registration ledger: `LISTING_RECORD_MISSING` (listed but no confirmed venue record), `LISTING_UNAPPROVED` (a confirmed venue with no sale and no approval trail: listing approval, an audited venue record, a confirmed export upload with the name, or a tagged CR-076 seed), `OBSERVED_UNCONFIRMED` (info: a public sighting of a venue we have not confirmed), `RECEIPT_POINTER_MISSING` (no registration receipt reference). `DOMAIN_LEFT_ACCOUNT`, `REGISTRY_MISMATCH` (warn for hold-only differences) and `HOLD_STALE` are reused. `portfolioCheck`'s summary has `alerts_n` and `by_code`. `GET /portfolio` and `GET /books.csv` carry `receipt_ref` and `deal_id`.
- **Migration note:** `venue_listings` is append-only; the migration lifts its trigger for the one statement that tags the CR-076 seed rows (`approval_source = 'seed_cr076'`), inside the migration transaction, then restores it.
- **Impact on Gavriel:** run AT-1..AT-7 (`CR079-AT1..7`); check that no live name shows `LISTING_UNAPPROVED`.
- **How to test it:** `GET /report` warnings; `GET /jobs/runs?job=daily` `portfolioCheck.summary.by_code`; `GET /books.csv` last two columns.
- **Deploy:** the Mac host after CI.
- **Lessons:** a CR changed shape mid-build (a separate step became a fold-in); telling the builder at once kept the cost to one revert.
