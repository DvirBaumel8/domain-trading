# Release v5.25.0 (21 Oct 2026)

**Contract:** 5.25.0. CR-070 ledger costs, forward-cost plans, books.csv, plus a fix to `GET /market/matched` (CR-075). MINOR (additive). Migration `1765700000000_v5-25-0.sql`.

## What changed (contract)
- **`POST /ledger/costs`** (bots or WRITE; `Idempotency-Key`; audited). Body `{rows: [{date: "2026-10-20", type: "tool" | "ai" | "adjustment", amount_usd: "-1.20", note: "cost-log", domain?: "name.com"}], dry_run?: true}`, 1..500 rows. `dry_run` answers **200** `{dry_run: true, received_n, accepted_n, rejected_n, total, total_usd}` and stores nothing; a real call answers **201**. Any other `type` (registration, renewal, sale, commission, refund, fee, payout_fee), a bad amount (more than 2 decimals, zero), a bad date, an unknown field or an unknown `domain` is **422 `VALIDATION_ERROR`** with `details.issues`, and nothing is stored. A cost is a negative amount. A correction is a reversing row (the opposite amount); the ledger stays append-only. `GET /ledger?type=ai|tool|adjustment` already worked.
- **`PUT /portfolio/{domain}/forward-costs`** (bots or WRITE; idempotent; audited). Body `{lines: [{month: "2027-10", item, planned_usd: "11.08", basis, cost_type}]}` replaces the planned lines of that name as a set. The old set is kept as an earlier version; `GET /portfolio/{domain}/forward-costs` (new, READ or bots) shows the current plan and every earlier version. `{lines: []}` clears the plan. A derived field (`walkaway`, `floor`, `min_offer`, `bin`, `renewal_due`, `renewal_cost`, `forward_total`, `expiry_date`, `drop_date`, ... also as `*_cents` / `*_usd`) at the top level or in a line is **422 `DERIVED_FIELD`**. Unknown domain: 404 `DOMAIN_NOT_FOUND`. DOM does not compare plans with the $1,500 figure (G-86).
- **`GET /costs/forward?from=2027-10&to=2027-12`** (READ or bots; no query = 12 months from this month; at most 36 months). Per month: the planned lines (current plan of every name, with `basis`), the committed renewals, and the sums; plus `totals` and `warnings`. Renewals use the rule behind `/report` `spend.committed_forward`: a live name not renewed yet, in the month of its `expiry_date`, at its recorded renewal price; a name that drops at its first expiry counts **0** (`reason: "DROPS_AT_FIRST_EXPIRY"`). A name with **no renewal price** has `renewal: null`, the warning `RENEWAL_PRICE_UNKNOWN`, and its month and the totals are **`incomplete: true`**: it is never added as 0.
- **`GET /books.csv`** (READ or bots; private, carries the walk-away; not under `/export`). One row per live name (owned, listed, delisted), the columns in `formats.md` §Books CSV: `domain,display_name,line,category,status,buy_date,cost_usd,expiry_date,renewal_price_usd,renewal_price_source,drop_date,bin_usd,floor_usd,walkaway_usd,min_offer_usd,next_event,next_event_date,listed_venues`. Every value equals the same name in `GET /portfolio`. Text cells have the formula guard of the ledger CSV. `/export/afternic.csv` and `/export/sedo.csv` still never carry the walk-away.
- **No change to pricing (CR-070 R-4 declined):** the walk-away stays 48% of BIN to the nearest $5, never below $500 (mineunited.com BIN $1,488 gives walk-away $715, floor $967; BIN $900 gives $500).
- **Fix, `GET /market/matched` (CR-075, Gavriel's check of 21 Oct):** it froze an empty set for a future `asof` (2026-12-20). Now an `asof` later than the newest sealed source day (a complete `dynadot_aftermarket`, `dynadot_closed_auctions` or `godaddy_inventory` snapshot; today UTC when none is sealed) is **409 `MATCHED_ASOF_FUTURE`** (`details.newest_sealed_day`) and nothing is stored. A set with 0 positives is returned with `frozen: false`, `frozen_at: null` and its `sha256`, but is **not stored**, so a later call can freeze a real set. The migration removes the matched sets already stored with 0 positives (they came from test calls; the append-only trigger is switched off for that one delete and switched back on).
- New codes: `DERIVED_FIELD` (422), `MATCHED_ASOF_FUTURE` (409), `RENEWAL_PRICE_UNKNOWN` (warning). New tables `forward_cost_plans`, `forward_cost_lines` (append-only, in the backup).

## Impact on Gavriel and Sales
- Sales can write its tool, AI and adjustment costs and its forward-cost plan here with the shared bots token, then read `GET /costs/forward` and `GET /books.csv` instead of keeping box copies. Send only plan inputs: DOM computes floor, walk-away, min offer, renewal due date and renewal cost, and refuses them with `DERIVED_FIELD`.
- Record each renewal price (`POST /portfolio/{domain}/renewal-price`) so `GET /costs/forward` is not `incomplete`.
- Challenger and the data bots: call `GET /market/matched` with an `asof` on or before the newest sealed day. Nothing else changes for them.
- Nothing here asks Dvir to do anything.

## How to test (with `dry_run`)
- `POST /ledger/costs {"rows":[{"date":"2026-10-20","type":"ai","amount_usd":"-1.20","note":"cost-log"}],"dry_run":true}`: 200, `accepted_n: 1`, and `GET /ledger?type=ai` is unchanged. The same body with `"type":"registration"`: 422. Without `dry_run`: 201 and the row shows (reverse it with `"1.20"`).
- `PUT /portfolio/mineunited.com/forward-costs` with `{"walkaway":"715","lines":[]}`: 422 `DERIVED_FIELD`. With a real line: 200 and `version` 1; send a second set and `GET /portfolio/mineunited.com/forward-costs` shows both versions.
- `GET /costs/forward?from=2027-10&to=2027-10`, and a bare `GET /costs/forward`: check `incomplete` against the names with no renewal price.
- `GET /books.csv`: one row per live name; compare `walkaway_usd` with `GET /portfolio`.
- `GET /market/matched?asof=<a day after the newest sealed day>`: 409 `MATCHED_ASOF_FUTURE`. Use a past `asof` to call it twice and compare the `sha256`.
- Local tests: BK525-1..13 (`tests/modules/reporting/books.test.ts`), MK525-1..3 (`tests/modules/market/market.test.ts`; MK523-6 and MK523-7 now use `asof` 2026-12-01 because 2026-12-20 is after the newest sealed fixture day). The admin-cli migration count is 60.

Deploy: pushed to `main` with the tag; the Mac host deploys after CI passes. Gavriel confirms the live version on `/health`.

**Lessons:** a "call it twice" test step must use a past `asof` (a future date froze an empty set and made the freeze look broken); and a route that freezes a result needs a "nothing to freeze yet" case written before the freeze, or a test call leaves a permanent empty record.
