# Release v6.1.0 (1 Nov 2026)

**Contract:** 6.1.0. MINOR, additive: two new read-only fields. No migration.

- **Why:** from **31 Oct 15:40 UTC to 1 Nov 00:00 UTC** production was down. Neon suspended the free project for the rest of the month ("Your account or project has exceeded the quota"). The free plan gives each project 100 CU-hours of compute and 5 GB of data transfer out a month. We can't yet see which one ran out (Gavriel is reading the Neon usage page), and the service had no meter for either.
- **What changed:**
  - `GET /health` has **`db_transfer: {bytes_in, since}`**: bytes the database sent to the server since the process started.
  - Each job step's `db` in `GET /jobs/runs` has **`bytes_in`**, so the steps that pull the most data out of Neon are visible per run.
  - **Host kit:** `visits-token.sh` used to open a database connection on every 10-minute deploy tick, which kept Neon from sleeping (it sleeps after 5 idle minutes). It now runs only in hour 15 UTC, when the datasave keeps the database awake anyway. A requested visit-counter token is handed over within a day; `VISITS_TOKEN_NOW=1` runs it at once.
- **Impact on Gavriel:** none to call. Please poll `/health` only as often as needed; `/health/ping` doesn't touch the database.
- **How to test it:** `GET /health` shows `db_transfer.bytes_in` > 0. After today's datasave, `GET /jobs/runs?job=datasave` shows `db.bytes_in` per step. Test DT610-1.
- **Deploy:** tag → Mac host, then `install.sh` copies the new `visits-token.sh`. No migration. Pushed before the 15:25 UTC datasave.
- **Lessons:** the free plan has three limits (storage, compute, data out) and we watched only storage. The data-out cost of reading a 354 MB table back on every run was invisible until the database stopped. Next: `episodes` and the Dynadot top-up work inside the database (G-139).
