# Release v2.5.0 (7 Oct 2026)

**Contract:** 2.5.0. Additive (MINOR), with one widening: suites outside `holdout.required_suites` can now be frozen. CR-007 G-4a to G-4d, plus the means for CR-008 AC-10. **Deploy:** see the end.

## What changed, and how Gavriel tests each item

| Item | What | How to test it |
|---|---|---|
| **Test sets, `new`** (G-4a/b, AC-12, AC-13) | `POST /selection/test-sets` with source rows, a seed and filters: DOM removes used names, duplicates and filtered rows (each with a reason), splits test/dev by the seed, and computes as-of features (`bt1@v1` census, `ext_dates`) in a back-test run | Upload a small set twice with the same seed under two names: the second removes every name as `ALREADY_REGISTERED` only after the first is sealed; a set before sealing keeps its own rows. `GET` shows progress; `seal` registers the rows and freezes the test membership |
| **Rescore** (CR-008 AC-10) | `POST /selection/test-sets` `{purpose: "rescore", slices: ["R15-TEST15-USED"], settings: "v11"}` computes as-of features for registered names and reports accept / reject rates with Wilson 95% ranges, plus how many decisions changed against the uploaded features. Nothing is registered | After the fixtures are registered and `bt1@v1` is approved. Expect about 6 hours for 894 names; keep polling the `GET` |
| **Suites** (G-4c/d, AC-14, AC-15) | Any suite id; `gates_not_assessed` and `clears_hold`, each named in Dvir's approval (suite id, each gate id, "clears hold"). Holdout replays apply only the assessed gates and report `accepts_at_risk` | Freeze a suite from a sealed set's test slice with `gates_not_assessed: ["tm_us","tn","hist2","hist2_guard"]`; a holdout replay then needs no gate columns |
| **Buy hold** | The hold suites are those whose latest definition has `clears_hold`; with none, `holdout.required_suites` as before. `GET /selection/buy-hold` adds `hold_suites` and `hold_suites_source` | `GET /selection/buy-hold`: `hold_suites_source: "required_suites"` until a `clears_hold` suite exists |

## Notes
- **As-of features are reconstructed** from today's registry: a sibling counts only if its creation date is before `as_of`. A name registered before `as_of` and deleted since is invisible (a known limit). Seal records the input date as the day before `as_of`.
- **Test rows stay sealed:** a `new` set never shows a row's label, features or decision. Only holdout replays score test rows.
- **Migration:** `1760900000000_v2-5-0.sql` adds `test_sets`, the append-only `test_set_rows`, and `holdout_suites.gates_not_assessed` / `clears_hold`.
- **Not in this release:** the drop list and the forward test (CR-007 G-2 source A and G-1, v2.6.0).
