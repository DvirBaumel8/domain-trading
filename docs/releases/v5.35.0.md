# Release v5.35.0 (25 Oct 2026)

**Contract:** 5.35.0. The daily save seals pick-proof days that no bot sealed. MINOR (additive). No migration.

## Why
The Grok bots hit their token limit on 22 Oct 2026 and are paused until about 26 Oct. A pick-proof day was frozen and sealed only on a bot call, so nothing froze or sealed 23 Oct onward. The source rows of a day (D-1) are deleted after 3 days, so each unsealed day was about to be lost for good. 23 Oct was the first one, due to be lost in the 25 Oct 15:00 UTC run.

## What changed (contract)
- **New datasave step `pickproofSeal`**, between `buildPanel` and `snapshotRetention` (the job now has ten steps):
  - every pick day from the first frozen day up to yesterday (UTC) that is not sealed is frozen if needed, then sealed;
  - this is what the first `GET /pickproof/{date}/manifest` after the deadline does: the same pool rule, seed and draw;
  - a day the step froze itself shows `sources.frozen_by: "datasave"` in its manifest (outside `pool_sha256`);
  - today is never touched, so a bot's own freeze, picks and seal still come first.
  - Summary: `{status, days: [{date, result: "sealed"|"error", frozen_now, code}]}`.
- **New code `POOL_SOURCE_PRUNED` (410):** returned by a call that would freeze a day whose D-1 closeout rows are already gone. Before this release such a call would have frozen an empty pool.

## Impact
- **Challenger, Buyer, Gavriel:** days sealed while you were paused have no arm A (no picks), like 22 Oct, so they count for the drawn arms only, if Challenger accepts them. A late-frozen pool uses the filter codes and the sales-graded set as they were at freeze time, which may differ slightly from an on-time freeze. Each such day is marked `frozen_by: "datasave"`. Please rule on whether these days count, and add their seal lines to `pick-proof-seals.md`.
- When you are back, nothing changes in your routine: you freeze, pick and seal day D as before; the step only acts on days still unsealed the next day.
- Nothing here asks Dvir to do anything.

## How to test (via the API)
- `GET /jobs/runs?job=datasave`: step `pickproofSeal` lists the days it sealed.
- `GET /pickproof/2026-10-23/manifest` (and 24, 25 Oct): `sealed: true`, `sources.frozen_by: "datasave"` where the step froze the day.
- Local tests: PP535-1, PP535-2 (`tests/modules/pickproof/pickproof.test.ts`).

Deploy: pushed to `main` with the tag; the Mac host deploys after CI passes. Gavriel confirms the live version on `/health` when back; until then Dvir checks it.

**Lessons:** a step that only runs when an outside caller shows up stops when the caller stops. Every daily protocol step that loses data if skipped needs a scheduled fallback.
