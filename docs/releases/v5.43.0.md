# Release v5.43.0 (25 Oct 2026): the knowledge base, phase 1 (CR-078, G-132)

**Contract:** 5.43.0 (MINOR: twelve new routes, two new codes, one new daily step, one migration).

## What changed (contract)
- **New routes** (WRITE, bots or data token for the POSTs; READ or bots for the GETs; the POSTs take `Idempotency-Key`, are audited with row counts only, accept `dry_run` and 1..1,000 rows, and are all-or-nothing: one bad row is 422 `KB_ROWS_REJECTED` with `details.rejects[]`, nothing stored): `POST /kb/sources`, `/kb/authors`, `/kb/claims`, `/kb/evidence`, `/kb/links`, `/kb/questions`; `GET /kb/questions`, `/kb/questions/{id}/verdict`, `/kb/claims`, `/kb/sources`, `/kb/recheck`, `/kb/echo-candidates`.
- Rows name each other by natural key (source URL, author name, claim_key, question slug). Append-only with `supersede: true` corrections. Sources are deduplicated by canonical URL; excerpts get a MinHash for echo detection.
- `GET /kb/questions/{id}/verdict` computes the verdict in plain code from the versioned `kb_settings` (v1 = research §2.3): weight G x C x N x R x K, independence clusters, certainty high / moderate / low / very_low with each step down in plain words; appends a `kb_verdicts` row only when the result changed. Anything above very_low needs 3 independent clusters, 2 of them A or B.
- New daily step `kbLoad` (after `referenceRefresh`): loads DOM's repo files `data/knowledge/*.jsonl` once per file hash.
- New codes `KB_ROWS_REJECTED` (422), `KB_QUESTION_NOT_FOUND` (404). Data tokens may POST under `/kb/`. Migration `1766800000000_v5-43-0.sql` (nine `kb_*` tables).


## Impact on Gavriel
New, optional. Nothing he calls today changes. He can post what his own knowledge base holds and read verdicts. DOM's October research arrives later as repo files.

### How to post (all `POST /kb/*` take `{rows: [...], dry_run?}`, `Idempotency-Key` required)
Order: authors, questions, sources, claims, evidence, links. Natural keys: author = `name`; source = `url` (canonicalised: utm_* and fragments dropped); question = `slug`; claim = `topic|variable|population` lowercased (`claim_key`, or send the `claim` triplet); evidence = source url + claim + `locator`.
```
POST /kb/questions  {"rows":[{"slug":"s8-auctions-vs-closeouts","text":"Should S8 money go to auctions with bidding rather than closeouts?","options":["auctions","closeouts"],"population":"S8 names, up to $250"}]}
POST /kb/sources    {"rows":[{"url":"https://example.com/post?utm_source=x","type":"practitioner_blog","reliability":"B","reliability_reason":"named investor, 5 years of posted sales","conflict_of_interest":"none","status":"graded","excerpt":"first 300 characters ...","topics":["auction_tactics"]}]}
POST /kb/claims     {"rows":[{"topic":"auction_tactics","questions":["s8-auctions-vs-closeouts"],"option":"auctions","statement":"Names with bids resell better.","variable":"resell rate of auction names with bids","direction":"increases","population":"S8 expired .com names","date_range_end":"2026-06-30"}]}
POST /kb/evidence   {"rows":[{"source":"https://example.com/post","claim":{"topic":"auction_tactics","variable":"resell rate of auction names with bids","population":"S8 expired .com names"},"stance":"supports","credibility":2,"sample_size":200,"evidence_kind":"measured","locator":"table 2","quote":"bids sold through at a higher rate"}]}
POST /kb/links      {"rows":[{"from":"https://repost.example/x","to":"https://example.com/post","kind":"echo_of"}]}
GET  /kb/questions/s8-auctions-vs-closeouts/verdict
```
- Re-posting the same rows is a no-op (counted duplicates). A correction is the same row with `"supersede": true`.
- Rules he must keep: quote at most 15 words, excerpt at most 300 characters, a reason for every grade except F, a new unknown source is F and weighs nothing, D weighs nothing.
- `GET /kb/echo-candidates` lists look-alike excerpts; he confirms with `POST /kb/links`.

## How to test (no production)
`dry_run: true` on any POST returns the counts and stores nothing. Fixtures: `tests/fixtures/knowledge/0000-example.jsonl`.

## Deploy
Migration runs at start (nine tables, `kb_settings` v1). No setting to change. `data/knowledge/` has no files yet, so `kbLoad` reports `files_seen: 0`.

**Lessons:** all-or-nothing batches suit rows that name each other by natural key (a half-stored batch would leave evidence pointing at missing claims). The module had to copy the small size guard because the module graph forbids importing `engine/bulk.ts`; a shared bulk skeleton in `core/` would remove that copy (follow-up). Full suite: 270 files, 2,924 tests passed.
