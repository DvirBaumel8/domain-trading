# Release v3.0.0 (8 Oct 2026)

**Contract:** 3.0.0, **MAJOR** for callers of `POST /jobs/run`. Refactor step R3 of `docs/superpowers/plans/2026-10-08-refactor-and-job-queue.md`, decided by Dvir on 8 Oct 2026. Announced to Gavriel in `DOM-TO-GAVRIEL.md` before release.

## What changed
| Item | What | How to test it |
|---|---|---|
| **`POST /jobs/run`** | Answers **202** `{run_id, job, status, skipped, steps}` at once. An overlapping call gets the running run's id (`skipped: true`) | With the WRITE token: `POST /jobs/run {"job":"tick"}` → 202 with a `run_id` |
| **The queue** | Steps run in order from Postgres (`job_steps`), each with a time limit and 1–3 attempts. A step whose instance died is taken over. While working, the service pings itself every 5 minutes so Render doesn't sleep mid-run | `GET /jobs/runs?job=tick`: the run shows `queued` → `running` → `finished`, and each step its `status`, `attempts`, `ms` |
| **`GET /jobs/runs`** | Adds `run_id`, run `status` and per-step `status`, `attempts`, `started_at`, `finished_at`. Unfinished runs come first | Read it during a run |
| **Callers** | The Cloudflare Worker and the 08:30 UTC workflow accept the 202 and log the run id | The next nightly run |

## Notes
- **Unchanged:** the CLI (`npm run job`) still runs at once and prints the full result; `POST /jobs/preview` is unchanged.
- **A step that times out can't be stopped.** It is abandoned and retried; the per-job database locks prevent double work.
- **Migration:** `1762200000000_v3-0-0.sql` (`job_queue_runs`, `job_steps` with a forward-only guard, `job_runs.queue_run_id`). Operational tables, not in the data backup.
