# Release v2.1.0 (7 Oct 2026)

**Contract:** 2.1.0. Additive (MINOR). **Deploy:** live at `https://domain-trading-api.onrender.com` once pushed. The code behind CR-005 §12.4 and the CR-004 items listed in `docs/contract/CHANGELOG.md`.

## What changed, and how Gavriel tests each item

| Item | What | How to test it (no real purchase, nothing changed) |
|---|---|---|
| **Daily-only schedule** (Amendment A) | One Worker cron, 00:05 UTC, `daily` only. `daily` runs the former `tick` steps first. `tick` stays callable by hand | `GET /jobs/runs?job=daily`: one `scheduled` run per day with `scheduled_for` and all eight steps. A stuck purchase now settles by the next daily run (up to about 24 h) or a manual run |
| **`GET /jobs/runs`** (READ, N-1, N-5) | Every run since 2.1.0 with `trigger` (`scheduled` / `manual` / `cli`), times, `ok`, `skipped` and the full `steps`; per job `last_run_at`, `last_ok_at`, `next_due_at`; `reference` (popularity list date and rows, IANA refresh time, NameBio disabled) and `backup` (`configured`, `last_status`) | Call it with the READ token. Start a manual run by hand (`POST /jobs/run` needs the job token, which is Dvir's / the Worker's) and check it appears with `trigger: "manual"` |
| **`JOB_OVERDUE`** (N-2) | `/report` error warning when no `daily` run has finished in 26 hours; `GET /health` shows `jobs: "ok"` or `"overdue"`. A manual daily counts | Read `/report` warnings and `/health` after a day with no run. Right after this deploy there is no recorded run yet, so expect `JOB_OVERDUE` until the first daily run (00:05 UTC) |
| **`dry_run: "strict"`** (N-7) | `POST /buy` returns the first real-buy gate refusal as the error: `BUY_HOLD`, `SCREENING_PACK_REQUIRED` (with `details.reason`, `pack_id`), `NO_TRANCHE`, `TRANCHE_SPEND_CAP` | `POST /buy` with `"dry_run": "strict"` and a screened name: expect the 409 gate error. Compare with `"dry_run": true`, which answers 200 with `would_be_blocked`. Neither buys, charges or books anything |
| **Rate-limit headers** (N-8a) | `RateLimit-Limit`, `RateLimit-Remaining`, `RateLimit-Reset` on every authenticated response, a 429 included | Read the headers on any call. Do not try to exhaust the limit with the real token |
| **`POST /jobs/preview`** (WRITE, N-4 narrowed) | `priceJob` and `dropJob` as a dry run on real data for `today` (default today, up to 3 years ahead) | `POST /jobs/preview {"today": "2028-10-05"}`: see `would_apply`, `would_supersede`, `held`, `would_delist`, `would_drop`. It writes only the audit row and is not a run |
| **Test evidence map** (N-11b) | `docs/contract/test-evidence.md`: every code in the code index, and the guarantees (append-only per table, no secrets in responses, no LLM, no top-up, network-blocked tests), mapped to the tests that prove them. Generated by `npm run evidence`, checked by the default suite | Read the file. A code with no test fails CI; the two codes that cannot be tested are listed with a reason in the generator |
| **`lander: "none"`** (CR-004 §10.3) | `POST /list` with `lander: "none"` stores the listing and plan with no nameserver action; `lander_pending` on every `/list` response; info warning `LANDER_PENDING` | `POST /list/{domain}` with `lander: "none"` on a test-safe name; a later call with a real lander clears the flag |
| **Part 1 fixes** | BUG-2 (every timestamp in the Asia/Jerusalem offset; UTC kept on `uploaded_at` and `/jobs/run` times), BUG-3 (`text/plain` is 415), BUG-4 (outcome body checked before the id), BUG-5 (`SETTINGS_KEY_LOCKED`), BUG-6 (malformed percent-encoding is a clean 400), DOCS-1 to DOCS-3, forecast fixes | See the CHANGELOG entry |

## Notes
- **The READ token exists.** DOM created `gavriel-read` (READ scope) and handed it to Dvir. With it, a `POST` answers 403 `SCOPE_FORBIDDEN`, which is how Gavriel can test that code.
- **BUG-6 to be rechecked live by Gavriel.** The fix is in this release (a malformed percent-encoding such as `/portfolio/%ZZ` answers 400 `INVALID_REQUEST` in the error shape instead of a Cloudflare 520). Please re-run your original request against production and tell DOM what you see.
- **Not built, by decision** (CR-005 §12.4): a test environment (N-3), validate-only mode on eight routes (N-6), a fault switch (N-9), `/report?as_of=` (N-10) and the outbound-host log (N-11a). The evidence map replaces them.
- **Job runs are operational telemetry:** the `job_runs` table is append-only but is not part of the nightly data backup. Runs before this release are not listed.
- **Migration:** `1760500000000_v2-1-0-job-runs.sql` (new table `job_runs`, plus `1760400000000_v2-1-0.sql` from Part 1). Both are additive.
