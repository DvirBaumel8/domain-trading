# Release v5.40.0 (draft)

**Contract:** 5.40.0. `GET /jobs/runs` step records gain `db`. MINOR (additive). No migration.

## Why
Improvement loop 2026-10-25, G-125. Every call takes about 1 s from the Mac host to Neon, mostly round trips, and the audit found code paths with one query per row. We could not see how many queries each call or job step makes.

## What changed (contract)
- `GET /jobs/runs`: each finished step has `db: {queries, ms, errors?, top?}` next to `ms`. `top` (the three most repeated query shapes, SQL text with placeholders, never values) appears from 50 queries. A failed or timed-out step has no `db`; steps of older runs have none.
- Host-side (not contract): the API log line "request completed" gains `db_queries`, `db_ms` and, from 20 queries, `db_top`. `npm run traffic -- <api.log>` ranks routes by total time with their query counts.

## Impact on Gavriel
- None required. The new field is additive.

## How to test (via the API)
- `GET /jobs/runs` with a READ token: finished steps carry `db.queries`.
- Local tests: DQ540-1..6 (`tests/modules/ops/unit/db-stats.test.ts`, `tests/modules/ops/db-stats.test.ts`), TR540-1..3 (`tests/unit/traffic-report.test.ts`).

Deploy: pushed to `main` with the tag; the Mac host deploys after CI passes.
