# Release v5.24.0 (21 Oct 2026)

**Contract:** 5.24.0 (MINOR, additive). CR-071 R-8b: coverage on Dynadot bot uploads.

- **What changed:** `POST /snapshots/dynadot` takes an optional `coverage` object: `{partial, calls_n, pages_planned, pages_ok, pages_failed, rows_received_n}`, strict.
  - A day is sealed with `final: true` even when some panel pages failed.
  - The manifest stores the coverage, the seal freezes it, and `GET /snapshots` shows it (`coverage`, `null` when not sent).
  - Migration `1765600000000_v5-24-0.sql` adds the column and extends the seal guard to `origin` and `coverage`.
- **Impact on Gavriel / DOM Architect:** send `coverage` with the final part of each daily Dynadot panel pull (R-8, R-8a). Uploads without it still work.
- **How to test it:** once `/health` shows 5.24.0:
  1. Send `POST /snapshots/dynadot` with `dry_run: true`, `final: true` and the AT-14 `coverage`. Expect 201, with nothing stored.
  2. Repeat with an unknown key in `coverage`, or with `pages_ok` outside `pages_planned`. Expect 422 `VALIDATION_ERROR` (AT-15).
  3. Then the real upload with the first genuine pull. `GET /snapshots?date=D&source=dynadot_aftermarket` shows `complete`, `sealed: true` and the same `coverage`.
- **R-9 (Dynadot closed auctions):** blocked on Dynadot's side (the account has no auction API access). The `closed_auctions` kind stays built; R-10 (GoDaddy endings) is the closed-auction source.
- **Deploy:** the Mac host deploys after CI passes. Nothing for Dvir.
- **Tests:** DS524-1, DS524-2.

**Lessons:** the bots found the missing field with a `dry_run` call before any real upload, which is the cheapest place to find it. Upload contracts should take a coverage or metadata object from the start whenever a source can fail partway through a pull.
