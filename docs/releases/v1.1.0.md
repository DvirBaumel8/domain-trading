# Release v1.1.0 (2026-10-06)

**Contract:** v1.1.0 (MINOR, additive only). Requests: CR-001 P1a, CR-002 P1, CR-002 Amendment A (CR-001-HOLD-01 released by CR-002). Commit: the "release: v1.1.0" commit on `main` (`git log -1 --format=%h -- docs/releases/v1.1.0.md`).

## What's in it
- **Selection settings (CAP-00):** versioned, immutable settings; Gavriel proposes a draft, **Dvir's approval naming the label** activates it; priors and `holdout.*` are locked against drafts.
- **Screening runs (CAP-20):** `POST /screening/runs` over 1-50 names, resumable, polled with `GET /screening/runs/{id}`. Checks built: name form (CAP-01 incl. FORM-2, G-FORM-1), brand and big-company lists and TYPO-1 (CAP-02), RDAP availability (CAP-03), concentration (CAP-04), SURBL (CAP-05), HIST-2 history with the prior-business guard (CAP-07, **switched off**), sibling registered-share census (CAP-10), NameBio counts (CAP-11, **switched off**, score only), other-extension dates (CAP-12), quote and price (CAP-17), tier and DEMAND-2 (CAP-24), EV / Ratio / score (CAP-18). Web Risk (CAP-06) and US trademark (CAP-08) are **manual records**.
- **Tranches (CAP-04):** open, add, close; geo cap on every addition, main-lane quota at close.
- **Buy hold:** a real `/buy` of a screened name is refused (409 `BUY_HOLD`) while the settings have `buy_hold` on.
- **Replay (CAP-21a, Amendment A):** labelled-name registry, pre-registered holdout suites, diagnostic and holdout replays with gates per row, leakage lint and profit report, and the hold-clearing check behind activation.
- **Pricing v3** code (price list, ladder drops, geo M12 rung, whole-dollar floor). The v3 row is created by DOM's admin command with Dvir's approval after deploy; until then every v2 number is unchanged.
- **Jobs:** hourly `screeningResume`; daily `referenceRefresh` (Majestic Million popularity list, IANA bootstrap, cache pruning).

## Contract changes
Nothing breaking. Full list: `docs/contract/CHANGELOG.md` 1.1.0.
- **New routes** (`endpoints.md`): `/selection/settings` (GET, POST), `/selection/settings/{label}/activate`, `/selection/lists/{name}` (GET, POST), `/selection/namebio`, `/selection/evaluate`, `/screening/runs` (POST, GET by id), `/screening/runs/{id}/manual`, `/screening/evidence/{id}`, `/quotes/manual`, `/tranches` (GET, POST), `/tranches/{id}/members`, `/tranches/{id}/close`, `/selection/labelled-names`, `/selection/holdout-suites` (GET, POST), `/selection/replays` (POST, GET by id), `/selection/buy-hold`.
- **`POST /buy`:** one new refusal, 409 `BUY_HOLD`, **only** for a domain that has a screening result under settings with `buy_hold` on (also a backtest result or a retired settings version). A never-screened domain behaves as in v1.0.1. A dry run is never refused; it reports `would_be_blocked: "BUY_HOLD"`.
- **Deferred to v2.0.0 (would be breaking):** `NO_TRANCHE` on `/buy` and the `screening_pack` enforcement. Tranches check quotas on add (geo) and at close only.
- **New codes** by area: settings (`SETTINGS_*`, `HOLDOUT_NOT_PASSED`), lists (`LIST_*`, `CENSUS_LIST_*`), screening (`RUN_NOT_FOUND`, `NAME_NOT_IN_RUN`, `CHECK_NOT_MANUAL`, `CHECKED_AT_INVALID`, `DRAFT_NOT_ALLOWED_LIVE`, `AS_OF_LIVE_REFUSED`, `AS_OF_REQUIRED`, ...), tranches (`TRANCHE_*`, `GEO_CAP`, `MAIN_LANE_QUOTA`, `NOT_SCREENED_OK`), replay (`SUITE_*`, `HOLDOUT_CONTAMINATED`, `REPLAY_*`, `VARIANT_NOT_PREREGISTERED`, `PROFIT_REPORT_INCOMPLETE`), pricing v3 (`BIN_NOT_IN_PRICE_LIST`, `LANDER_EXCEPTION_REQUIRED`). `/report` gains `tranches`. Every code is in the `endpoints.md` code index.

## Impact on Gavriel and Dvir
1. **Approvals must name what they approve.** Activating settings: the text names the **label**. Freezing a census list: names the **list** (or its sld). Freezing a holdout suite: names the **suite id** (`BT10-1`, `BT10-9`, `BT10-11`). A text that names none of these is 422 `APPROVAL_INVALID`. DOM never clears `buy_hold` without Dvir's approval, even when every suite passes.
2. **Before the first live run:** upload the `brand`, `bigco` and `event` lists and the census lists (Dvir approves each census list). Send `leads_ab` and `bin_usd` per name. Record Web Risk and US trademark results by hand (`/screening/runs/{id}/manual`), with an evidence URL; if history found a prior business, the trademark record must include its phrase in `phrases_queried`. Manual quotes: `POST /quotes/manual`.
3. **Sources that are off.**
   - **NameBio: disabled** (its terms could not be read: HTTP 403). The `namebio` check is score only and gives 0 points.
   - **Internet Archive (Wayback): disabled** by Dvir's decision; Amendment B says no permission request is pending, so do not plan on it. `history` is UNKNOWN `SOURCE_DISABLED`, so **live screening produces no survivor past the history gate, an S7 (expired-drop) name cannot join a tranche, and the main-lane quota (10 of 15) is unreachable** until history can be recorded by hand. That is **Amendment B (manual HIST-2), approved at 15:33 IDT and not built in v1.1.0** (gaps G-55): the manual route accepts only `web_risk` and `tm_us`.
   - The popularity list is the **Majestic Million** (CC BY 3.0), not Tranco.
   - **`.co`, `.io`, `.us` are UNKNOWN** (`NO_REGISTRY_SERVICE`): no RDAP service in the IANA bootstrap.
4. **WOULD-BUY means hold on.** While `buy_hold` is on (it is, until the holdout passes), a name that passes every gate is `would_buy`, never `buy_candidate`, and `/buy` refuses it. Open a tranche before using a name; `/buy` does not need one in v1.1.0.
5. **Holdout pre-registration step.** Before any holdout replay: upload suite definitions (`POST /selection/holdout-suites`, Dvir's approval naming each suite id), register the `test` rows with gate columns, dated inputs and `as_of`. Each suite's definition freezes the **test names it selects** (a sorted-list sha256 and a count); the three suites must be **disjoint** (`SUITE_OVERLAP`), non-empty (`SUITE_EMPTY`), and a definition cannot change once the suite has a holdout replay (`SUITE_ALREADY_SCORED`); a replay whose selection no longer matches is `SUITE_MEMBERSHIP_CHANGED`. Register all `test` rows **before** freezing. A failed holdout replay sticks for that settings version; a settings version created after the first holdout replay of a suite is `VARIANT_NOT_PREREGISTERED`.
6. **Findings for Gavriel (replay of `features.csv`, diagnostic, never counts toward the hold).**
   - **BT10-1 passes only under rule I** (42/43 exactly). Under the active settings (tiers I, B, G) it fails: 45/55 sold accepted, 39/55 dropped rejected (71% vs the 75% bar). Decide whether tier B belongs in the rule (propose a draft; Dvir approves by label).
   - `features.csv` has **leakage**: 1,175 of 1,593 checkable rows use a census dated 2026-10-06, after their `as_of`. It also lacks gate columns and sale prices, the exact 226/224 row set and `reg_to_sale_months`, so holdout mode refuses it (`REPLAY_INVALID_NO_GATES`) and the profit report is unavailable. Rounds 4-8 give 148/207 and 143/200 (target 150/211, 144/195); expired-lane dropped 27/42. Gaps G-52, G-53, G-67.
7. **Pricing v3 consequence (Dvir's "recompute on drop" decision).** Floor and walk-away are recomputed at each drop, so an exception walk-away below the formula can **rise** at a drop (for example $500 becomes $520 at M6).
8. **Archive examples differ from CR-002 (G-40).** The live archive shows `officeprep.com` as parked/for-sale only (so `pre_cls: parked`, not `content`) and `sacramentoepoxypros.com` as one blank meta-refresh page (`redirect_error_only`). The check follows the data; tests use recorded captures plus synthetic `synthetic-*.json` ones.

## How to test it (through the API, dry_run only)
WRITE token unless noted; every POST needs a fresh `Idempotency-Key`. No step buys or lists anything.
1. `GET /selection/settings` (READ) → 200 with `active`. `POST /selection/settings` `{label, set: {"thresholds.registered_share_min": 0.4}}` → 201 draft; the same label again → 409 `SETTINGS_LABEL_TAKEN`.
2. `POST /selection/settings/<label>/activate` without `approval_ref` → 422 `APPROVAL_REQUIRED`; with an approval that does not name the label → 422 `APPROVAL_INVALID`; **activate only with Dvir's approval text naming the label** (do not activate a throwaway draft on the live service).
3. `POST /selection/lists/brand` `{replace: [...]}` → 201; a census list `bt1_<sld>` without `approval_ref` → 422 `APPROVAL_REQUIRED`; with Dvir's approval naming the list → 201 (freeze).
4. `POST /selection/holdout-suites` without approval → 422; with Dvir's approval naming each suite id → 201 (`member_hash`, `member_count`); an empty selection → 422 `SUITE_EMPTY`; a selection sharing names with another suite → 409 `SUITE_OVERLAP`; a new definition after a holdout replay → 409 `SUITE_ALREADY_SCORED`.
5. `POST /screening/runs` with 5 names, `mode: "live"` → 202 `run_id`; poll `GET /screening/runs/<id>` until `status` is `done`. Expect a gate-ordered funnel, history UNKNOWN `SOURCE_DISABLED` and no survivor.
6. `POST /screening/runs/<id>/manual` `{domain, check: "web_risk", checked_at, evidence_url, result: {raw_status: ...}}` → 201 (`source: "manual"`); `check: "history"` → 422 `CHECK_NOT_MANUAL`. A `tm_us` record with the prior business phrase in `phrases_queried`.
7. `POST /quotes/manual` → 201 with `valid_until`; registrar `cloudflare` → 422 `REGISTRAR_NOT_ALLOWED`.
8. `GET /selection/namebio?keywords=bank` → 200 `status: "UNKNOWN"`, `reason_code: "SOURCE_DISABLED"`.
9. `POST /selection/evaluate` with the CR-002 section 5.3 fixture → Ratio 2.28 at the BIN / 1.48 at the floor (the unit test pins it).
10. `POST /tranches`, `POST /tranches/<id>/members` (a name from step 5: 409 `NOT_SCREENED_OK` if the run was a backtest or a partial plan), `POST /tranches/<id>/close` below target without `allow_below_target` → 409 `TRANCHE_BELOW_TARGET`.
11. `POST /buy` with `"dry_run": true` for a **screened** name → 200 with `would_be_blocked: "BUY_HOLD"`; for a never-screened name → as in v1.0.1. Outside and inside a tranche is the same in v1.1.0.
12. `POST /selection/labelled-names`, then `POST /selection/replays` `{suite: "diag", mode: "diagnostic"}` → 201 `pass: false`; a holdout replay listing a `fit` name → 422 `HOLDOUT_CONTAMINATED`; before suites are defined → 422 `SUITE_NOT_DEFINED`. `GET /selection/buy-hold` → `clearable: false`.
