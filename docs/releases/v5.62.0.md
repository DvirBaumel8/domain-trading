# Release v5.62.0 (27 Oct 2026)

**Contract:** 5.62.0 (MINOR, migration). CR-080 item 3 (JOINT-OPS build order #2).

- **What changed:** the server reads Dynadot itself. The restricted read-only key `dom-readonly-datasave` is refused by the legacy API3 ("invalid key") but works on the RESTful v2 API (Bearer key + HMAC-SHA256 `X-Signature` with the secret + `X-Request-ID` + `Accept: application/json`). `dynadotAftermarket` reads `GET /restful/v2/aftermarket/listings` (1,000 a page, one call every 5 s, ~470 pages, about 40 minutes) and seals the day through the bot-upload path with origin `server`; the R-8/R-8v2 GAP rule records a GAP instead of a collapsed panel. `dynadotCloseouts` reads `GET /restful/v2/aftermarket/get_expired_closeout_domains` (the path Gavriel's connector uses; checked live; `current_price` is in cents, unlike the listings' dollars).
- **Impact on Gavriel:** the server is primary for Dynadot aftermarket listings once the step reports `ok` for 3 days (your rule); a bot upload for a day the server sealed answers 409 `SNAPSHOT_SEALED` (the lock). The same 3-day rule applies to closeouts.
- **How to test it:** after the next datasave, `GET /jobs/runs?job=datasave` `dynadotAftermarket.summary` (`status`, `pages_n`, `rows_n`, `sealed`, `gap`). Tests DYN-1..14.
- **Deploy:** the Mac host after CI.
- **Lessons:** test a key against the live API before building on its docs: the docs did not say restricted keys are REST-only, and one live call settled it. Known cost: the Dynadot read adds about 40 minutes to the datasave before the shortlist; a later release moves it to the end of the run.
