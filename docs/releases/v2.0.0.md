# Release v2.0.0 (2026-10-06)

**Contract:** v2.0.0 (MAJOR, breaking, `/buy` only). Requests: CR-001 P1b enforcement, CR-002 P-4 (`NO_TRANCHE`). Commit: the "feat!: v2.0.0" commit on `main`.

## What's in it
- A real `POST /buy` needs the domain's latest screening pack to be complete, from the latest screening run, issued under the still-active settings version and at most `pack.max_age_at_buy_hours` (default 72, a zod default; the stored v1 row still parses) old: else 409 `SCREENING_PACK_REQUIRED` (`details.reason`, `details.pack_id`). Checked after `BUY_HOLD`, before any registrar call.
- A real `/buy` needs an active membership of the open tranche: 409 `NO_TRANCHE`. The tranche's optional spend cap: 409 `TRANCHE_SPEND_CAP`, checked on this buy's quote and again under the global buy lock. `purchases.tranche_id` (nullable) records the tranche.
- Dry run: `would_be_blocked` is the first of `BUY_HOLD`, `SCREENING_PACK_REQUIRED`, `NO_TRANCHE`, `TRANCHE_SPEND_CAP`, or absent.
- Migration `1760300000000_v2-0-0.sql` (adds the column and an index). No data change.
