# Release v5.68.0 (27 Oct 2026)

**Contract:** 5.68.0 (PATCH). BUG-056 lander $100k false positive; BUG-057 Dynadot aftermarket deep-page GAP fix.

- **What changed:**
  - **BUG-056:** the lander price parser's "Buy it now for $X" pattern (with required "it" and "for") is now tried first across the whole page before falling back to generic "Buy Now" proximity patterns. A $100,000 amount (offer cap, lease copy, unrelated text) near a generic "Buy Now" no longer wins over the actual buyer-visible "Buy it now for $1,488.00". The `LANDER_PRICE_MISMATCH` false positive on `ukcbamcompliance.com` clears at the next `portfolioCheck`. Tests LP-9, LP-10.
  - **BUG-057:** the aftermarket `deep_pages_empty` GAP no longer fires after collecting real rows from other pages. When the API returns empty deep pages (normal for large pagination), the collected rows are sealed as partial coverage (`coverage.pages_empty` lists the empty pages) instead of being discarded. The page-1 check stays: a page 1 with a total but `raw_n` 0 is still a GAP (the API is broken). This unblocks CR-080 day-1: the next `dynadotAftermarket` run seals with `rows_n > 0`. Tests DYN-7, DYN-7a, DYN-7b.
- **Impact on Gavriel:**
  - `ukcbamcompliance.com` `LANDER_PRICE_MISMATCH` ($100,000) clears on the next `portfolioCheck` run (or manually with `POST /jobs/run {"job":"daily"}`).
  - The next `datasave` `dynadotAftermarket` step seals the aftermarket with real rows. Architect can re-stamp CR-080 day-1.
- **How to test it:** run `POST /jobs/run {"job":"daily"}` then check `GET /report` for `LANDER_PRICE_MISMATCH`; run `POST /jobs/run {"job":"datasave"}` and check `GET /jobs/runs` for `dynadotAftermarket` `status: "sealed"` or `"partial"` with `rows_n > 0`.
- **Deploy:** Mac host after CI; no migration.
- **Lessons:**
  - Pattern-priority ordering matters: the most specific regex must come first, regardless of where the text appears in the HTML. The generic "Buy Now $X" proximity match was too greedy.
  - An all-or-nothing GAP on any empty page is fragile for a 474-page API; partial coverage with the real rows is the honest answer.
