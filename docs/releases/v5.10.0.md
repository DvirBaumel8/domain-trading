# Release v5.10.0 (17 Oct 2026)

**Contract:** 5.10.0. CR-061: a limited `data` token, named READ tokens, a holdout date guard on the engine uploads, and database size in the upload answers

- **What changed:** (A) New token scope `data`: `POST /candidates/intake`, `POST /engine/sales`, `POST /engine/unsold` and `POST /data/*` only; all else 403 `SCOPE_FORBIDDEN`. (B) `POST /engine/sales` and `/engine/unsold` reject rows dated after the holdout date (default 2026-10-14) with `HOLDOUT_SEALED`; the date moves only through `POST /engine/holdout-date` (WRITE, Dvir's `approval_ref` naming the date); `GET /engine/holdout-date` reads it. (C) Both upload answers carry `db_bytes_before` and `db_bytes_after`; a load that would pass 70% of 0.5 GB is refused with 409 `DB_SIZE_HIGH`. Contract: `endpoints.md` Scoring engine, README "Who may call".
- **Impact on Gavriel:**
  - **Tokens.** Dvir creates them on the Mac host after the deploy (below); each bot gets only its own. WRITE stays with Gavriel.
  - **Holdout.** Do not upload `holdout-sales-after-2026-10-14.csv`. If it is sent, its rows come back `HOLDOUT_SEALED`. To unseal: Dvir's line must name the new date; send it as `approval_ref` to `POST /engine/holdout-date` with your WRITE token.
  - **Upload answers** gain two fields; nothing else changes. `data` tokens cannot read: reads use the bot's own READ token.
- **How to test it (all with the right token; use dry data):**
  1. `POST /engine/sales` with the `data-engineer-upload` token and a row dated 2026-10-14: 201, `accepted_n` 1, `db_bytes_before` and `db_bytes_after` present.
  2. Row dated 2026-10-15: `rejects[].reason` `HOLDOUT_SEALED`.
  3. Same token on `POST /buy` (even `dry_run`), `/list/x.com`, `/sold/x.com`, `/offers`, `/portfolio/import`, or any GET: 403 `SCOPE_FORBIDDEN`.
  4. A READ token on `POST /engine/sales`: 403; `GET /audit` shows `token_name` and `scope: read`.
  5. `GET /engine/holdout-date`: `{sales_max_date: "2026-10-14"}`.
- **Deploy:** migration `1764300000000_v5-10-0.sql` runs on start. Push to `main`, tag `v5.10.0`; deploys to the Mac host after CI passes (`scripts/local-host/deploy.sh`, DOM). Gavriel confirms the live version on `/health`.
