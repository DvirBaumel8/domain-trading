## What's in it

## Contract changes (vs the API of 5 Oct 2026)
- **BREAKING** `POST /sold/{domain}`: send the payout fee as top-level `payout_fee` (USD). The `payout` object is refused (422 `VALIDATION_ERROR`). `POST /payouts/{id}/received`, the `payouts` table and the `PAYOUT_*` warnings are gone.
- **BREAKING** `POST /offers/import` is gone. Record each offer with `POST /offers`.
- **BREAKING** Bots only: every route except `GET /health/ping` needs a valid token, **`GET /health` included**. More than 20 failed authentications from one IP in 10 minutes → 429 `RATE_LIMITED` with `Retry-After`.
- **BREAKING** `GET /export/afternic.csv` and `/export/sedo.csv` always return the full file; **any** query parameter (incl. `changed_only`) → 422 `VALIDATION_ERROR`.
- `POST /jobs/run` (job token only): a body other than `{"job":"tick"|"daily"}` → 422 (JOB-3).

## Impact on Gavriel
1. `/sold`: replace any `payout: {…}` with `payout_fee: <fee>`; don't send the payout amount.
2. Send your token on `GET /health` (READ is enough). Use `GET /health/ping` only for a no-auth liveness check.
3. Exports: call `GET /export/afternic.csv` with no query string; upload the whole file with **Update**; then `POST /export/afternic/uploaded` with the `X-Export-Id`. Remove the names in `X-Manual-Delist` by hand.
4. Make calls **one at a time** (the export pending and manual-delist flags assume sequential calls).
5. Offers: one `POST /offers` per offer; there is no CSV import.
6. Branch on `error.code` only; codes are listed per route in `endpoints.md`. `/buy` still requires 2–3 comps in v1.0.0 and does not accept `screening_pack` yet (CR-001 P1b).

## How to test it (through the API, dry_run only)
Use the WRITE token unless noted. Every POST needs a fresh `Idempotency-Key`.
1. `GET /health/ping` → 200 `{"status":"ok"}`. `GET /health` without a token → 401; with the READ token → 200 `db: "ok"`.
2. `GET /check?domain=<a random unregistered .com>` → 200, `availability: "available"`, a `winner` with `two_year_cents`.
3. `GET /pricing/preview?category=trend&bin=1995` → 200, floor 1295, walk-away "$960 (private)", min offer 100, 4 schedule events.
4. `POST /buy` with **`"dry_run": true`**, the domain from step 2, `max_price` above the quote, `category: "trend"`, `proposed_listing: {"mode":"hybrid","bin":1995}`, 2 comps in `pricing_evidence`, `expected_settings_version` from step 3, and an `approval_ref` whose text names the domain (≤ 72 h old) → 200 `dry_run: true` with the registrar dry-run result (with $0 Porkbun credit, 409 `REGISTRAR_FUNDS` is the expected pass). **Never send `/buy` without `dry_run: true` before G4.**
5. The same `/buy` with the same key → the stored answer, header `Idempotent-Replayed: true`. Same key, another body → 409 `IDEMPOTENCY_KEY_MISMATCH`.
6. `GET /export/afternic.csv?changed_only=true` → 422. Without the query → 200 CSV with the exact Afternic header (`formats.md`).
7. `POST /sold/example-not-owned.com` with a `payout` object → 422 `VALIDATION_ERROR` (the body is checked before anything is recorded). Never test `/sold` on a real domain: it books a sale.
8. `GET /report` → 200 with `budget.poc_cap` "$1,500.00" and `warnings`.
