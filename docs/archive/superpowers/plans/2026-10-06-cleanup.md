# Cleanup and minimisation: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Make the codebase smaller and simpler, so future changes cost fewer tokens and carry less risk. Founder rules and behaviour stay the same, except for the cuts Dvir chose on 6 Oct 2026. Hosting stays $0.

**Inputs (read-only audits, 6 Oct):** `.superpowers/audit/code-audit.md` (sections A–F) and `.superpowers/audit/test-audit.md` (sections A–F). Implementers take the items from these files by section ID.

**Dvir's decisions (6 Oct 2026):**
- **Cut:** the offers CSV import (`POST /offers/import`, `offer_imports`), and the payouts table and endpoint (`payouts`, `POST /payouts/{id}/received`, `PAYOUT_*` warnings, `payouts_pending`). `/sold` keeps booking `sale` and `payout_fee` ledger rows exactly as today, so its optional payout input maps to the fee row only.
- **Simplify:**
  - Always export the full Afternic file: drop `export_run_domains`, `changed_only` and the pending/manual-delist derivation that depends on per-file records.
    - Keep `POST /export/{venue}/uploaded` as the audit record of an upload.
    - Keep the delist header for removed names, computed from status changes since the last confirmed upload.
  - Drop `JOBS_MODE=internal` and its in-process timers. Jobs run only via `POST /jobs/run` (production) or `npm run job -- <name>` (local, including a new `tick` and `daily` subcommand that call the same runner).
- **Kept, not cut:** GoDaddy adapter, multi-registrar selection, the DNS client, the check cache, Sedo export, the report views, CLAUDE.md, the old plans.
- **Docs:** shrink the specs. JOB-3 changes to **422** for a bad body; the code already returns 422.

## Global Constraints
- **Founder-rule tests must stay at least as strong:** caps, approval, idempotency, audit, no top-up, secrets never leaked, no live create, append-only.
- **Every task ends with the full `npx vitest run && npx tsc --noEmit && npm run build` green.** The default suite stays offline.
- **Behaviour-preserving tasks (T3, T4)** must not change any API response, error code or DB write. If a test has to change, it's because a duplicate was removed or a helper extracted, never a weakened assertion.
- **Migrations:** there is no production DB yet (no deploy has happened). T5 squashes all migrations into a single baseline that reflects the final schema. Existing local dev databases are re-created (`npm run db:reset` or the documented docker steps).
- **Specs are the contract.** Tasks T1/T2 update the affected spec sections for the cuts (short edits). T6 then shrinks the specs overall.

### Task 1b: Bots-only access (Dvir, 6 Oct 2026: "the system has only one and only customer, the grok bots; every other consumer should be blocked and must not make us save anything in the DB")
- Any request without a valid credential (bot READ/WRITE token, or the job token on `/jobs/run`) → 401/403/404 with **zero DB writes**: no `audit_log` row, no `idempotency_keys` row, no other write. Same for unknown routes.
- Authenticated requests keep today's audit rules (AL-1 now means every *authenticated* POST).
- **Per-IP failed-auth limiter** (in memory, before any DB lookup): after 20 failed attempts per IP per 10 min → 429 with no DB access. Use the request IP Fastify derives with trustProxy one hop.
- **Public routes:** only `GET /health/ping` (no DB). `GET /health` (DB check, version, adapters) now requires any valid bot token.
- Tests:
  - AU-1 sweep: no token / bad token on every route → refused, and the `audit_log` + `idempotency_keys` counts are unchanged;
  - the limiter → 429 with no token lookup (spy on the db);
  - `/health` without a token → 401, with a READ token → 200;
  - an unknown route without a token → no DB write;
  - a valid token's 4xx is still audited.
- Spec edits: 00-architecture §6/§7, test-plan (AL-1, AU-1, JOB-6 `/health` row), report.md `/health`.
